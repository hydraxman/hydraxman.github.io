今天这份 GitHub Trending，有点像 AI Agent 圈的一次集体转向：冲上前排的，不再只是‘会聊天的模型周边’，而是能直接插进开发、会议、信息整合和终端协作里的实战工具。开发者已经不太满足于看参数表，他们更在意这些项目明天能不能真的接进工作流。

更有意思的是，这份榜单一半在做生产力，一半在拆 AI 产品的底牌：一边是会议助手、技能库、多代理调度器，另一边是 system prompt 泄露、视频理解、研究型总结器。热度表面上很分散，底层却指向同一个判断——AI 开源的竞争，正在从‘谁更会说’切到‘谁更会做、谁更接近真实使用场景’。

No.1 asgeirtj/system_prompts_leaks

  • 项目简介： 这是一个持续收录主流 AI 产品 system prompt 的公共档案库，覆盖 Claude、ChatGPT、Gemini、Copilot、Perplexity 等多条产品线。
  • 为什么火： AI 行业现在最有流量的，不只是模型能力，还有“这些产品背后到底怎么被提示、怎么被约束”。这个仓库天然踩中好奇心和研究需求两头。
  • 技术亮点： 项目把不同产品、版本和更新时间整理成可检索目录，还能做 prompt diff。它更像一份“AI 产品行为说明书的地下档案馆”，而不是一页零散爆料。
  • 适用场景： 适合做提示词审计、对齐研究、竞品分析、AI 产品教学，以及理解不同产品的人设和边界。
  • 关键数据： 语言 JavaScript；Stars 51,274；Today Stars 1,386；Forks 8,360；License CC0-1.0；最近更新 2026-07-06；Topics ai, ai-agents, anthropic, awesome, chatbot, chatgpt；Homepage https://asgeirtj.github.io/system_prompts_leaks/。

No.2 addyosmani/agent-skills

  • 项目简介： 这是 Google Chrome 团队工程师 Addy Osmani 维护的一套生产级 AI coding agent 技能库，核心目标是把“代理写代码”这件事做得更稳定、更像工程。
  • 为什么火： 大家已经不缺会写代码的模型，缺的是一套能在真实项目里复用的工作方法。这个仓库卖的不是花哨 prompt，而是“怎么让代理少翻车”的经验包。
  • 技术亮点： 仓库强调 planning、debugging、refactor、review 等工程技能，把原本只存在于资深开发者脑子里的流程拆成可复用模板，像给 AI 配一套工程 SOP。
  • 适用场景： 适合希望规范 AI 编码流程、降低代理失误率、把代码生成拉回工程化轨道的个人开发者和团队。
  • 关键数据： 语言 Shell；Stars 70,635；Today Stars 1,114；Forks 7,654；License MIT；最近更新 2026-07-06；Topics agent-skills, antigravity, antigravity-ide, claude-code, cursor, skills；Homepage —。

No.3 Zackriya-Solutions/meetily

  • 项目简介： Meetily 是一个本地优先的 AI 会议助手，支持实时转写、说话人分离和本地总结，强调音频和纪要尽量不出设备。
  • 为什么火： 企业现在最怕的不是 AI 不够聪明，而是会议内容被上传到云端。它把隐私、速度和可部署性打包在一起，刚好卡住高频痛点。
  • 技术亮点： 项目把 Rust、本地转写、speaker diarization 和本地大模型总结串到一起，像把“录音笔 + 速记员 + 摘要器”塞进一台离线电脑。
  • 适用场景： 适合法务、咨询、研发周会、客户访谈、金融医疗等对会议隐私特别敏感的记录场景。
  • 关键数据： 语言 Rust；Stars 19,092；Today Stars 2,493；Forks 1,937；License MIT；最近更新 2026-06-05；Topics ai, ai-meeting-assistant, llm, local-ai, mac, meeting-minutes；Homepage https://meetily.ai。

No.4 ruvnet/RuView

  • 项目简介： RuView 想做一件很科幻的事：不靠摄像头，只用普通 Wi‑Fi 信号去推断空间存在、呼吸体征和实时动态。
  • 为什么火： “无摄像头感知”同时踩中了隐私、安全和智能空间三个热词。它一边像科研 demo，一边又足够有想象空间，所以特别容易带起讨论。
  • 技术亮点： 项目把 Wi‑Fi 当成一种低成本空间传感器，用信号变化去做 presence detection 和 vital sign monitoring。技术上最抓人的地方，不是精度口号，而是“没有像素也能看见变化”。
  • 适用场景： 适合智能家居、护理监测、隐私敏感安防、存在感知和空间交互实验。
  • 关键数据： 语言 Rust；Stars 77,399；Today Stars 471；Forks 10,394；License MIT；最近更新 2026-07-06；Topics awesome, claude, densepose, esp32, firmware, home-assistant；Homepage https://Cognitum.One/RuView。

No.5 Leonxlnx/taste-skill

  • 项目简介： Taste Skill 是一组给 AI 编码工具“补审美课”的技能包，目标很直白：别再生成千篇一律、塑料味很重的页面。
  • 为什么火： AI 写前端已经不算新鲜，真正稀缺的是“写得快还不难看”。这类项目火，说明大家开始从“能生成”转向“能不能有品位”。
  • 技术亮点： 它不是再教模型多写几个组件，而是把布局、留白、字体、动效和品牌感一起打包，像给代码代理配了一个更严格的设计总监。
  • 适用场景： 适合官网、落地页、品牌升级、产品首页，以及所有“不想看起来像 AI 模板”的前端项目。
  • 关键数据： 语言 JavaScript；Stars 58,756；Today Stars 1,453；Forks 4,004；License MIT；最近更新 2026-07-04；Topics agent, ai, claude, claude-code, codex, coding；Homepage https://tasteskill.dev。

No.6 alirezarezvani/claude-skills

  • 项目简介： 这是一个从 Claude Code 出发、但已经扩展到 Codex、Gemini CLI 等多个代理平台的大型技能仓库。
  • 为什么火： 团队真正需要的，早就不是“再来一个会写代码的模型”，而是“让不同代理按统一方法干活”。这种技能库天然会吸走一大批工程团队关注。
  • 技术亮点： 仓库同时覆盖工程、产品、营销、合规、研究等多个域，本质上是在把组织经验模块化，像给 AI 团队提供一套可复制的角色库。
  • 适用场景： 适合希望快速搭建代理工作流、沉淀团队方法论、给不同 AI 助手分配专业角色的组织。
  • 关键数据： 语言 Python；Stars 21,078；Today Stars 611；Forks 2,834；License MIT；最近更新 2026-07-06；Topics agent-plugins, agent-skills, agentic-ai, ai-coding-agent, anthropic-claude, claude-ai；Homepage https://alirezarezvani.medium.com/。

No.7 openai/codex-plugin-cc

  • 项目简介： 这是一个把 Codex 接进 Claude Code 的插件，核心能力是代码评审、任务委派和跨代理协作。
  • 为什么火： 多代理工作流正在从演示走向日常：一个模型写、一个模型审、一个模型接手补救，开始变成可执行流程，而不是 PPT。
  • 技术亮点： 它把 review、adversarial review、transfer、rescue 这些动作做成明确命令，重点不是“能不能调用 API”，而是把协作语义设计出来。
  • 适用场景： 适合代码审查、复杂任务拆分、挑战式复核，以及希望让两个代理互相盯错的研发流程。

No.8 mvanhorn/last30days-skill

  • 项目简介： 这是一个面向 AI agent 的研究技能包，能把 Reddit、X、YouTube、HN、Polymarket 和通用网页材料汇总成有出处的总结。
  • 为什么火： 信息过载已经是所有团队的共同焦虑。谁能把“搜一圈、看一圈、总结一圈”自动化，谁就更容易拿到注意力。
  • 技术亮点： 它的卖点不是单点搜索，而是跨平台拉材料后做 grounded synthesis，像给代理装了一套“过去 30 天舆情雷达”。
  • 适用场景： 适合市场研究、竞品追踪、投资观察、热点整理、主题 briefing 和内容选题前期调研。
  • 关键数据： 语言 Python；Stars 49,660；Today Stars 511；Forks 4,138；License MIT；最近更新 2026-07-06；Topics ai-prompts, ai-skill, bluesky, claude, claude-code, clawhub；Homepage —。

No.9 ogulcancelik/herdr

  • 项目简介： Herdr 是一个住在终端里的 agent multiplexer，帮你同时管理多个编码代理的状态、窗口和任务切换。
  • 为什么火： 当团队真的开始并行用 Claude、Codex、Cursor 这类工具时，新的瓶颈已经不是模型数量，而是调度成本。Herdr 刚好在解决这个更真实的问题。
  • 技术亮点： 它把 workspaces、tabs、panes、可重连终端和本地 socket API 拼在一起，像是在做“AI 时代的 tmux / supervisor 混合体”。
  • 适用场景： 适合多仓库并行开发、远程 SSH 编码、长任务守护，以及需要同时调度多个代理的小团队。
  • 关键数据： 语言 Rust；Stars 12,760；Today Stars 783；Forks 743；License NOASSERTION；最近更新 2026-07-06；Topics agent, agent-orchestration, ai, ai-agents, claude-code, cli；Homepage https://herdr.dev。

No.10 bradautomates/claude-video

  • 项目简介： Claude Video 给 Claude 补上“看视频”的能力：下载视频、抽帧、转写，再把材料一起喂给模型理解。
  • 为什么火： 视频已经成了知识、课程、产品演示和社媒内容的主战场。谁先把视频纳入代理上下文，谁就更接近下一代内容工作流。
  • 技术亮点： 项目不是只做字幕抽取，而是把 frame extraction、transcription 和模型理解串成一条流水线，相当于给 Claude 配了一个视频速读助手。
  • 适用场景： 适合课程复盘、会议录像理解、产品演示拆解、YouTube 内容总结，以及把视频转成结构化笔记。
