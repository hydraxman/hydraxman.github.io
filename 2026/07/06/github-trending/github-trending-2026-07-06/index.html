今天这份 GitHub Trending，有点像 AI Agent 赛道的一次集体拐弯：最火的不是又一个聊天入口，而是会议纪要、代码评审、浏览器操控、终端协作、安全测试这些“能直接替你干活”的工具。开发者的注意力，正在从“模型是不是更聪明了”转向“它能不能马上接进工作流”。

更值得玩味的是，榜单里既有 meetily、page-agent 这种很务实的生产力项目，也有 system_prompts_leaks 这种带着窥探意味的灰度仓库。这说明行业还在两条路上同时狂奔：一条追求更省时间、更少人力；另一条则在拼谁先摸清 AI 产品真正的底牌。能走得更远的，通常不是最会制造话题的，而是最会解决真问题的。

No.1 Zackriya-Solutions/meetily

  • 项目简介： Meetily 是一个本地优先的 AI 会议助手，主打实时转写、说话人分离、会议总结，而且数据默认不出本机。
  • 为什么火： 今年企业最怕的不是“AI 不够聪明”，而是“会议内容被送上云”。它把隐私、速度和可部署性捆在一起，正好踩中团队协作里最敏感的一块。
  • 技术亮点： 仓库明确强调 Rust 实现、本地处理、Parakeet / Whisper 实时转写、speaker diarization，以及可接 Ollama 等本地模型。这种组合很像把“录音笔 + 速记员 + 摘要器”装进一台离线电脑里。
  • 适用场景： 适合法务、咨询、研发周会、客户访谈、医疗或金融等不愿把音频外发的会议记录场景。
  • 关键数据： 语言 Rust；Stars 16,640；Today Stars 1,409；Forks 1,779；License MIT；最近更新 2026-06-05；Topics ai, ai-meeting-assistant, llm, local-ai, offline-first；Homepage https://meetily.ai。

No.2 openai/codex-plugin-cc

  • 项目简介： 这是一个把 Codex 接进 Claude Code 的插件，核心能力是代码评审和任务委派。
  • 为什么火： 多智能体协作正在从“概念展示”变成真实工作流。大家已经不满足于只让一个模型单打独斗，而是希望把评审、挑战式复核、后台委派拆给不同代理。
  • 技术亮点： README 给出的命令很直白：/codex:review、/codex:adversarial-review、/codex:rescue、/codex:transfer 等，说明它不只是接 API，而是在认真设计跨代理协作的操作语义。
  • 适用场景： 适合代码审查、复杂任务拆分、把某些工作从 Claude Code 分发给 Codex 的研发团队。
  • 关键数据： 语言 JavaScript；Stars 25,345；Today Stars 1,519；Forks 1,534；License Apache-2.0；最近更新 2026-06-23；Topics —；Homepage —。

No.3 asgeirtj/system_prompts_leaks

  • 项目简介： 这是一个持续整理主流 AI 产品 system prompt 的公共档案库，覆盖 Claude、ChatGPT、Gemini、Copilot、Perplexity 等多条线。
  • 为什么火： 外界对 AI 产品的兴趣，已经从“它会什么”进一步深入到“它被怎样约束、怎样被引导”。这类仓库天然带流量，也自带争议。
  • 技术亮点： 它不是简单贴几段提示词，而是持续维护版本差异、更新时间和多产品目录结构，甚至提供 prompt diff。对研究者来说，这更像一套可检索的行为配置史料。
  • 适用场景： 适合 AI 产品研究、提示词审计、对齐分析、教学演示，以及理解不同模型的产品人格设定。
  • 关键数据： 语言 JavaScript；Stars 49,787；Today Stars 981；Forks 8,148；License CC0-1.0；最近更新 2026-07-05；Topics ai, ai-agents, anthropic, chatgpt, claude, claude-code；Homepage https://asgeirtj.github.io/system_prompts_leaks/。

No.4 Leonxlnx/taste-skill

  • 项目简介： Taste Skill 是一组面向 AI 编码工具的设计技能包，目标很明确：别再让 AI 生成“像模板拼出来”的无聊界面。
  • 为什么火： 过去几个月，AI 写前端越来越快，但同质化 UI 也越来越严重。这个项目之所以受欢迎，不是因为它教模型写更多代码，而是因为它试图补上“审美”这一刀。
  • 技术亮点： 仓库强调布局、字体、动效、留白这些设计基本功，还把 image-generation skills 和前端实现串起来，让参考板、品牌感、页面结构形成闭环。
  • 适用场景： 适合做官网、落地页、产品首页、品牌改版，以及任何“不想再长得像 AI 做的”前端项目。
  • 关键数据： 语言 JavaScript；Stars 57,308；Today Stars 850；Forks 3,921；License MIT；最近更新 2026-07-04；Topics agent, ai, claude, codex, design, frontend；Homepage https://tasteskill.dev。

No.5 alirezarezvani/claude-skills

  • 项目简介： 这是一个面向 Claude Code 生态起家的大型技能库，但已经扩展到 Codex、Gemini CLI、OpenClaw、Hermes Agent 等多个平台。
  • 为什么火： 团队对 AI 编码工具的真正需求，已经从“让它能写”变成“让它按统一方法写”。这个仓库卖的不是单个 prompt，而是一整套可复用的组织经验。
  • 技术亮点： README 明确给出 354 个技能、96 个 agents、102 个 commands、13 个平台支持，以及覆盖 engineering、DevOps、security、productivity 等域的能力库。它更像一个“给 AI 团队配 SOP 的开源仓库”。
  • 适用场景： 适合希望标准化 AI 研发流程、快速搭建技能体系、给不同代理分配专业角色的工程团队。
  • 关键数据： 语言 Python；Stars 20,462；Today Stars 394；Forks 2,791；License MIT；最近更新 2026-07-03；Topics agent-plugins, agent-skills, ai-coding-agent, claude-code；Homepage https://alirezarezvani.medium.com/。

No.6 rommapp/romm

  • 项目简介： RomM 是一个自托管 ROM 管理与游玩平台，可以扫描游戏库、补全元数据、在浏览器里直接启动部分游戏。
  • 为什么火： “自托管 + 怀旧 + 好看”这三个标签叠在一起，几乎天然会吸引 homelab 与复古游戏社区。它不是最宏大的项目，但很容易打到用户心里。
  • 技术亮点： 支持 400+ 平台元数据、可接 IGDB / Screenscraper / MobyGames，支持 EmulatorJS 与 RuffleRS 浏览器游玩，还能处理 DLC、mods、manuals 这类细碎资产，完整度很高。
  • 适用场景： 适合个人游戏收藏整理、家庭服务器、复古设备爱好者，以及想把 ROM 库做成“可分享媒体中心”的用户。
  • 关键数据： 语言 Python；Stars 10,474；Today Stars 411；Forks 501；License AGPL-3.0；最近更新 2026-07-05；Topics emulation, open-source, retrogaming, self-hosted；Homepage https://romm.app。

No.7 ogulcancelik/herdr

  • 项目简介： Herdr 是一个住在终端里的 agent multiplexer，帮你同时盯住多个编码代理的进度和阻塞状态。
  • 为什么火： 真正在用 Claude、Codex、Cursor 这类工具的人，很快都会撞上一个现实问题：代理变多之后，调度成本也在飙升。Herdr 抓住的正是这个“管理代理”的新需求。
  • 技术亮点： 它强调每个代理都有自己的真实终端、支持 workspaces / tabs / panes、可脱离后重连，还带本地 socket API。说白了，它想做的不是一个花哨面板，而是“AI 时代的 tmux 替代品”。
  • 适用场景： 适合多仓库并行开发、远程 SSH 编码、同时跑多个 AI 代理做分工协作的个人或小团队。
  • 关键数据： 语言 Rust；Stars 11,951；Today Stars 650；Forks 696；License 未声明；最近更新 2026-07-05；Topics agent, agent-orchestration, ai-agents, claude-code, cli, codex；Homepage https://herdr.dev。

No.8 alibaba/page-agent

  • 项目简介： Page Agent 是一个直接运行在网页里的 GUI Agent，可以用自然语言操控表单、按钮和 DOM 元素。
  • 为什么火： 浏览器自动化这件事，过去长期被 headless 脚本和复杂测试框架垄断。它现在受追捧，是因为越来越多产品团队想把“网页会自己操作自己”这件事直接塞回前端。
  • 技术亮点： README 的卖点非常清楚：不依赖 headless browser，不一定需要扩展，直接在页面内用 JavaScript 驱动 GUI；同时还能接 MCP Server，把浏览器控制能力暴露给外部代理。
  • 适用场景： 适合 SaaS 内置 AI Copilot、复杂表单自动填写、浏览器办公流，以及需要更强可访问性的 Web 产品。
  • 关键数据： 语言 TypeScript；Stars 23,737；Today Stars 801；Forks 2,053；License MIT；最近更新 2026-07-03；Topics agent, ai-agents, browser-automation, mcp, typescript, web；Homepage https://alibaba.github.io/page-agent/。

No.9 harvard-edge/cs249r_book

  • 项目简介： 这是一个围绕 Machine Learning Systems 搭建的开放教材与课程体系，不只给你 PDF，还把实验、TinyTorch、模拟器和课程组件一起打包。
  • 为什么火： 今年“会写 prompt”已经不够稀缺，真正升温的是“懂训练、推理、部署、系统取舍”的工程能力。这个仓库上榜，说明大家开始认真补 AI 基础设施课了。
  • 技术亮点： 项目把 Textbook、Vol I / Vol II、TinyTorch、Labs、MLSys·im、StaffML 串成一个统一课程，强调不仅要读懂理论，还要亲手搭、亲手推演系统约束。
  • 适用场景： 适合高校课程、自学型工程师、AI 平台团队入门训练，以及想系统理解 ML Systems 的读者。
  • 关键数据： 语言 Python；Stars 26,796；Today Stars 333；Forks 3,186；License 未声明；最近更新 2026-07-05；Topics artificial-intelligence, cloud-ml, computer-systems, machine-learning；Homepage http://mlsysbook.ai/。

No.10 usestrix/strix

  • 项目简介： Strix 是一个开源 AI 渗透测试工具，主打自动化发现漏洞、验证漏洞，并给出修复建议。
  • 为什么火： 安全是最容易算 ROI 的 AI 场景之一：你不一定愿意把核心研发全交给代理，但你很愿意先让它替你扫漏洞、跑 PoC、卡住危险 PR。
  • 技术亮点： README 强调 multi-agent orchestration、真实 exploit validation、开发者友好 CLI，以及 CI/CD 集成和自动修复报告。这比“又一个安全扫描器”更进一步，因为它瞄准的是动态验证而不只是静态告警。
  • 适用场景： 适合应用安全测试、渗透测试提效、Bug Bounty 自动化，以及把安全检查纳入代码提交流水线的团队。
  • 关键数据： 语言 Python；Stars 36,954；Today Stars 1,121；Forks 3,747；License Apache-2.0；最近更新 2026-07-03；Topics agents, ai-hacking, ai-pentesting, ai-security, bug-bounty, code-quality；Homepage https://strix.ai。
