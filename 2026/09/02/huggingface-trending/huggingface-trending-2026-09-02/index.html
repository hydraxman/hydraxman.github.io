今天的 Hugging Face Models 热榜仍由 Qwen 与 GLM 新权重占据前排：Qwen3.8-Flash-Next 的 Trend Score 为 3,576，GLM-5.3-Flash 与 GLM-5.3 紧随其后。三款 Unsloth GGUF 衍生版进入 Top 10，关注点已经从“新模型发布”延伸到“能否放进现有推理栈”。

榜单还出现 DeepSeek 的实验性视觉 Agent 模型、腾讯 770B MoE 预览版和 LTX-2.5 音视频生成模型。Trend Score 只表示 Hugging Face 的趋势排序，不是性能、质量或安全评分；Downloads 与 Likes 也是累计指标，选型仍要回到模型卡、硬件、许可和风险。

1. Qwen/Qwen3.8-Flash-Next

  • 模型简介： Qwen3.8-Flash-Next 是面向 Qwen4 的实验性架构预览，也是该架构首个开放权重版本。它将因果语言模型与视觉编码器组合，覆盖文本、图像与视频理解；仓库提供预训练和后训练后的 Transformers 权重。
  • 为什么热： Trend Score 3,576，Downloads 207,941，Likes 4,621。新架构预览、稀疏激活和原生多模态构成主要关注点。 榜单位置只代表当前平台关注度。
  • 技术特点： 模型卡给出 125B 语言模型主体、每 token 激活 6B，另含 51B n-gram embedding 与 4B MTP；48 层、512 个专家，每 token 路由 10 个并使用 1 个共享专家。它组合 Gated DeltaNet、Qwen Sparse Attention、Gated Residual 与 n-gram embedding，原生上下文 262,144 token，可用 YaRN 扩展到 1,000,000。
  • 适用场景： 适合长上下文 Agent、代码与专业任务、复杂文档/图表理解，以及图片和长视频问答。短文本业务不应默认开启静态 YaRN；模型卡提示固定缩放因子可能影响较短输入表现。
  • 关键数据： Trend Score 3,576；Downloads 207,941；Likes 4,621；参数 125B 主体 / 6B 激活 + 51B n-gram embedding + 4B MTP；上下文 262,144 原生；SHA de4b8e4d43b9。
  • 许可与风险： 采用 Qwen Community License 1.0。达到许可中规定的超大规模商业产品门槛，或用于 Model-as-a-Service、以编程/办公为主的 AI Work Assistant 时，存在署名或另行许可要求。模型卡将它标为实验预览，也没有提供通用安全与偏见说明；开放权重不等于无条件商用。

2. zai-org/GLM-5.3-Flash

  • 模型简介： GLM-5.3-Flash 是 GLM-5 系列首个原生多模态模型，从新训练的 base model 出发，把多模态、长上下文和推理效率放进同一架构。
  • 为什么热： Trend Score 1,754，Downloads 441,348，Likes 1,870。320B/18B 激活、原生多模态和多框架服务路线同时吸引模型与部署团队。 榜单位置只代表当前平台关注度。
  • 技术特点： 模型卡披露 320B 总参数、18B 激活参数和 30T-token 多模态预训练语料，采用稀疏注意力与线性注意力混合架构并引入 mHC。固定 SHA 配置包含 45 层、288 个路由专家、每 token 激活 8 个并配 1 个共享专家，最大位置长度 1,048,576，权重带 FP8 e4m3 配置。
  • 适用场景： 适合代码与 Agent 工作负载、长上下文工具调用、图像理解和中英双语对话。部署可选 SGLang、vLLM、TokenSpeed、Transformers、KTransformers 与 Unsloth；模型卡没有公布最低 GPU 数、显存或真实吞吐下限。
  • 关键数据： Trend Score 1,754；Downloads 441,348；Likes 1,870；参数 320B 总参数 / 18B 激活；上下文配置 1,048,576；SHA 03eb5366286a。
  • 许可与风险： 固定 SHA 的 README 与 LICENSE 均标注 MIT，分发仍需保留版权和许可声明。模型卡中的性能比较来自发布方设置，依赖具体 harness、上下文与判分条件；它也没有单独列出完整的偏见、安全与事实性限制。

3. zai-org/GLM-5.3

  • 模型简介： GLM-5.3 以代码、长任务和工具执行为主要卖点。模型卡说明它与 GLM-5.2 使用同一 base model，增益来自 post-training，因此它属于同一底座上的后训练升级。
  • 为什么热： Trend Score 1,390，Downloads 94,403，Likes 1,464。后训练带来的代码、长任务与网络安全能力更新仍在扩散。 榜单位置只代表当前平台关注度。
  • 技术特点： README 没有披露总参数或激活参数。固定 SHA 配置显示 78 层、256 个路由专家、每 token 激活 8 个并配 1 个共享专家，最大位置长度 1,048,576，权重配置为 FP8 e4m3；部署覆盖 SGLang、vLLM、TokenSpeed、Transformers、KTransformers、Unsloth 和 Ascend NPU 方案。
  • 适用场景： 适合代码库级生成、终端编程 Agent、自动化工具执行，以及隔离和授权环境中的漏洞发现、红队与安全评估。普通聊天应管理思考历史，避免长任务状态无边界累积。
  • 关键数据： Trend Score 1,390；Downloads 94,403；Likes 1,464；参数 Model Card 未披露；配置为 78 层、256 路由专家、8 激活 + 1 共享；SHA 187fb9fff631。
  • 许可与风险： 采用自定义 GLM-5.3 License；其中对达到特定超大规模收入门槛的 MaaS 运营设有额外安全审查条件。模型的网络安全能力具有双用途风险，公开 benchmark 也包含特定 Agent harness、长任务和第三方判分设置，不能简化为无条件领先。

4. Qwen/Qwen3.8-27B

  • 模型简介： Qwen3.8-27B 是 27B 稠密视觉语言模型，面向代码、专业工作、研究和长时 Agent 任务，可理解文本、图片和视频，并支持 thinking/non-thinking 切换。
  • 为什么热： Trend Score 654，Downloads 4,960,483，Likes 13,565。27B 稠密规模、262K 原生上下文和 Apache-2.0 提供了相对直接的私有化入口。 榜单位置只代表当前平台关注度。
  • 技术特点： 模型卡给出 27B dense、64 层和 hidden size 5120，采用 3 个 Gated DeltaNet 层与 1 个 Gated Attention 层循环的混合布局，并训练 MTP。原生上下文 262,144 token，可用 YaRN 扩到 1M；服务框架包括 SGLang、vLLM 与 TokenSpeed。
  • 适用场景： 适合本地或私有化代码助手、长文档分析、图表与 STEM 图片理解、视频问答和多轮 Agent。模型卡没有最低显存与 GPU 数据，部署前仍需实测吞吐；超出 262K 再考虑 YaRN，避免为短文本承担无谓损失。
  • 关键数据： Trend Score 654；Downloads 4,960,483；Likes 13,565；参数 27B dense；上下文 262,144 原生，可扩展至 1,000,000；SHA 1d4bf0f2ff60。
  • 许可与风险： Apache-2.0，允许商用与衍生，分发需保留许可证、版权与 NOTICE 等义务。模型卡没有系统性的安全、偏见或事实性限制章节，公开评测属于官方模型卡口径。

5. unsloth/Qwen3.8-Flash-Next-GGUF

  • 模型简介： 这是 Qwen/Qwen3.8-Flash-Next 的 Unsloth GGUF 量化与转换仓库，保留基础模型的多模态定位，把交付重点转向 llama.cpp 与桌面本地运行。
  • 为什么热： Trend Score 648，Downloads 431,339，Likes 665。基础模型位列榜首，本地量化工件也同步升温。 榜单位置只代表当前平台关注度。
  • 技术特点： README frontmatter 明确 base model 关系，并列出 BF16、Q8_0 与多档 IQ/Q 量化目录。它沿用基础模型的 125B 主体、6B 激活和 262K 原生上下文；模型卡没有给出最低 RAM/VRAM，也没有为每个量化档提供独立复现的质量损失。
  • 适用场景： 适合愿意用 llama.cpp 或 Unsloth Desktop 部署 Qwen3.8-Flash-Next 的本地多模态、长上下文和代码任务。视觉组件、量化精度、内存占用与速度都应在目标硬件上一起检查。
  • 关键数据： Trend Score 648；Downloads 431,339；Likes 665；基础模型 Qwen/Qwen3.8-Flash-Next；GGUF 量化/转换衍生版；SHA 5d16c055a7c5。
  • 许可与风险： 模型卡沿用 Qwen Community License 1.0，固定 SHA 下未见独立 LICENSE 文件，应按基础模型条款执行。量化不会消除 MaaS、AI Work Assistant 或大规模产品的许可要求；发布方的量化质量主张也需要同口径复现。

6. deepseek-ai/DeepSeek-V4-Flash-Vision-Exp

  • 模型简介： DeepSeek-V4-Flash-Vision-Exp 是 DeepSeek-V4 系列首个实验性多模态模型，在 DeepSeek-V4-Flash 架构上加入视觉模块并继续训练，目标是获得图像理解与多模态 Agent 能力。
  • 为什么热： Trend Score 432，Downloads 17,893，Likes 439。新发布的视觉 Agent 实验版正在快速积累试用，但名次不代表成熟度。 榜单位置只代表当前平台关注度。
  • 技术特点： 仓库包含 tokenizer、提示编码参考和最小 PyTorch 推理实现，覆盖视觉编码器与 aligner、DFlash attention、MoE、Hyper-Connections 和 DSpark forward path；OpenAI 风格 JSON 内容块与 <image>path</image> 文本格式可编码为等价提示。模型卡没有披露参数量、上下文长度、最低显存或推荐硬件。
  • 适用场景： 适合研究多模态 Agent、终端与图形界面任务、图表理解，以及复现官方最小推理链。生产团队应先验证依赖、显存、吞吐、图像输入边界和长任务稳定性；实验版身份不适合直接当成成熟服务承诺。
  • 关键数据： Trend Score 432；Downloads 17,893；Likes 439；参数与上下文未披露；官方 vLLM 示例为单台 4×GB300；SHA 6821d6ad3681。
  • 许可与风险： 仓库 README 与 LICENSE 均标注 MIT。模型卡给出的文本与多模态 Agent benchmark 来自发布方设置，其中 DeepSeek 模型使用特定 harness、max reasoning effort、temperature 1.0 与 top_p 0.95；这些结果不能外推为所有任务上的全面领先。卡片也没有提供系统性的安全、偏见与事实性限制说明。

7. tencent/Hy4-preview

  • 模型简介： Hy4-preview 是腾讯 Hy 团队的新一代 MoE 旗舰预览模型，当前仓库为 Instruct 版本，面向软件工程、办公、游戏和科研任务。
  • 为什么热： Trend Score 375，Downloads 3,516，Likes 380。770B/49B、1M 上下文与 FP8 多卡服务形成清晰的新模型信号。 榜单位置只代表当前平台关注度。
  • 技术特点： 模型卡给出 770B 总参数、每 token 激活 49B、78 层；77 个 MoE 层使用 256 个路由专家与 1 个共享专家，每 token 激活 top-8 + shared。另有原生 MTP 层用于 speculative decoding，注意力采用 Gated DSA + IndexCache，残差使用 iHC，上下文为 1M。
  • 适用场景： 适合长时软件工程、跨文件办公分析、游戏原型、科研推理和工具调用。官方 vLLM/SGLang 示例采用 FP8、TP=8 与 MTP speculative decoding，更接近多卡服务评估对象；模型卡没有给出具体 GPU 型号与显存下限。
  • 关键数据： Trend Score 375；Downloads 3,516；Likes 380；参数 770B / 49B 激活，另有 10B MTP / 0.7B 激活；上下文 1M；SHA 705d81ee5156。
  • 许可与风险： Apache-2.0，允许商用与衍生并要求保留标准许可声明。它明确是 early preview，模型卡承认复杂任务可能思考过久并出现过度自我验证；内部任务对比属于发布方评测，需用真实工作负载复核。

8. unsloth/Qwen3.8-27B-GGUF

  • 模型简介： 这是 Qwen/Qwen3.8-27B 的 Unsloth GGUF 衍生仓库，目标是把 27B 原生视觉语言模型带到本地量化推理与桌面工具中；它没有改变基础模型身份。
  • 为什么热： Trend Score 352，Downloads 9,354,057，Likes 3,323。超过九百万累计下载说明 GGUF 工件有稳定使用面，但不是当日增量。 榜单位置只代表当前平台关注度。
  • 技术特点： 基础模型为 27B dense、64 层，原生上下文 262,144。仓库提供从低比特 IQ/Q 系列到 Q8、BF16 的多档工件，并包含多模态所需的视觉投影文件；模型卡未给最低 RAM/VRAM，也没有统一独立测评每档量化损失。
  • 适用场景： 适合 llama.cpp 与兼容 GGUF 工具上的离线多模态助手、代码 Agent、长文档和视频理解。视觉任务不能只下载语言 GGUF，还要核对 mmproj；低比特更省内存，但质量与速度必须实测。
  • 关键数据： Trend Score 352；Downloads 9,354,057；Likes 3,323；基础模型 Qwen/Qwen3.8-27B；GGUF 量化/转换衍生版；SHA 4ca720788d1e。
  • 许可与风险： README 标注 Apache-2.0，并指向 Qwen/Qwen3.8-27B；固定 SHA 下未见独立 LICENSE 文件。分发仍要遵守基础模型许可义务，发布方对量化精度的声明也不能替代目标硬件与任务测试。

9. Lightricks/LTX-2.5

  • 模型简介： LTX-2.5 是开放权重音视频生成模型，可从文本、图片和视频输入生成同步视频与音频。2.5 版加入原生多镜头生成、扩散式视频解码器、提示增强和可选时长预测。
  • 为什么热： Trend Score 331，Downloads 1,232,274，Likes 2,444。它是 Top 10 中唯一以联合音视频生成为主的模型，应用边界与语言模型明显不同。 榜单位置只代表当前平台关注度。
  • 技术特点： 模型族按组件发布，包含 22B DiT 的 dev 与 distilled 版、自定义 12B 文本编码器、视频/音频 VAE、LoRA、时长头和时空上采样器；另有 ComfyUI int8 与特定硬件量化变体。distilled 版固定 8-step、CFG=1，dev 版可训练。
  • 适用场景： 适合广告分镜、短片预演、多镜头连续性、图生视频和 LoRA 定制。Python 路线列出较新的 Python、CUDA 与 PyTorch 要求，可用 fp8-cast 加 CPU offload 降低显存压力；模型卡仍未给最低显存数字。
  • 关键数据： Trend Score 331；Downloads 1,232,274；Likes 2,444；主要组件 22B DiT + 自定义 12B 文本编码器；gated auto；SHA 5e6e71018ee1。
  • 许可与风险： 使用 LTX-2.x Community License；免费商用范围受实体收入门槛约束，超过门槛或转让特定衍生权重可能需要付费协议。模型不用于提供事实信息，可能放大偏见、偏离提示或生成不当内容；访问页面可见不等于权重无需接受条款即可下载。

10. unsloth/GLM-5.3-Flash-GGUF

  • 模型简介： 这是 zai-org/GLM-5.3-Flash 的 Unsloth GGUF 量化与转换仓库，目标是把 320B/18B 激活的原生多模态模型带到 llama.cpp 与桌面部署场景。
  • 为什么热： Trend Score 314，Downloads 63,718，Likes 322。基础模型升温后，部署团队继续寻找可落地的量化格式。 榜单位置只代表当前平台关注度。
  • 技术特点： README 明确 base model 关系，并复述 320B 总参数、18B 激活、混合注意力与多模态定位；仓库提供 BF16、Q8_0 及多档 IQ/Q 量化目录。模型卡没有公开最低内存、显存、速度或各档量化的独立质量对比。
  • 适用场景： 适合有大内存、多设备或 CPU offload 条件，希望以 GGUF 运行 GLM-5.3-Flash 的本地多模态与 Agent 用户。低比特示例不等于普通消费级设备可以顺畅运行 320B 模型。
  • 关键数据： Trend Score 314；Downloads 63,718；Likes 322；基础模型 zai-org/GLM-5.3-Flash；GGUF 量化/转换衍生版；SHA 2975ab414d30。
  • 许可与风险： README 标注 MIT 并指向同为 MIT 的基础模型，固定 SHA 下未见独立 LICENSE 文件。分发需保留基础模型版权与许可声明；部分运行路径依赖特定上游改动，兼容性不能按所有稳定版工具一概而论。

读榜结论

需要相对直接的私有化入口，Qwen3.8-27B 的 27B 稠密结构与 Apache-2.0 更容易进入评估；需要长上下文与多模态高吞吐服务，Qwen3.8-Flash-Next、GLM-5.3-Flash 和 Hy4-preview 提供更激进的稀疏路线，但模型卡没有替团队回答真实硬件成本。

三款 GGUF 仓库解决部署格式，不会改写基础模型的能力、许可与风险。DeepSeek-V4-Flash-Vision-Exp 适合实验性多模态 Agent 研究，LTX-2.5 面向音视频生产；两者都应先用真实任务与目标硬件做小规模验证。

数据来源：Hugging Face Models Trending 官方榜单，以及各模型固定快照提交的 Model Card。Trend Score 仅表示趋势排序，不代表性能、质量或安全排名。
