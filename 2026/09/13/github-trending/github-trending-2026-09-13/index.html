一颗能追踪航班、船舶和卫星的三维地球，拿到了今天榜单里最醒目的增量：gods-eye-view 新增 2,265 Stars。它把分散的公开信息放进同一个可探索的空间；排在第二的 DeskcommCRM，则把聊天、客户资料和 AI 销售助手装进企业自己的系统。两者解决的问题不同，却都把现成的数据和服务变成了可操作的产品。

2026 年 9 月 13 日的 GitHub Trending 前十还包括苹果设备侧载、家庭媒体管理、数学建模与 AI 应用示例。选型时有两处尤其不能略过：MathModelAgent 的授权限制商业使用，SmartTube 的 README 披露了开发环境遭恶意软件感染的事件。热度值得看，许可范围和软件来源同样决定这些工具能否进入日常工作。

1. bilawalsidhu/gods-eye-view

  • 项目简介：把公开航班、船舶、卫星、地震和摄像头信息汇集到浏览器中的三维地球。用户可以点选目标、跟随航班切换视角，也能在配置相应服务后用语音控制场景。它的价值是把原本要在多个页面查找的信息放到同一张空间底图上。

  • 为什么火：今日新增 2,265 Stars。可交互的地球让公开数据的用途很容易被看懂，README 又提供了无需密钥的启动路径，降低了初次体验门槛。不过，写实三维效果与语音功能仍各有服务前提，不能把演示里的全部效果理解为零成本默认可用。

  • 技术亮点：README 将数据层设计为独立模块，并允许把相机、样式、图层及选中目标保存到分享链接。数据口径也分得较清楚：交通车辆沿真实道路模拟，并非逐车实时观测；摄像头朝向和火箭轨迹存在估算。科幻式画面不等于军用传感器的测量精度。

  • 适用场景：适合地理信息教学、公开来源信息研究和空间可视化原型。用于商业展示前要逐项核对地图、数据集和三维模型条款；代码的 MIT 授权不覆盖这些第三方材料，也不自动覆盖项目演示动图。

  • 关键数据：语言 JavaScript；Stars 29,454；Today +2,265；Forks 5,956；License MIT（数据/素材另许可）；最近推送 2026-09-12 19:52:51 UTC；Topics：3d-globe、cesium、flight-tracking、geospatial、geospatial-intelligence、gis；Homepage：https://maptheworld.ai/。项目说明见 README。

2. melgarafael/DeskcommCRM

  • 项目简介：围绕 WhatsApp 销售搭建的客户关系管理系统。聊天收件箱、联系人、销售阶段和 AI 助手放在一起，目标是让助手回答咨询、筛选线索、推进跟进，再在需要时交给人工处理。

  • 为什么火：今日新增 505 Stars。对靠聊天成交的小团队，客户消息和销售记录分散是很具体的麻烦；把自动回复接到真实业务状态上，比一个独立聊天窗口更有采用理由。这是产品用途上的吸引力，Stars 本身并不能证明销售转化提高。

  • 技术亮点：技术栈包括 Next.js、TypeScript 和 Supabase。文档描述了按租户隔离的数据与知识库、AI 转人工记录，以及事件驱动的自动化规则。MCP（模型上下文协议）提供 AI 调用外部工具的统一接口，项目用它暴露 CRM 操作能力。

  • 适用场景：适合有服务器维护能力、以 WhatsApp 经营客户的中小团队。部署要准备数据库、域名和模型服务；文档中的 WAHA 接入与 Meta 官方渠道是两条不同路径，相关平台条款、费用和隐私合规仍需自行核对，不能把自托管等同于自动合规。

  • 关键数据：语言 TypeScript；Stars 1,729；Today +505；Forks 542；License MIT；最近推送 2026-09-12 19:40:07 UTC；Topics：ai、ai-agents、chatbot、crm、customer-support、ecommerce；Homepage：https://deskcomm.com.br。项目说明见 README。

3. asgeirtj/system_prompts_leaks

  • 项目简介：收集多家 AI 产品系统提示词的社区资料库。系统提示词是应用在用户提问前设置的行为说明，例如回答风格、工具规则和任务边界；这个仓库把作者声称提取到的文本按产品整理。

  • 为什么火：今日新增 357 Stars。做 AI 应用的人需要理解产品行为如何被组织，按产品和日期整理的文本便于比较。但这些是社区收录材料，不是厂商逐条认证的技术文档，也不能凭其中出现的模型名判断某个产品已经正式发布。

  • 技术亮点：README 提供最近增补记录以及按厂商、产品、组件划分的文件索引。它适合做文本差异和规则组织研究，不提供模型权重，也无法靠复制一份提示词重建原产品的工具、权限和运行环境。

  • 适用场景：适合提示词研究、产品交互设计和安全评审时的对照阅读。引用时应保留来源与版本，重要机制还要回到官方文档核实；仓库的 CC0 声明也不能替第三方文本保证权利清晰。

  • 关键数据：语言 JavaScript；Stars 65,312；Today +357；Forks 10,726；License CC0-1.0；最近推送 2026-09-09 22:44:38 UTC；Topics：ai、ai-agents、ai-prompts、anthropic、chatbot、chatgpt；Homepage：—。项目说明见 README。

4. nab138/iloader

  • 项目简介：用于向苹果设备安装 SideStore 或其他 IPA 应用包的桌面工具。它把登录、安装、导入配对文件和管理开发证书放进图形界面，减少在多个命令和工具之间切换的次数。

  • 为什么火：今日新增 209 Stars。侧载流程的障碍往往是配对文件、证书和错误提示，iloader 直接围绕这些操作提供界面。对于已经知道自己要安装什么的人，少处理几次底层细节就是实际价值。

  • 技术亮点：项目使用 Tauri 构建桌面应用，README 列出 idevice 设备通信和 isideload 安装组件。功能包括导入任意 IPA、放置配对文件、查看并撤销开发证书与应用标识，以及针对常见问题给出错误建议。

  • 适用场景：适合个人设备上的应用测试与侧载管理。安装仍涉及 Apple ID、设备信任和开发签名，不会消除苹果平台自身的限制；应用包来源与证书权限应单独审查。品牌图标另有使用规则，教程引用应保留官方链接且不暗示官方背书。

  • 关键数据：语言 TypeScript；Stars 3,052；Today +209；Forks 209；License MIT（品牌另有限制）；最近推送 2026-09-10 20:49:24 UTC；Topics：idevice、ios、sideloading、sidestore；Homepage：https://iloader.app。项目说明见 README。

5. Flowseal/zapret-discord-youtube

  • 项目简介：面向 Windows 的 zapret 配套工具集，集中处理 Discord、YouTube 等服务的连接问题。仓库通过批处理入口组织不同策略，并提供服务安装、状态检查和诊断功能。

  • 为什么火：今日新增 52 Stars，在前十中增量较小，不能称为突然爆红。它对应的是持续存在的连接与兼容问题；项目把策略切换和诊断收在一起，方便用户按自己的网络条件排查。

  • 技术亮点：README 说明其使用 WinDivert 拦截和过滤流量，二进制来自上游 zapret 项目。服务管理可以启停策略、更新地址列表并执行连通性检查。策略效果取决于网络环境，批处理文件本身并不构成普遍有效的连接保证。

  • 适用场景：适合了解 Windows 网络配置、并获准调整所在网络的用户。流量驱动可能触发安全软件告警，应先核对下载来源与文件校验值，不应为省事整体关闭防护；同时遵守当地法律和网络管理政策。

  • 关键数据：语言 Batchfile；Stars 33,198；Today +52；Forks 2,539；License 主项目 MIT；随附 WinDivert 为 LGPL-3.0 或 GPL-2.0 二选一；最近推送 2026-08-30 20:32:38 UTC；Topics：—；Homepage：—。项目说明见 README。

6. jihe520/MathModelAgent

  • 项目简介：把问题分析、数学建模、编程、绘图和论文排版串起来的项目。当前 README 强调以 Skills 组织工作：这些是供编码助手调用的分阶段任务规范，项目同时提供桌面版和既有部署路径。

  • 为什么火：今日新增 264 Stars。数学建模需要反复在公式、代码与文稿之间核对，成套工作流比单次问答更贴近实际任务。文档列出 17 套 Typst 论文模板，能降低排版起步成本；排版完整并不代表模型假设、数值或结论正确。

  • 技术亮点：Typst 是用文本编写排版文档的工具，项目围绕它组织模板、建模知识与分阶段验收。需要留意 README 的内部边界：功能清单提到人工审批与知识库，但计划区仍把部分人工协作、检索和容错集成标为未完成，不能把愿景清单当成全部可用功能。

  • 适用场景：适合练习建模流程、搭建个人辅助工具，并由使用者复核数据、计算和引用。作者明确提醒项目处于实验阶段，不能许诺获奖或直接交稿；参赛还应遵守赛事 AI 使用规则。授权仅允许个人免费使用，禁止商业服务及闭源分发，商业用途需联系作者。

  • 关键数据：语言 Python；Stars 5,099；Today +264；Forks 401；License 个人非商用（非 OSI）；最近推送 2026-09-10 20:40:40 UTC；Topics：agent、llm、mathmodel、skills；Homepage：https://mathmodel.top/home。项目说明见 README。

7. Sonarr/Sonarr

  • 项目简介：为 Usenet 和 BitTorrent 用户设计的个人录像管理工具。它监测剧集更新、配合下载客户端取得内容，并整理命名、扫描缺集，在有更高质量版本时按规则升级媒体文件。

  • 为什么火：今日新增 228 Stars。媒体库一旦变大，追踪更新、识别缺集和统一命名会成为长期维护负担。Sonarr 把这些重复操作集中管理，这类持续需求能解释它为何仍有关注价值，却不能据此推断今天发生了特定版本事件。

  • 技术亮点：README 列出下载失败后尝试其他版本、可配置命名和手动搜索，并说明与 SABnzbd、NZBGet、Kodi、Plex 的集成。它负责协调剧集信息、下载任务和媒体库，底层内容传输仍依赖配套系统。

  • 适用场景：适合维护家庭服务器或合法授权媒体库的用户。需要自行配置索引来源、下载客户端及存储权限；自动管理功能不会授予剧集版权，只应处理有权获取和保存的内容。

  • 关键数据：语言 C#；Stars 15,889；Today +228；Forks 1,952；License GPL-3.0；最近推送 2026-09-12 05:06:23 UTC；Topics：—；Homepage：https://sonarr.tv。项目说明见 README。

8. alsk1992/CloddsBot

  • 项目简介：把自然语言对话接到预测市场、加密资产和期货操作的个人交易终端。项目提供浏览器聊天入口，也描述了消息平台接入、交易工具和组合管理能力。

  • 为什么火：今日新增 377 Stars。它将行情、策略查询与交易操作放到一个对话入口，容易吸引自动化交易开发者。README 中的市场覆盖和策略数量属于项目方陈述，既不是实盘盈利记录，也不能说明在不同市场上都具备可用优势。

  • 技术亮点：README 描述了内置 WebChat、SQLite 会话持久化、较早对话的摘要压缩，以及多市场工具接入。这些模块解决交互和任务组织问题；交易安全仍取决于密钥权限、订单约束和外部接口行为，不能由聊天体验代替验证。

  • 适用场景：适合有交易系统经验的开发者研究接口编排。优先采用只读密钥和模拟环境，把真实下单与资金权限隔离；不要用榜单热度作为入金依据，预测市场和衍生品还受所在地及平台准入规则约束。

  • 关键数据：语言 TypeScript；Stars 2,439；Today +377；Forks 308；License MIT；最近推送 2026-09-12 03:58:12 UTC；Topics：agi、ai、arbitrage、claude、crypto、defi；Homepage：https://www.cloddsbot.com。项目说明见 README。

9. yuliskov/SmartTube

  • 项目简介：为 Android TV 和电视盒子优化的媒体客户端，提供适配遥控器的界面、播放速度调整和 SponsorBlock 集成。SponsorBlock 利用社区标记跳过视频中的赞助片段，覆盖程度取决于社区数据。

  • 为什么火：今日新增 160 Stars。电视上的播放控制和界面体验是长期需求，不过当前最需要关注的是供应链风险：维护者在 README 开头披露开发环境曾感染未知恶意软件，少数构建可能受到影响，并表示已清理环境、重建发布设置。该说明不能替每个安装包证明安全。

  • 技术亮点：项目列出高分辨率、高帧率和 HDR 播放支持，但实际效果受硬件及编码格式限制。文档也明确手机和平板不受支持，评论功能不稳定，语音搜索与投屏表现可能不及官方客户端。

  • 适用场景：适合 Android TV 用户在确认设备兼容性和软件来源后评估。已安装用户应先阅读安全公告、核对新版本与密钥变更，必要时撤销第三方连接授权，并保留系统安全防护；VegaOS 设备不能按 Android TV 兼容处理。

  • 关键数据：语言 Java；Stars 33,169；Today +160；Forks 2,012；License MIT；最近推送 2026-09-12 01:12:18 UTC；Topics：android、android-tv、android-tv-box、java、kotlin、retrofit2；Homepage：https://smarttubeapp.github.io。项目说明见 README。

10. Shubhamsaboo/awesome-llm-apps

  • 项目简介：按用途整理的 AI 应用代码集合，涵盖入门助手、多智能体协作、语音应用、工具连接与检索增强生成。检索增强生成（RAG）指先从外部资料中找到相关内容，再让模型据此回答，适合有自有文档的应用。

  • 为什么火：今日新增 237 Stars，累计 137,556 Stars。对想实现一个具体功能的开发者，已有目录和可运行入口比宽泛的能力演示更容易起步。累计关注体现了示例库的传播范围，不能替代对每个子项目维护状态的判断。

  • 技术亮点：README 把项目分为单文件入门示例、进阶应用、长期运行助手、语音与 MCP 等类别；部分工具以 Skills 形式安装。各目录有自己的依赖和服务前提，应逐项阅读，不能把整个集合看作统一架构或一个安装后全能的应用。

  • 适用场景：适合学习、做原型和寻找实现参考。正式接入业务前，逐个核查模型费用、外部数据服务、鉴权、测试与许可证依赖；医疗、法律或投资类示例尤其不应直接当作专业结论来源。

  • 关键数据：语言 Python；Stars 137,556；Today +237；Forks 20,230；License Apache-2.0；最近推送 2026-09-12 03:45:58 UTC；Topics：agents、llms、python、rag；Homepage：https://www.theunwindai.com。项目说明见 README。

怎么选

如果要从今天的榜单里选一个项目开始，先按任务缩小范围：空间可视化看 gods-eye-view，聊天销售看 DeskcommCRM，AI 原型参考 awesome-llm-apps。涉及客户数据、交易资金或设备授权时，先在隔离环境验证权限和失败行为；MathModelAgent 的非商用限制与 SmartTube 的安全公告，应在安装或复用之前读完。
