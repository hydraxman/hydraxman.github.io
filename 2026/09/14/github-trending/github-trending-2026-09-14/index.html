把大模型放回自己的机器，把 AI 接进销售和制作流程，成了今天 GitHub 热榜上两条醒目的路线。colibri 用硬盘、内存和显存协同运行大模型，DeskcommCRM 把智能体放进 WhatsApp 销售过程；God’s Eye View 则把航班、卫星与公共摄像头放进同一个三维地球，今日新增 2,898 Stars，在这十个项目中增量最高。

另一边，企业管理平台 Ever Gauzy 与电视客户端 SmartTube 仍占有位置。功能够多、页面够酷，都不能替代采用前的判断：硬盘推理可能慢，地图数据另有使用条款，音乐模型权重有非商业限制，电视客户端还需要留意维护者的安全公告。日榜反映关注度，不等于产品成熟度或安全认证。

1. JustVugg/colibri

  • 项目简介： 一个用 C 编写的大模型推理引擎，重点运行混合专家模型（MoE）：每次生成只调用部分专家网络，因此可以把常用权重留在快内存，其余按需从硬盘读取。它提供聊天、服务接口和网页入口，目标是扩大现有硬件能运行的模型范围。

  • 为什么火： 今日新增 960 Stars。它的吸引力是降低大模型对大显存的依赖，尤其适合已经有工作站、却不想把全部推理迁到云端的人。能启动模型与交互足够流畅仍是两回事，不能把“硬件可用”读成“低成本高速”。

  • 技术亮点： 把显存、内存与 NVMe 固态硬盘组织成分层存储，结合专家缓存、热度统计和预取，并提供 CPU、CUDA、Metal 等执行路径。维护者明确表示没有速度服务保证；优化默认不得暗中改变模型精度或专家路由语义。

  • 适用场景： 本地推理研究、异构工作站实验、需要保留数据控制权的开发者。先用实际任务测首字延迟、持续生成速度与磁盘读量；引擎的 Apache-2.0 许可不自动覆盖所加载模型的权重。

  • 关键数据： 语言 C；Stars 29,502；Today +960；Forks 3,215；License Apache-2.0；最近推送 2026-09-13（UTC）；Topics：—；Homepage：https://justvugg.github.io/colibri。项目说明见 README。

2. ever-co/ever-gauzy

  • 项目简介： Ever Gauzy 把企业资源计划、客户管理、人事、招聘、项目与工时管理放在同一平台。它也提供桌面计时应用和后端接口，适合把人员投入、项目进度与收支信息关联起来，而不只是再做一个客户通讯录。

  • 为什么火： 今日新增 58 Stars，明显低于本榜几个 AI 项目。它代表的是另一种需求：团队仍需要可自行部署、可扩展的经营软件。今天上榜值得关注，但这点增量不足以支持“突然爆红”的判断。

  • 技术亮点： 平台支持多组织、角色权限、计时与活动记录；服务器和桌面组合可使用 SQLite，或连接外部 PostgreSQL。公开接口让它能作为业务后端，不过功能越多，数据迁移、权限设计和运维工作也越重。

  • 适用场景： 代理商、外包团队和需要按项目核算成本的中小组织。员工截图与活动监控必须先取得适当授权；社区版使用 AGPL-3.0，另有商业许可，改造后通过网络提供服务前要评估源码提供义务。

  • 关键数据： 语言 TypeScript；Stars 4,900；Today +58；Forks 931；License AGPL-3.0（社区版）；最近推送 2026-09-13（UTC）；Topics：accounting / billing / bookkeeping / crm / crm-platform / erp；Homepage：https://gauzy.co。项目说明见 README。

3. bilawalsidhu/gods-eye-view

  • 项目简介： 在浏览器里探索三维地球，叠加航班、船舶、卫星、地震和公共摄像头等信号。它支持跟踪目标、切换视觉效果和语音操作；许多基础图层无需密钥即可开始使用，逼真的三维底图则取决于额外服务。

  • 为什么火： 今日新增 2,898 Stars，兼具演示传播力与可探索性：读者可以从全球视角一路进入某个航班或地点。视觉冲击并不说明每层数据都实时准确，交通流使用模拟，摄像头姿态等也可能是估计值。

  • 技术亮点： 数据层分模块组织，视角、样式、图层和跟踪目标可以编码到分享链接；语音智能体还能在地球上添加路线与标记。它汇聚的是公开及第三方信号，项目明确拒绝具名个人检索、人脸识别或个人追踪功能。

  • 适用场景： 地理信息教学、公共数据探索与三维交互原型。不得用于航行、应急等安全关键决策。MIT 仅覆盖源码；地图服务、数据集和三维模型各有条款，含 Google 三维瓦片的展示 GIF 也不授予独立复用许可。

  • 关键数据： 语言 JavaScript；Stars 31,591；Today +2,898；Forks 6,342；License MIT（数据/资产另许可）；最近推送 2026-09-13（UTC）；Topics：3d-globe / cesium / flight-tracking / geospatial / geospatial-intelligence / gis；Homepage：https://maptheworld.ai/。项目说明见 README。

4. tech-leads-club/agent-skills

  • 项目简介： 面向 Claude Code、Cursor、Copilot 等编码智能体的技能目录与安装工具。Skill 是把操作说明、模板和参考资料打包的能力单元；这里强调的不只是收集数量，还包括技能从分发到落盘的可检查性。

  • 为什么火： 今日新增 215 Stars。智能体能执行文件和工具之后，随手安装一份来历不明的技能就可能扩大风险。这个项目把安全审查与多客户端安装放在同一入口，有明确的工程价值，但“已扫描”不能等同于“绝对安全”。

  • 技术亮点： README 描述了内容哈希、锁文件、静态检查与发布前技能扫描，也列出路径隔离、符号链接防护和审计记录。工具引擎与技能内容分别授权：前者 MIT，维护者编写的技能通常为 CC-BY-4.0，第三方技能保留原许可。

  • 适用场景： 给团队统一分发编码规范、测试流程和专门操作知识。启用前仍应阅读技能会调用的工具、权限和外部地址；把它引入生产仓库时，固定版本并保留署名，比单看目录的安全口号更可靠。

  • 关键数据： 语言 TypeScript；Stars 5,566；Today +215；Forks 498；License MIT + CC-BY-4.0（分层）；最近推送 2026-09-12（UTC）；Topics：agent / ai / antigravity / claude-code / copilot / cursor；Homepage：https://agent-skills.techleads.club。项目说明见 README。

5. melgarafael/DeskcommCRM

  • 项目简介： 一个可自行部署的客户关系管理系统，围绕 WhatsApp 对话组织销售。智能体可以接待、筛选线索、移动销售阶段，并把需要人判断的会话移交给员工；同一系统还管理联系人、知识库、预算与操作记录。

  • 为什么火： 今日新增 444 Stars。它把 AI 的价值放在跟进客户、分配线索和交接人工这些具体动作上，适合靠聊天成交的业务。项目声称的合规设计或防封措施，不代表自动获得隐私合规认证，也不保证平台账号永不受限。

  • 技术亮点： 前端使用 Next.js，数据与身份能力基于 Supabase；按组织隔离的知识检索帮助智能体回答问题，数据库行级权限限制不同客户的数据范围。MCP（模型上下文协议）把 CRM 操作暴露给智能体，事件队列处理自动化规则。

  • 适用场景： 诊所、房产、代理商及其他以 WhatsApp 获客的团队。它支持 WAHA 与 Meta 官方通道，但服务器、模型调用及部分连接组件仍有成本；上线前要实测租户隔离、人工交接和客户停止联系的处理逻辑。

  • 关键数据： 语言 TypeScript；Stars 2,120；Today +444；Forks 580；License MIT；最近推送 2026-09-12（UTC）；Topics：ai / ai-agents / chatbot / crm / customer-support / ecommerce；Homepage：https://deskcomm.com.br。项目说明见 README。

6. calesthio/OpenMontage

  • 项目简介： 把研究、提案、文案、分镜、素材、剪辑与合成组织成一套视频生产流程。它通过技能文件指导编码智能体使用制作工具，覆盖讲解、纪录蒙太奇、屏幕演示等任务，既能调用生成服务，也能剪辑已有的真实运动素材。

  • 为什么火： 今日新增 383 Stars。对创作者而言，难点常在多个工具之间接力，而非单独生成一张图或一段视频。它提供完整阶段与可恢复状态，降低流程拼装负担；“完整工作流”仍不意味着每次输出都可免审交付。

  • 技术亮点： YAML 定义制作流程，技能说明每阶段的操作与检查方式，结构化模式约束阶段产物；合成可按任务选择 React/Remotion 或 HTML/GSAP 的 HyperFrames 路径。字幕、音频、素材搜索和最终编码由不同工具配合完成。

  • 适用场景： 需要反复制作教程、短视频或素材混剪的技术型创作者。离线配音和公开素材可以减少付费依赖，但来源、署名和使用范围仍须逐项核对；云端生成费用、制作软件条款不因主仓库采用 AGPL-3.0 而消失。

  • 关键数据： 语言 Python；Stars 58,314；Today +383；Forks 7,343；License AGPL-3.0；最近推送 2026-09-06（UTC）；Topics：agent / agentic-ai / ai / claude / copilot / cursor；Homepage：https://www.openmontage.video/。项目说明见 README。

7. asgeirtj/system_prompts_leaks

  • 项目简介： 按厂商和产品整理系统提示词文本及相关资料，并提供最近更新索引。这类文本描述聊天产品或编码助手在用户提问之前收到的行为要求；它是第三方整理的研究材料，不是厂商正式发布的完整规范。

  • 为什么火： 今日新增 727 Stars。README 的最近更新表包含 9 月 13 日新增内容，对关注产品行为变化的人很有吸引力。不过文件名、标注日期和收录声明，都不能独立证明文本真实性、完整性或仍在现网使用。

  • 技术亮点： 按产品与组件拆分文本，让研究者可以比较工具约束、任务风格和版本差异。它的用途主要是文本分析与版本对照，不是可直接提升模型能力的软件；更不能从一份提示词倒推出模型训练细节。

  • 适用场景： 提示设计研究、产品行为比较与教学讨论。引用时应标为第三方样本，避免把内容当成权威接口文档；仓库声明 CC0-1.0，不等于维护者能替所有被收录的第三方文本清除权利争议。

  • 关键数据： 语言 JavaScript；Stars 65,932；Today +727；Forks 10,792；License CC0-1.0（仓库声明）；最近推送 2026-09-13（UTC）；Topics：ai / ai-agents / ai-prompts / anthropic / chatbot / chatgpt；Homepage：—。项目说明见 README。

8. vxcontrol/pentagi

  • 项目简介： 一个可自行部署的自动化安全测试系统，让多个专门智能体协作开展信息收集、测试与报告整理。它把测试工具、执行环境和过程记录放在一起，定位于有授权的安全研究，而非无边界地扫描互联网目标。

  • 为什么火： 今日新增 613 Stars。它把智能体的计划与工具执行放进安全测试这个可观察的工作场景，能帮助团队研究哪些步骤可被自动化。工具调用成功与漏洞结论正确不同，最终判断仍需要测试人员核实。

  • 技术亮点： Docker 环境承载工具执行，PostgreSQL 保存命令与输出，配有可选知识图谱和监控集成。README 还专门讨论如何开放 Docker 能力而不交出宿主机；容器存在不代表宿主机权限天然安全。

  • 适用场景： 授权靶场、企业内部安全验证和测试流程研究。严格限定目标、出站网络与凭据权限。主代码为 MIT，但 NOTICE 与 README 对云 SDK 的许可描述不一致；使用相关组件或服务前，应逐项核对实际版本及合同。

  • 关键数据： 语言 Go；Stars 23,867；Today +613；Forks 3,091；License MIT（云组件条款有歧义）；最近推送 2026-09-10（UTC）；Topics：ai-agents / ai-security-tool / anthropic / autonomous-agents / golang / gpt；Homepage：https://pentagi.com。项目说明见 README。

9. multimodal-art-projection/YuE

  • 项目简介： 当前主分支介绍 YuE2：输入歌词与风格后，先产生可以阅读和修改的旋律、和弦计划，再生成带人声与伴奏的歌曲。旧版 YuE 保留在单独分支，不能沿用旧项目的功能或许可印象来判断当前版本。

  • 为什么火： 今日新增 500 Stars。相较只能反复改提示词，显式乐谱给音乐创作增加了可操作的中间结果：可以先改旋律、和声，再听新版本。README 的自动评测还涉及候选筛选，不能把排行榜均值直接当成所有歌曲的听感结论。

  • 技术亮点： 分阶段接口把乐谱规划、音乐语义生成、声学合成与解码拆开，智能体技能可以围绕乐谱开展修改与比较。编辑会生成一段新的完整录音，不保证保留被修改区域以外的原始波形。

  • 适用场景： 非商业音乐研究、原创旋律实验和可解释的歌曲编辑。快速开始要求 Linux、Python 3.12 以及支持 BF16 的 NVIDIA GPU，24 GB 显存。代码、技能与文档为 Apache-2.0，模型权重另用 CC-BY-NC-4.0，商用前不能混为一谈。

  • 关键数据： 语言 Python；Stars 7,663；Today +500；Forks 858；License Apache-2.0；权重 CC-BY-NC-4.0；最近推送 2026-09-11（UTC）；Topics：ai / audio-generation / deep-learning / foundation-models / gpt / huggingface；Homepage：https://map-yue2.github.io/。项目说明见 README。

10. yuliskov/SmartTube

  • 项目简介： 为 Android TV 与电视盒子设计的媒体客户端，提供适合遥控器的界面、播放速度调节、HDR 与高分辨率支持，也可按设置跳过社区标记的赞助片段。它不依赖 Google Services，但并非所有智能电视系统都能安装。

  • 为什么火： 今日新增 238 Stars。用户对电视端播放控制的需求依旧具体：界面、遥控器操作、内容播放规则都影响日常使用。不过当前 README 首屏是安全公告，这比新功能清单更值得潜在安装者优先阅读。

  • 技术亮点： 它把电视端交互、设备关联与可选 SponsorBlock 服务结合起来。跳过片段依赖社区提交，可能漏标或服务不可用；语音搜索、投屏效果和评论功能也存在设备差异或稳定性限制。

  • 适用场景： 希望调整播放体验的 Android TV 用户，不适用于 Samsung Tizen、LG webOS、Apple TV 或 VegaOS 新设备。维护者称开发环境曾遭恶意软件感染，部分构建可能受影响、公钥也可能泄露；安装前应阅读最新公告并核对官方发布渠道，保持系统安全功能开启。

  • 关键数据： 语言 Java；Stars 33,405；Today +238；Forks 2,028；License MIT；最近推送 2026-09-13（UTC）；Topics：android / android-tv / android-tv-box / java / kotlin / retrofit2；Homepage：https://smarttubeapp.github.io。项目说明见 README。

怎么选

偏向技术实验，可从 colibri 的真实硬件表现和 YuE2 的可编辑乐谱入手；偏向业务应用，先用隔离的测试数据验证 CRM 与视频制作流程。涉及员工、客户、第三方内容或外部服务时，权限与许可检查应早于替换现有系统。
