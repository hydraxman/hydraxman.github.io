让编程助手少说几句客套话、先把下一步讲清楚，也能登上 GitHub 日榜第一。9 月 11 日的榜首 i-have-adhd 今日新增 3,854 Stars；排在第三的 Superpowers，则把需求确认、测试和审查写进助手的工作流程。两者解决的问题相邻：人既要读得懂 AI 的回答，也要能判断它做的事靠不靠谱。

同一份榜单里，还有三维地球、交易终端、本地模型选型和材质绘制工具。它们的使用门槛差别很大，许可证也不能只看一个“公开仓库”标签。Stars 代表关注，不代表产品成熟度；Today 是 GitHub Daily 页面显示的新增 Stars，榜单顺序也不等于按这一列简单排序。

1. ayghri/i-have-adhd

  • 项目简介：它给编程助手增加一组输出规则：先说下一步做什么，多步操作编号，删掉岔题和客套话。Skill 可以理解为一份可复用的工作说明，安装到支持它的助手里，就能在合适的任务中调用；这里改的是回答组织方式，不是底层模型。

  • 为什么火：今日新增 3,854 Stars，排在榜首。README 用修复登录逻辑的前后对比说明价值：从一大段解释，变成具体文件位置、修改动作和测试命令。对于每天要读很多 AI 回答的人，少翻一屏就有直接收益；这也是它比抽象的“提示词优化”更容易理解的地方。

  • 技术亮点：十条规则把动作前置、状态提示、错误表述、下一步建议写成明确约束，用户还能修改自己的版本。规则中的短列表和具体时间估计应服从任务事实，不能为了简短删掉风险，也不能让助手编造耗时。

  • 适用场景：适合嫌回答太长、容易被旁支信息打断的开发者，也适合团队统一故障排查回复。项目面向注意力友好的阅读体验，不提供 ADHD（注意缺陷多动障碍）的诊断或治疗。

  • 关键数据：语言 Python；Stars 37,820；Today +3,854；Forks 2,184；License MIT；最近推送 2026-09-10（UTC 日期）；Topics adhd、claude-、claude-code-plugin、claude-skills、developer-tools、productivity；Homepage —。

2. bilawalsidhu/gods-eye-view

  • 项目简介：在浏览器里的三维地球上看航班、船舶、卫星、地震和公共摄像头，还能用语音切换视角。它把分散的公开信号汇在同一张地图上，便于从全球分布一路看向一个具体目标。

  • 为什么火：今日新增 1,588 Stars。一个能点开探索的地球，比数据接口清单更直观；项目也降低了首次体验的门槛，基础地图与部分图层无需先配置密钥。写实三维城市、语音和部分数据源仍有额外服务条件，不能把演示效果当成全部免费。

  • 技术亮点：CesiumJS 负责三维地理显示，图层按模块组织。README 说明，部分实时数据按 15—30 秒间隔到达，画面延后一段时间再插值，让运动更平滑；公路车流含模拟成分，摄像头姿态和发射轨迹也有粗略估计。屏幕上的连续运动不等于每一帧都有真实观测。

  • 适用场景：适合地理可视化教学、公开数据探索和交互原型，不宜直接用作安全关键决策系统。源码采用 MIT，但海底光缆数据、地图服务、三维模型等各有授权条件；商业使用前要逐项检查，尤其是非商业数据集。

  • 关键数据：语言 JavaScript；Stars 23,693；Today +1,588；Forks 4,935；License MIT（数据另有条款）；最近推送 2026-09-05（UTC 日期）；Topics 3d-globe、cesium、flight-tracking、geospatial、geospatial-intelligence、gis；Homepage https://maptheworld.ai/。

3. obra/superpowers

  • 项目简介：Superpowers 把软件开发方法拆成可组合的 Skills。编程助手先澄清需求和设计，再列实施计划、分派任务、写测试和接受审查，减少直接开写后才发现方向不对的返工。

  • 为什么火：总 Stars 已达 284,622，今日新增 731。它的吸引力在于把“先想清楚、做完要验证”落实成能触发的工作步骤，并为多种编程助手提供安装入口。榜单位置说明关注度，不能直接证明开发速度或缺陷率改善。

  • 技术亮点：测试驱动开发采用“先让测试失败，再实现最小修改，最后整理代码”的顺序；子任务还有两轮审查，分别检查是否符合要求与代码质量。任务规划中列出文件路径和验证步骤，使交接给另一个助手时少依赖隐含上下文。

  • 适用场景：适合需求较复杂、需要多人或多个助手协作的功能开发。只改一句文案时，全套流程可能增加等待和上下文开销；团队可以先从测试与审查部分入手，再决定覆盖范围。

  • 关键数据：语言 Shell；Stars 284,622；Today +731；Forks 25,459；License MIT；最近推送 2026-09-10（UTC 日期）；Topics ai、brainstorming、coding、obra、sdlc、skills；Homepage —。

4. alsk1992/CloddsBot

  • 项目简介：CloddsBot 把自然语言对话、市场数据、策略和订单执行接到一起，面向预测市场、加密现货及永续合约。预测市场交易的是事件结果合约，永续合约则涉及保证金与强平风险；能连接这些平台不等于能稳定赚钱。

  • 为什么火：今日新增 299 Stars，总量为 1,536。项目将自托管聊天入口与多平台交易整合，减少在行情、策略和操作界面之间切换。README 的“1000+ 市场”是项目自述的覆盖范围，不是独立验证过的盈利或可用性成绩。

  • 技术亮点：README 列出统一风险引擎、每日亏损限制、熔断与紧急停止，以及回测和决策记录。套利检测部分注明默认 dry-run，即只演练而不真实下单；这项默认值不能推及所有交易路径，也不能消除不同平台结算、费用和流动性带来的差异。

  • 适用场景：更适合有交易系统经验的人在隔离环境中研究接口、风控和模拟执行。涉及真金白银前，应单独核对每条执行路径的权限、订单限制与退出机制；不要交出主钱包密钥，也不要把项目热度当作投资建议。

  • 关键数据：语言 TypeScript；Stars 1,536；Today +299；Forks 249；License MIT；最近推送 2026-09-10（UTC 日期）；Topics agi、ai、arbitrage、claude、crypto、defi；Homepage https://www.cloddsbot.com。

5. Tencent/teamai-cli

  • 项目简介：TeamAI 用一个共享 Git 仓库分发团队的 Skills、规则、文档和工具连接配置。成员可以继续用不同编程助手，团队把共同做法放在一处维护，避免每个人各自复制一份提示词后逐渐分叉。

  • 为什么火：今日新增 837 Stars。团队同时使用 Claude Code、Codex、Cursor 等工具时，统一约定比统一客户端更容易落地。它还把经验检索和团队改进纳入产品，但 README 将这两层标为 beta，成熟度需要分开看。

  • 技术亮点：分发走“提交修改、审查合并、成员同步”的路径，并支持角色与标签订阅。MCP（模型上下文协议）配置用于连接外部工具；支持矩阵显示不同助手的功能覆盖并不相同。经验召回默认关闭，需要团队或成员明确启用。

  • 适用场景：适合已经积累了有效开发规范、又在多种助手之间协作的团队。共享目录可以存开关与非敏感配置，不应放密码或密钥；引入同步机制之前，也要明确谁有权修改全员使用的规则。

  • 关键数据：语言 TypeScript；Stars 3,698；Today +837；Forks 236；License MIT；最近推送 2026-09-10（UTC 日期）；Topics —；Homepage —。

6. AlexsJones/llmfit

  • 项目简介：下载几十 GB 的模型前，llmfit 先检查处理器、内存、显卡与显存，估算哪些模型和量化版本适合这台机器。量化是用更低精度存储模型参数，通常能节省内存，但质量与速度仍取决于具体模型和运行后端。

  • 为什么火：今日新增 247 Stars。它回答的是本地部署最先遇到的问题：现有硬件够不够用。README 还加入本机测速与社区分享，让同类硬件上的真实测量有机会替代纯规格估算。

  • 技术亮点：推荐从内存适配、预计速度、质量与上下文长度等维度展开，提供终端交互界面、网页界面和 JSON 接口。速度估计结合内存带宽、运行采样和社区测量；详情页可以查看假设，测速功能则用于测实际运行结果。

  • 适用场景：适合个人电脑部署模型、工作站选型和统一设备清单。推荐分数不能替代业务测试，尤其要用自己的提示长度、输出长度和并发条件测一轮，再决定下载或采购。

  • 关键数据：语言 Rust；Stars 35,666；Today +247；Forks 2,260；License MIT；最近推送 2026-09-10（UTC 日期）；Topics gguf、llm、localai、mlx、skill、unsloth；Homepage —。

7. liquidslr/system-design-notes

  • 项目简介：这份笔记围绕 Alex Xu 的《System Design Interview》两卷展开，从估算容量、限流、分布式存储，延伸到聊天、地图、支付和交易所等系统。README 明确写着仍在完善，适合把它当阅读索引。

  • 为什么火：今日新增 891 Stars，说明工程基础内容也能获得相当集中的关注。相比泛泛的架构术语表，按“设计一个具体系统”组织内容，更方便面试准备和查漏补缺；并不需要用 AI 话题解释它的价值。

  • 技术亮点：章节之外还按主题连接 Dynamo、Bigtable 等论文及公司工程文章，能从简化笔记继续追到设计背景。限流用于控制请求速度，一致性哈希用于减少扩缩容时的数据迁移，两类问题各自有适用条件，不能只记名词。

  • 适用场景：适合后端工程师复习系统设计，建议拿一个熟悉的产品自己估算流量与存储，再对照章节。仓库未声明许可证，笔记又基于出版书籍，公开可读不等于可以打包售卖或任意转载。

  • 关键数据：语言 —；Stars 18,664；Today +891；Forks 3,473；License 未声明许可证；最近推送 2026-08-12（UTC 日期）；Topics —；Homepage https://pagefy-blush.vercel.app/system-design/system-design-interview-by-alex-xu。

8. cathrynlavery/diagram-design

  • 项目简介：Diagram Design 给编程助手提供一套图表类型、排版约束和导出方法。输出以自包含 HTML 和 SVG 为主，SVG 是可缩放矢量图形，放大后线条与文字仍能保持清晰，也方便继续编辑。

  • 为什么火：今日新增 1,287 Stars。需求很具体：架构图和流程图要能读懂，也要与自己的文档风格相容。当前 README 列出 39 类图，包括结构、时序、依赖关系与数据库模式；它提供的是表达形式，不负责替项目核实图里的事实。

  • 技术亮点：项目把系统行为与布局形式分开描述，并为图表提供浅色、深色和完整编辑风格的静态变体。静态输出默认无需 JavaScript 或外部图片依赖，另有可选动画用于顺序讲解；也支持把已有图表来源重新排版。

  • 适用场景：适合技术方案、产品说明和团队知识文档。图做得整齐并不能证明架构正确，交付前仍要逐条检查连接方向、节点职责和数据含义；品牌图标也保留各自的商标边界。

  • 关键数据：语言 HTML；Stars 37,603；Today +1,287；Forks 2,387；License MIT（第三方另列）；最近推送 2026-09-10（UTC 日期）；Topics agent-skills、claude-code、codex、data-visualization、diagrams、drawio；Homepage https://cathrynlavery.github.io/diagram-design/。

9. freestylefly/awesome-gpt-image-2

  • 项目简介：这个仓库整理 GPT Image 的提示词、案例、模板和可复用 Skills，覆盖产品展示、海报、界面和知识插图。它把主体、光线、材质与布局拆开，帮助使用者从“照抄一段话”转向修改有明确作用的参数。

  • 为什么火：今日新增 957 Stars。案例同时展示画面目标与提示结构，便于设计者找到起点；README 新增的 GPT Image 2.5 专区提供同提示词对照展示。不过，示例来源和模型条件有明确的不确定性说明，不应把展示页当成模型能力排行榜。

  • 技术亮点：项目把提示词当作可组合的配置资产，并提供分类画廊和模板入口。README 特别注明，2.5 专区没有新增实时 2.5 图像生成功能，部分原始生成条件与精确工具模型标识未核实；看图时应保留这些条件差异。

  • 适用场景：适合为图像任务寻找构图方向、制定模板和建立内部案例集。仓库自身标为 MIT，但第三方提示词与图片不自动继承这份授权，商业使用要回到原始权利人和来源条款确认。

  • 关键数据：语言 JavaScript；Stars 30,778；Today +957；Forks 2,982；License MIT（案例另核授权）；最近推送 2026-09-09（UTC 日期）；Topics agents、ai-image-generation、chatgpt、dsh-plugin、gpt-image-2、image-prompts；Homepage https://gpt-image2.canghe.ai。

10. armory3d/armorpaint

  • 项目简介：ArmorPaint 用于给三维模型绘制 PBR 材质。PBR 指基于物理的渲染：用颜色、粗糙度、金属度等属性描述表面，使同一材质在不同光照下表现更一致。它服务的是三维资产制作流程。

  • 为什么火：今日新增 87 Stars，总量 4,363。与前面的 AI 配套工具相比，它关注更直接的创作操作：怎样把材质画到模型上。这个增量不宜形容成爆红，但它提醒读者，热榜也容得下专业制作软件。

  • 技术亮点：仓库给出 Windows、Linux、macOS、移动平台和 WebAssembly 的构建路径，开发以 C 为主要语言。WebAssembly 使编译后的程序有机会在浏览器环境运行；有构建目标并不等于每个平台都具备相同的稳定性和功能。

  • 适用场景：适合有三维材质制作需求、愿意比较工作流的美术和开发者。README 提醒源码版本面向开发者、可能不稳定，官方预编译版本收费支持开发；源码许可与下载现成软件的价格是两回事。

  • 关键数据：语言 C；Stars 4,363；Today +87；Forks 515；License Zlib；最近推送 2026-09-09（UTC 日期）；Topics 3d、armorpaint、painting、texturing、tool；Homepage https://armorpaint.org。

日常使用编程助手的人，可以先比较 i-have-adhd 的输出规则与 Superpowers 的测试、审查流程；需要团队统一配置，再看 TeamAI。准备跑本地模型时，llmfit 给出的是筛选起点，最终仍要用真实任务验证。涉及交易资金、地图商用或第三方图片时，权限和授权应先于安装决定。
