Qwen3.8-27B 及其衍生版占了今天 Hugging Face 模型热榜的四个席位：原始权重、量化部署、缩短推理和写作微调各有位置。排在第一的 Edge0 则尝试把另一款 Qwen 模型的专家权重留在 SSD 上，按需读入。开发者可选的路径变细了：同一模型的不同包装，可能比换一个更大的模型更贴近眼前的硬件约束。

音乐模型 YuE2 和视频模型 LTX-2.5 也在前十。它们把焦点带到可编辑乐谱、多镜头和音画同步，但创作能力与使用许可要分开看。今天的选型问题可以很具体：任务需要什么输入，硬件能承受多大缓存，生成结果又能否用于商业项目。

1. Edge0/Edge0-35B-A3B-preview

模型简介：Edge0 把 Qwen3.6-35B-A3B 做成了面向本地设备的推理预览包，包含 4-bit 基础权重、低秩适配器 LoRA 和提前预测专家路由的适配器。它的重点是改变权重的加载方式，并非重新训练一个独立基础模型。

为什么热：榜首位置与它解决的问题很契合：本地大模型常先撞上内存容量。把不活跃的权重留在固态硬盘上，能让原本难以常驻内存的模型进入可试用范围。不过，榜单不能说明每位关注者的动机。

技术特点：混合专家模型（MoE）每次只调用部分专家网络；Edge0 按需从 SSD 读入专家，并预测下一步需要谁，让读取与计算重叠。发布者在 24 GB 内存的 Mac mini M4 Pro 上报告，短上下文峰值活跃内存为 2.9 GiB，解码速度为 14.9–17.7 token/s。这个数字不是整机最低内存要求。

适用场景：适合有快速本地存储、希望在 Apple Silicon 上探索离线聊天与推理的开发者。当前 MLX 后端面向苹果芯片，不能把演示直接理解为任意手机都能运行。

关键数据：Trend Score 2,448；Downloads 37,131；Likes 3,292。Hub 标注任务为 text-generation，最近更新为 2026-09-17。

许可与风险：模型卡与其 Qwen 基础模型均声明 Apache-2.0，基础模型许可证另有明确文本。它仍是预览版本，模型卡坦言工具调用、多步规划和长任务能力较弱；长上下文还会增加保存历史状态的缓存。

2. deepseek-ai/DeepSeek-V4.1-Flash

模型简介：DeepSeek-V4.1-Flash 是原生处理图像和文字、输出文字的混合专家模型。模型卡给出的主干规模为 552B，并支持最长一百万 token 的上下文；token 是模型处理文本时使用的片段单位，并不等于汉字数。

为什么热：它把重点放在长输入的服务成本。文档阅读、图文分析和持续调用工具的助手都会积累大量上下文，节省这些历史状态占用的显存，比单看模型名字里的 Flash 更有实际意义。

技术特点：模型采用因果编码器—解码器结构，预填充阶段每个 token 激活 8B 参数，生成阶段激活 16B。KV 缓存用于保存已经读过的内容对应的注意力状态；模型卡报告其全局 KV 缓存压到每 token 890 字节。该值只描述这一类缓存，不是全部权重或完整推理服务的内存。

适用场景：适合能承担大型模型部署的团队，评估长文档、多模态输入及输入量较大的工具任务。需要同时检查服务框架对新结构、缓存精度和图像输入的支持。

关键数据：Trend Score 1,360；Downloads 390,657；Likes 2,983。Hub 标注任务为 image-text-to-text，最近更新为 2026-09-10。

许可与风险：仓库 LICENSE 为 MIT。激活参数少不意味着只需装下激活部分的权重，更不能把大型主干当成小显存模型。官方评测与缓存数据是发布者报告，部署吞吐、延迟和正确率仍取决于自己的硬件与任务。

3. Qwen/Qwen3.8-27B

模型简介：Qwen3.8-27B 是带视觉编码器的稠密模型，语言模型参数为 27B，支持图像和视频理解。与按需选择专家的架构不同，稠密模型主要依靠完整的网络计算路径完成推理。

为什么热：它既独立上榜，也成为后面量化版和高效率推理版的底座。同一个模型衍生出不同部署选择，说明用户关心的不只有能力，还有能否装进现有硬件、推理是否足够经济。

技术特点：模型卡明确区分原生 262,144 token 上下文与扩展至一百万 token 的配置。思考模式默认开启，可以逐次请求关闭，也能调整推理深度、保留历史推理上下文。把原生长度与扩展上限分开，才能正确估算缓存和服务配置。

适用场景：适合需要同一套权重处理文档图像、视频理解、编程和多步任务的开发者。基础格式适合标准推理框架；若主要目标是本地桌面运行，可以比较第 7 项的量化文件。

关键数据：Trend Score 602；Downloads 7,456,257；Likes 15,514。Hub 标注任务为 image-text-to-text，最近更新为 2026-08-14。

许可与风险：模型卡与 LICENSE 均为 Apache-2.0。长上下文、图像数量和推理长度都会推高资源使用；支持一项功能不代表在所有任务上都可靠，尤其应测试长材料中具体信息的定位与引用。

4. m-a-p/YuE2-3B

模型简介：YuE2 可以把歌词与风格描述变成包含人声和伴奏的完整歌曲，也允许围绕可编辑乐谱修改旋律、和弦与编曲。它在这份以语言模型为主的榜单中提供了另一类创作工具。

为什么热：音乐生成常见的难题是满意一半却无法局部修改。YuE2 的吸引力在于把可编辑乐谱放进流程，让创作者有机会保留旋律、调整和声，再重新合成歌曲。

技术特点：它支持旋律加和弦、仅旋律规划或直接生成。ABC 是用文本记谱的格式，开发者可以自行编辑，也可以让外部智能体提出修改再交给模型合成。模型卡给出的本地起步条件包括支持 BF16 的 24 GB NVIDIA GPU；输出为 48 kHz 立体声。

适用场景：适合音乐研究、非商业的歌曲原型、编曲教学和可控生成实验。已有录音也可用于改编流程，但前置的转录、乐谱处理和最终生成不是同一个步骤。

关键数据：Trend Score 601；Downloads 11,626；Likes 710。Hub 标注任务为 text-to-audio，最近更新为 2026-09-16。

许可与风险：权重采用 CC BY-NC 4.0，需署名且限非商业用途；代码、分词文件和其他材料还可能有单独许可。歌曲、歌词、声音和输入录音的权利也要另外确认。模型卡的最佳候选评测包含多次生成后选择，不能当作单次生成的必然质量。

5. TokenRhythm/NeoHorse-1-4B

模型简介：NeoHorse-1-4B 是 TokenRhythm 从 Qwen3.5-4B 后训练而来的约 4B 文本模型，面向工具使用、编程和指令跟随。这个版本只包含语言模型权重，不包含视觉权重。

为什么热：它代表一种与大模型扩容不同的路线：把小模型放进能够记录执行结果的任务环境，再用反馈改进训练。对开发者来说，小模型能否稳定完成一类具体工具任务，比泛泛的聊天印象更值得衡量。

技术特点：相关路由框架会把任务分配给不同模型，记录工具交互与结果，再根据能力需求组织后续训练。这里的框架是模型外部的调度和执行环境，不是权重自身在部署后自动进化。模型卡把递归自我改进定位为原型探索，连续多轮迭代仍是后续方向。

适用场景：适合受控文本工具环境、代码辅助和指令任务的实验。需要图像理解的应用应另选权重，不能因为它来自视觉语言模型家族就默认保留视觉能力。

关键数据：Trend Score 437；Downloads 19,789；Likes 2,280。Hub 标注任务为 text-generation，最近更新为 2026-09-10。

许可与风险：衍生仓库及 Qwen3.5-4B 基础模型均有 Apache-2.0 许可依据。工具任务的成绩不能证明开放环境的安全性；上线前应限制工具权限、隔离执行环境，并保留失败任务与实际输出的测试集。

6. Lightricks/LTX-2.5

模型简介：LTX-2.5 面向本地执行与微调，可从文字、图像或视频输入生成同步的视频和音频。它把多镜头生成列为主要升级点，目标是在切镜头时保持人物、环境、声音和风格的一致性。

为什么热：对于制作短片的人，连续几个镜头是否保持一致，比一张惊艳的静帧更影响可用性。它的吸引力是把镜头组织、视频生成和声音放进同一工作流，而不是保证任意长片都能一次完成。

技术特点：仓库按组件拆分权重，包含完整可训练版、蒸馏版、文本编码器及视频和音频解码组件。蒸馏版给出固定 8 步采样；部分 int8 文件只面向 ComfyUI，不能直接用于另一套 PyTorch 加载路径。

适用场景：适合有本地生成环境的创作者，试验多镜头概念片、图生视频和音画同步。选权重时先对应自己的运行框架，再确认解码器和其他组件，避免仅下载一个文件就期待完整流程可用。

关键数据：Trend Score 425；Downloads 1,602,865；Likes 4,215。Hub 标注任务为 image-to-video，最近更新为 2026-09-01。

许可与风险：这是有访问同意流程的 gated 仓库，采用 LTX-2.x Community License，并非无条件宽松许可。合并计算关联实体后，年营收达到 1,000 万美元的实体，除协议限定的非商业用途外需付费授权；衍生模型转交给此类实体也有约束。还须遵守使用限制、保留透明度与内容来源标记，核对所用组件条款。模型卡明确说它不能提供事实信息，生成画面不应当作真实事件证据。

7. ISTA-DASLab/Qwen3.8-27B-GSQ-RCO-GGUF

模型简介：ISTA-DASLab 提供 Qwen3.8-27B 的非均匀 GGUF 量化文件，以及用于多模态输入的视觉投影组件。GGUF 是常见的本地模型文件格式；量化用较低精度保存权重，以缩小文件和内存需求。

为什么热：它与第 3 项是同一基础模型的不同部署选择。吸引力在于按文件大小预算分配精度，让有限硬件也有更具体的取舍，而不是把量化版包装成一次新的基础模型突破。

技术特点：GSQ（Gumbel-Softmax Quantization）优化低位宽的量化表示，RCO（Riemannian Constrained Optimization）按总大小约束给不同权重张量分配精度。模型卡列出 8.4、9.3、10.1、11.8 GB 四档主文件，另有 0.9 GB 视觉组件；这些是文件大小，不是整套应用的峰值内存。

适用场景：适合用 llama.cpp、Ollama 或 LM Studio 比较不同量化档位的用户。需要图文理解时应同时配置视觉组件，并为上下文缓存和程序本身留出额外空间。

关键数据：Trend Score 421；Downloads 1,027,602；Likes 1,244。Hub 标注任务为 image-text-to-text，最近更新为 2026-09-02。

许可与风险：衍生模型卡与 Qwen3.8-27B 的 LICENSE 均为 Apache-2.0。发布者在特定任务上的接近无损结果，不能推广成所有提示都无损；小文件档位和加速配置都应以自己的任务验证。

8. openbmb/MiniCPM5-2B

模型简介：MiniCPM5-2B 面向本地助手、编程、工具调用和资源受限场景。模型卡给出的总参数为 2,516,756,480，非嵌入参数为 1,981,982,720；名称里的 2B 不应替代精确的参数口径。

为什么热：它提供了另一种本地路线：直接选择较小的稠密模型，而不是把更大的权重切分到存储设备。对于只需要文本处理和特定工具任务的产品，小模型值得先作为成本基线。

技术特点：它采用标准 LlamaForCausalLM 结构、42 层网络，原生上下文长度为 131,072 token。工具调用以 XML 风格文本输出，模型卡建议用 SGLang 的专用解析器转成标准工具调用字段；能生成结构化文字与宿主程序能正确执行，是两个环节。

适用场景：适合离线文本助手、小规模代码任务和工具调用实验。当前仓库是 BF16 的后训练最终版；GGUF、MLX 和其他格式位于独立仓库，选型时要对上运行环境。

关键数据：Trend Score 412；Downloads 329,713；Likes 1,537。Hub 标注任务为 text-generation，最近更新为 2026-09-12。

许可与风险：模型卡明确称仓库与权重采用 Apache-2.0，同时提示输出可能错误、有偏见或被提示操纵。小参数并不免除审核；敏感专业建议不可直接采信，工具执行也需要宿主程序自己的防护。

9. ukisai/Swift-Qwen3.8-27b

模型简介：Swift-Qwen3.8-27b 是 UkisAI 对 Qwen3.8-27B 的推理效率微调版。它通过惩罚一些被认为触发过度思考的标记，训练模型产生较短推理过程，并引入来自 ThinkingCap-Qwen3.6-27B 的迁移组件。

为什么热：生成过程过长会增加等待时间和计算消耗，这让缩短推理成为独立的优化目标。但更短不能单独证明更好：真正有用的比较要同时保留答案质量、任务难度和相同推理设置。

技术特点：其主要对照是 Qwen3.8-27B 的 BF16 基础模型与同一基础模型加 Swift 适配器。模型卡展示不同任务的推理长度与成绩；这些结果适合用作测试假设，不应把一个总括性节省比例直接套进所有工作负载。

适用场景：适合已有 Qwen3.8-27B 工作流、愿意比较延迟与成功率的团队。先用自己的长推理任务对照，再决定短推理带来的收益能否覆盖偶发质量变化。

关键数据：Trend Score 359；Downloads 3,221；Likes 374。Hub 标注任务为 image-text-to-text，最近更新为 2026-09-16。

许可与风险：Qwen 底座仍是 Apache-2.0；Swift 修改部分适用自定义 Swift Open License v1.0，不能沿用底座许可概括整个衍生版。其商用门槛围绕上一完整财年、含关联实体的 100 万美元收入，达到门槛附近应向许可方确认，超出时需另取企业许可。模型卡还标有访问限制说明，实际权重获取条件以仓库当时的同意流程为准。

10. DavidAU/Qwen3.8-27B-TURBO-Fable-Cold-Fusion-735-882-Heretic-Uncensored-NEO-CODER-MAX-MTP-GGUF

模型简介：DavidAU 这一长名称仓库提供经过多阶段微调、合并后的 Qwen3.8-27B 衍生权重的 GGUF 量化版本，同时提供普通版与带多 token 预测组件的版本。它属于社区部署与对齐变体，不是新的独立基础架构。

为什么热：创意写作、较短思考过程和本地编程是其主要卖点。与官方模型相比，这类版本更强调特定输出风格；它上榜说明这一选择受到关注，不能直接推出综合能力更强。

技术特点：MTP 是 Multi-Token Prediction，即一次提出多个候选 token 再验证的加速方式。模型卡提醒，加速效果与候选接受率有关，复杂创作、高温度采样等情况下普通版本可能更合适。不要用同一个速度数字代表所有硬件和提示。

适用场景：适合熟悉 GGUF 工具链的开发者，在隔离环境中比较写作风格、代码输出和普通版/MTP 版的时延。对长名称无需逐词当成功能保证，应以具体文件、运行设置和任务结果为准。

关键数据：Trend Score 352；Downloads 1,116,038；Likes 839。Hub 标注任务为 image-text-to-text，最近更新为 2026-09-16。

怎么选，比排第几更重要

只做本地文本助手，可以先比较 MiniCPM5 与 NeoHorse 的真实任务成功率；已有 Apple Silicon、愿意接受预览版限制，再考虑 Edge0。需要图文能力时，Qwen3.8 原始版与它的量化版提供了不同资源档位，Swift 则多了一层推理长度与自定义商用许可的取舍。

创作工具的筛选顺序还要多加一项权利检查：YuE2 的权重限非商业，LTX 有营收门槛与衍生使用条件。先确认项目能合法使用，再比较生成质量，能避免把一个效果不错的原型做成无法交付的产品。
