让助手先给行动、不要顺手改无关代码、先确认设计再动手：9 月 9 日的 GitHub 日榜前十里，多套项目都在给 AI 编程助手补工作规范。同时，diagram-design 把图表做成可编辑的 HTML 与 SVG，HyperFrames 把网页技术用于视频制作。这里有两种很具体的需求：少做不必要的事，把需要的东西做成可检查的文件。

1. ayghri/i-have-adhd

  • 项目简介： 让编程助手少寒暄、少岔题，先说下一步做什么。它把输出风格写成可安装的 Skill——一组供助手遵循的说明与资源；名称里的 ADHD 指注意缺陷多动障碍，但使用它不需要任何诊断。它提供的是沟通约定，没有声称能治疗或诊断疾病。

  • 为什么火： 从产品设计看，它抓住了一个很日常的痛点：答案藏在长篇铺垫里，读完仍不知道该改哪个文件。比起换一个模型，直接改变回答顺序更容易被用户感知；今天增加的关注与这种轻量定位相符，但不能据此认定具体传播原因。

  • 技术亮点： README 列出十条规则，包括行动优先、多步任务编号、每轮交代当前状态、最后留下一个具体下一步。规则文件可以自行修改，适合把个人沟通偏好带进不同项目；过度压缩输出时仍须保留安全条件和错误上下文。

  • 适用场景： 适合经常在长回复里找命令、需要清晰步骤的人，也适合给团队统一助手回复格式。遇到复杂设计讨论时，应允许解释展开，避免把必要推理压成短指令。

2. cathrynlavery/diagram-design

  • 项目简介： 把架构、流程、状态和数据关系画成可在浏览器打开的 HTML 与 SVG 图表。SVG 是矢量图格式，便于在源文件里修改形状、文字与连线；项目面向 Claude Code、Codex 等支持技能文件的助手。

  • 为什么火： 它的吸引力在于把图表布局做成可复用规则，减少每次都从空白画布重新调整的成本。对需要反复修改架构图、汇报图的开发者而言，可编辑文件比一张无法改字的图片更实用。

  • 技术亮点： 当前 README 列出 39 类图表，并把系统行为模式与具体布局分开。默认静态输出，每类提供简约浅色、简约深色和编辑式三种变体；还支持把 draw.io 或 Mermaid 来源重绘到指定尺寸与细节层级。可选动画不改变静态优先的定位。

  • 适用场景： 适合技术文档、架构沟通和内容配图。自动排出连线不等于关系本身正确：方向、依赖和权限边界仍需作者检查。许可证正文为 MIT。

  • 关键数据： 语言 HTML；Stars 34,501；Today +1,020；Forks 2,190；许可证 MIT；最近推送 2026-09-08 19:45:13 UTC；Topics：agent-skills、claude-code、codex、data-visualization、diagrams、drawio、mermaid、svg；Homepage：项目主页。 README

3. openai/skills

  • 项目简介： OpenAI 曾用于分发 Codex 技能的目录，把说明、程序和资源放进独立文件夹，供助手完成特定任务。现在 README 顶部已明确标为弃用，并推荐使用 openai/plugins 获取当前技能与插件示例。

  • 为什么火： 它仍在今天的榜单中，说明旧入口仍获得关注；这不等于它是新项目，也不等于维护方向没有变化。对正在收藏技能资源的读者而言，最有用的信息是迁移提示，而非再推荐一次旧安装路径。

  • 技术亮点： README 区分随 Codex 提供的系统技能，以及通过安装器选择的精选、实验性技能。许可按技能目录内的 LICENSE.txt 单独提供，不能把整个集合笼统标成 MIT 或 Apache-2.0。

  • 适用场景： 适合了解技能目录的组织方式或检查既有依赖。新接入优先查看官方推荐的 openai/plugins 与插件构建文档；使用旧技能时逐项确认许可和兼容性。

4. affaan-m/ECC

  • 项目简介： ECC 围绕编程助手的运行环境组织技能、专职代理、规则、记忆和安全扫描。所谓 harness，可理解为决定助手何时调用工具、保存什么状态、怎样检查结果的运行框架；它补的是任务执行层。

  • 为什么火： 当一个助手要连续做规划、修改、检查时，分散的提示词很容易失去衔接。ECC 把这些能力放在同一套安装与配置入口下，对希望减少重复配置的用户有吸引力；功能集合规模不直接证明项目交付更稳定。

  • 技术亮点： 事件钩子在特定运行时机触发检查，记忆与会话摘要保存后续可用的信息，AgentShield 负责安全扫描。README 明确表示 Claude Code 当前支持最好，Codex 有同步路径，其他适配器能力受限，不能假设跨平台功能完全一致。

  • 适用场景： 适合愿意管理规则、权限与运行配置的开发者。安装前先对照所用客户端的支持范围，优先启用必要能力；同时叠加多套钩子或重复安装，会增加排查负担。项目也提醒不要把原生插件安装与完整手工安装重复叠加。

  • 关键数据： 语言 JavaScript；Stars 254,109；Today +1,426；Forks 38,102；许可证 MIT；最近推送 2026-09-08 17:39:44 UTC；Topics：ai-agents、anthropic、claude、claude-code、developer-tools、llm、mcp、productivity；Homepage：项目主页。 README

5. heygen-com/hyperframes

  • 项目简介： HyperFrames 让开发者用 HTML、CSS、媒体和动画编排视频，再输出 MP4。它可以通过本地命令行使用，也能让支持 Skill 的编程助手按视频制作流程工作。网页源文件成为可以检查和修改的视频工程。

  • 为什么火： 它在这十个项目中拥有最高的当天新增 Stars。对已习惯写网页的开发者，把现有布局与动画知识用于产品演示、数据动画，学习入口更熟悉；不过热度并不能替代对实际渲染成本和成片质量的判断。

  • 技术亮点： 关键是可定位时间的动画和确定性渲染：跳到指定时间，画面应对应那一刻的状态，而不依赖从头播放后的偶然结果。README 将规划、编写 HTML、接入媒体、检查、预览与渲染串成工作流；本地使用要求 Node.js 22+ 和 FFmpeg。

  • 适用场景： 适合产品介绍、更新演示、数据可视化和可复用动态图形。它承担视频编排与渲染，不替素材解决版权问题；采用前仍要检查字体、音画时序和最终文件，而非只看浏览器预览。

6. coreyhaines31/marketingskills

  • 项目简介： 面向技术营销人员和创业者的技能集合，覆盖文案、搜索优化、数据分析与转化优化。这里的转化是让访问者完成注册、咨询或购买等目标，不只是生成更多营销文字。

  • 为什么火： 代码助手也能参与产品定位、落地页和实验设计，前提是知道产品卖给谁、解决什么问题。这个项目的价值是把营销任务的前置问题与工作方法整理成可复用输入，减少每次从零描述业务背景。

  • 技术亮点： product-marketing 作为共享基础，其他技能先读取产品、受众和定位，再进入各自任务；相关技能之间也有交叉引用。比如文案、转化优化与 A/B 实验互相衔接，实验指向不同方案的实际效果比较。

  • 适用场景： 适合小团队做落地页诊断、文案迭代和营销分析。技能给出的方法不保证收入增长，效果仍要用真实访问与转化数据检验；接入业务工具前也要检查数据权限。项目披露了赞助合作与工具集成关系。

7. obra/superpowers

  • 项目简介： Superpowers 把软件开发方法拆成组合式技能：先通过对话弄清要做什么，确认设计，再形成实现计划，随后执行任务并审查结果。它约束助手的开发次序，而不只是增加一个代码生成入口。

  • 为什么火： 对已经能生成代码的工具，用户还需要控制它在错误假设上走多远。先确认设计、再进入执行的工作方式，适合需求含糊或改动范围较大的任务；今天的上榜更应理解为持续关注，而非仅凭单日排名宣称突然爆发。

  • 技术亮点： README 强调测试驱动开发，即先写能暴露问题的测试，再实现到通过；同时要求避免未被需求证明的功能和重复代码。子代理按任务执行，并配合检查与审查；这些步骤是工作法约束，不是质量保证书。

  • 适用场景： 适合非平凡功能开发、重构和需要设计确认的协作任务。对于简单改字，完整规划与多阶段检查可能比修改本身更重，应按风险选择投入的深度。不同客户端需分别安装，不能假定一处安装处处生效。

8. multica-ai/andrej-karpathy-skills

  • 项目简介： 这是从 Karpathy 对大模型编程问题的观察中提炼的社区指南，核心是一份 CLAUDE.md。仓库名不代表 Karpathy 官方发布；README 将其称为 Karpathy-Inspired，并列出原始观察的链接。

  • 为什么火： 把“先说清假设、保持简单、只改必要部分、用验收标准驱动执行”放进一份文件，门槛比完整工作流框架低。它适合先约束几个反复出现的坏习惯，但高 Stars 不说明这些文字会被每个模型可靠执行。

  • 技术亮点： 四条原则分别处理静默假设、过度抽象、顺手修改无关代码和缺少验证目标的问题。尤其是把“修好它”改成可检查的成功条件，有助于让实现与测试围绕同一目标；README 也明说这套指南偏谨慎而非速度。

  • 适用场景： 适合已有项目加入轻量约束，或作为团队规则的讨论起点。对小改动不必机械套用完整流程；README 声明 MIT，但仓库没有独立许可证文件，正式复用前宜进一步确认授权文本。

9. microsoft/markitdown

  • 项目简介： 微软的 Python 文档转换工具，支持 PDF、Word、PowerPoint、Excel 等输入，并尽量保留标题、列表、表格和链接。主要服务大模型与文本分析流程，不能把它当成高保真排版复刻工具。

  • 为什么火： 助手处理企业资料，首先要读进格式各异的文件。统一成保留结构的文本，能减少后续工具为每种格式分别编写处理逻辑的负担；它今天的关注度较高，与这类基础输入需求很契合，但不证明任何具体客户采用规模。

  • 技术亮点： 依赖可以按文件类型选择，避免为单一场景安装全部格式支持；第三方插件默认关闭。README 特别提醒它以当前进程权限进行文件与网络访问，对不可信输入应限制资源范围，并选用用途最窄的转换接口。

  • 适用场景： 适合知识库入库、资料检索和文档分析前处理。复杂版面、图像文字与原表格含义需要抽样核对；让外部用户提交文件时，应把转换服务放进权限受限的环境。项目要求 Python 3.10 或更高版本。

10. jo-inc/camofox-browser

  • 项目简介： 把 Camoufox 浏览器引擎封装成供 AI 助手调用的浏览器服务。Camoufox 基于 Firefox 修改浏览器指纹行为；camofox-browser 在其上提供页面操作、会话和内容读取接口。

  • 为什么火： 浏览器任务常常卡在页面状态和元素定位，项目用结构化页面快照与元素引用降低交互复杂度。它还主打降低自动化识别，但这属于项目的能力宣称，不能理解为对所有站点都有效的通行保证。

  • 技术亮点： 可访问性快照把页面表达为助手可操作的结构，元素使用 e1、e2 等引用标识；服务还提供用户会话隔离、文件上传和结构化提取。README 披露默认故障遥测，并提供关闭开关，处理敏感业务前应先检查该行为。

  • 适用场景： 适合对有权访问的网站开展自动化测试或获准的数据处理。降低识别概率不赋予访问权限，仍需遵守站点规则、速率限制与个人数据要求；不要把登录 Cookie 当作普通配置共享。

怎么选

如果主要问题是回复太长，先试轻量输出规则；如果是需求跑偏和无关修改，优先梳理项目规范，再考虑完整开发工作流。做内容可分别看 diagram-design 和 HyperFrames，处理办公资料看 MarkItDown。每次只引入与当前问题有关的能力，再用一组真实任务检查它是否减少返工。
