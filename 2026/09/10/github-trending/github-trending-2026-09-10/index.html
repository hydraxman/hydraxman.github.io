一个要求编程助手少说铺垫、先给动作的技能，拿到了 Today +4,624。9 月 10 日的 GitHub 日榜上，i-have-adhd 排在最前面；TeamAI 和 Superpowers 则分别处理团队规范共享、开发步骤管理。它们共同指向一种具体需求：让助手的回答容易执行，让任务有步骤可循。

1. ayghri/i-have-adhd

  • 项目简介： 把答案埋在解释后面，是编程助手常见的沟通问题。i-have-adhd 用一组可安装的技能规则调整回答：先说下一步做什么，多步骤编号，结尾只留下一个明确动作。它面向偏好低阅读负担的用户，不要求使用者具有 ADHD（注意缺陷多动障碍）诊断，也不是医疗工具。
  • 为什么火： Today 达到 +4,624，关注点却很朴素：让人更快找到文件、命令和下一步。相比继续增加助手功能，这种直接改善输出可读性的改动，试用门槛低、前后差别也容易感知；热度不能替代对个人工作习惯的实际适配。
  • 技术亮点： README 列出 10 条规则，包括动作前置、抑制岔题、说明当前状态，以及把列表控制在 5 项以内。这里的技术载体是可修改的 Skill，也就是提供给智能体的工作说明，不是另行训练的模型。
  • 适用场景： 适合经常在终端里被长回答打断的开发者。复杂排障仍需要保留错误上下文和安全条件，不能为了短而省掉关键限制。

2. Tencent/teamai-cli

  • 项目简介： 同一个团队使用 Claude Code、Codex、Cursor 等不同助手时，共享规范很容易散落成多份。TeamAI 把技能、规则、文档和工具连接配置放进团队 Git 仓库，再分发到成员使用的助手。
  • 为什么火： 它解决的是团队采用 AI 后的配置分裂：一个人修好的规则，其他人不必重新整理。今日 +563 的关注信号，值得与这种跨工具复用价值一起看；不能据此推断已有多少企业在生产环境采用。
  • 技术亮点： 执行层采用提交、审核合并、拉取的协作流程，并支持按角色和标签分发资源。MCP（模型上下文协议）配置用于连接外部工具；Team Context 与 Team Improvement 仍标为 beta，知识召回默认关闭，需要显式启用。
  • 适用场景： 适合维护多套编程助手配置的技术团队。各助手的能力矩阵并不相同，共享环境变量目录也不应放入密钥；先从非敏感规则和文档开始更稳妥。

3. obra/superpowers

  • 项目简介： Superpowers 给编程智能体配了一套开发方法：先澄清需求并确认设计，再拆分任务、实现和审查。它的价值在于让长任务有可追踪的步骤，而不是承诺一句话就能交付可靠软件。
  • 为什么火： 总 Stars 已超过 28 万，Today 为 +690，更适合解读为成熟项目继续获得关注。README 中的多工具安装入口降低了迁移成本，明确的测试和审查流程也让它容易成为团队统一开发习惯的起点。
  • 技术亮点： 测试驱动开发要求先写会失败的测试，再实现到通过，最后重构；子智能体执行后分两轮检查需求符合度和代码质量。隔离工作目录、计划文件与按严重程度处理审查问题，都服务于减少任务之间的干扰。
  • 适用场景： 适合多步骤功能开发和需要审查记录的团队。小修补未必需要整套流程；把步骤跑完也不等于测试覆盖充分，负责人仍需确认验收条件。

4. pascalorg/editor

  • 项目简介： Pascal Editor 在浏览器中创建和编辑 3D 建筑项目。它既有可复用的场景与查看器组件，也有本地编辑器和面向智能体的连接服务，适合把空间设计变成可操作的项目文件。
  • 为什么火： 建筑设计提供了比聊天更具体的交付对象：墙体、房间和家具位置都能在场景中检查。今日新增 171 个 Stars。对希望让智能体直接修改设计场景的开发者，编辑器与工具连接服务的组合更值得研究。
  • 技术亮点： React Three Fiber 将三维场景接入 React 界面，WebGPU 提供浏览器图形能力。MCP 连接让智能体调用编辑工具；README 还区分已发布运行时和包含新家具候选检查能力的预览版本，源码里的能力未必已经进入安装包。
  • 适用场景： 适合空间方案演示、参数化建筑编辑和嵌入式 3D 查看器开发。家具占地检查不能代替高度、开门范围或搬运路径检查；本地服务共享场景状态时，也要避免多个客户端同时修改。
  • 关键数据： 语言 TypeScript；Stars 22,835；Today +171；Forks 2,892；License MIT；最近推送 2026-09-09 20:03:05 UTC；Topics 3d / architecture / bim / cad / editor / floorplan / mcp / nextjs / parametric-design / react-three-fiber / threejs / typescript；Homepage https://editor.pascal.app。

5. earthtojake/text-to-cad

  • 项目简介： text-to-cad 把计算机辅助设计（CAD）、工程分析（CAE）和制造（CAM）相关工作拆成一组智能体技能。它围绕本地项目文件生成、查看、检查和交接模型，也覆盖机器人结构描述与部分制造准备任务。
  • 为什么火： 自然语言建模的吸引力，来自能交付工程文件而非只展示一张效果图。这个仓库把模型预览、标准零件查找、可打印性检查与切片放在同一技能库中；今日新增 97 个 Stars，适用价值取决于它能否覆盖读者所需的文件格式和检查步骤。
  • 技术亮点： CAD 技能以 STEP 工程交换文件为主要输出，并提供 STL、3MF、GLB 等导出选项。机器人技能描述关节与连杆，打印相关技能检查壁厚、悬垂和成型方向，再通过实际切片程序生成与打印机配置对应的 G-code 指令。
  • 适用场景： 适合机械原型、机器人模型与 3D 打印准备。自动建模不能免除尺寸、公差和受力校核；连接实物打印机前，应先检查模型、材料与设备参数。

6. cathrynlavery/diagram-design

  • 项目简介： Diagram Design 给智能体提供架构图、流程图、时序图等图解类型及设计约束，输出可直接在浏览器打开的 HTML 和 SVG。它强调信息层级与品牌一致性，而不是把所有概念都装进同样的圆角框。
  • 为什么火： Today 为 +2,286，是这份榜单里突出的增长项。对技术作者和产品团队来说，源文件能改、图形能复用，比一张无法编辑的图片更容易进入文档维护流程；这也是它值得关注的产品取向。
  • 技术亮点： 当前 README 写明 39 种图解类型，每种提供浅色、深色和完整编辑版三种静态变体。静态版本无需构建、JavaScript 或外部图片，行为语义与布局分开描述，动态解释为可选项。
  • 适用场景： 适合架构说明、技术博客和方案沟通。图画得清楚，不代表系统关系已经正确；组件边界、箭头方向和数字仍需要作者确认。

7. TauricResearch/TradingAgents

  • 项目简介： TradingAgents 把金融研究拆给不同智能体：分析基本面、新闻、情绪和技术指标，再让多空研究员讨论，由交易与风控角色形成决策。它是研究框架，不是收益保证。
  • 为什么火： 它让多智能体协作落到一个分工清晰的场景：不同观点如何汇合、风险如何被单独审查，都有可观察的步骤。总 Stars 超过 10 万、今日 +367 说明关注仍在延续，但不能推出策略盈利或资金实盘规模。
  • 技术亮点： 底层使用 LangGraph 组织任务状态和角色连接，支持多家语言模型提供方及本地模型。README 描述的流程先产生分析与交易建议，经投资组合管理角色批准后，才交给模拟交易所执行。
  • 适用场景： 适合研究角色协作、金融信息整合和模拟决策。模型可能误读数据，数据时间、交易成本与样本选择都会影响结论；使用前应单独验证数据质量与回测条件，不把输出直接当作投资建议。

8. liquidslr/system-design-notes

  • 项目简介： 这份笔记围绕 Alex Xu 的《System Design Interview》两卷展开，从容量估算、限流和一致性哈希，一直整理到消息队列、支付系统和交易所。README 明确说明内容仍在持续整理。
  • 为什么火： 在技能与智能体项目密集的榜单里，系统设计笔记以 Today +910 出现，提醒开发者基础学习资料仍有吸引力。它的优势是把常见面试题与延伸阅读放在同一入口，而不是提供新的软件运行能力。
  • 技术亮点： 目录按具体问题组织，并链接 Dynamo、Bigtable 等系统资料。比如限流回答如何约束请求频率，一致性哈希回答节点变化时如何减少数据重新分配；这些机制比背诵整张架构图更值得理解。
  • 适用场景： 适合后端工程师准备系统设计面试，或按题目补齐分布式系统知识。笔记不能替代原书和一手论文；仓库未声明许可证，复制、改编或再分发前应确认授权。

9. openai/plugins

  • 项目简介： openai/plugins 当前收录的是 Codex 插件示例与市场目录。README 展示 Figma、Notion、iOS、macOS 和 Web 开发等插件，方便开发者了解一个插件怎样把领域技能与外部工具连接打包。
  • 为什么火： Today 为 +505。对已经使用 Codex 的开发者，官方示例能降低插件组织方式的摸索成本；仓库名很宽泛，不能把它当作早期 ChatGPT 插件体系的延续。
  • 技术亮点： 每个插件要求有 .codex-plugin/plugin.json 清单，并可附带技能、智能体定义、命令、钩子和 MCP 连接配置。默认市场与 API 密钥登录用户的市场使用不同目录文件，插件如何被发现与插件具体做什么是两层配置。
  • 适用场景： 适合开发 Codex 扩展或学习领域工作流的工程师。仓库没有统一根许可证：例如 Superpowers 附带 MIT，Figma 材料适用 Figma Developer Terms（开发者条款）；不能把整仓一概按 MIT 复用。

10. freestylefly/awesome-gpt-image-2

  • 项目简介： 这个项目把生图案例、提示词模板和智能体技能放进同一个资料库。网站提供大图预览、复制提示词以及按风格或场景筛选，适合先寻找视觉方向，再修改成自己的任务说明。
  • 为什么火： 今日 +612 的关注，可以从它对复用的强调来理解：主体、光线、材质和布局被拆成可组合字段，创作者不必每次从一段散文式提示词开始。案例多并不意味着所有题材都能稳定复现。
  • 技术亮点： README 将方法称作 Prompt as Code，即把提示词当结构化资产维护。新增的 GPT Image 2.5 专题与既有 Image 2 工具独立运行，明确未增加实时 2.5 生成功能；展示页面、模型能力和可调用服务不能混为一谈。
  • 适用场景： 适合设计师、内容团队与维护提示词模板的开发者。代码的 MIT 许可不自动证明案例中所有人物、品牌与参考素材都可商用；复用时要另查具体素材和生成条件。
