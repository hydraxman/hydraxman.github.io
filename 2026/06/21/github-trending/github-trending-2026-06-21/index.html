今天这份 GitHub 热榜，最有意思的不是谁又拿了第一，而是开发者的注意力继续往“能直接拿来干活”的工具倾斜：一边是 AI Agent、上下文压缩、代码记忆这类基础设施越卷越深，另一边是视频制作、桌面应用、设计协作、CRM 这种更贴近真实业务流的产品也在快速吸星。

换句话说，大家已经不太满足于“模型看起来很强”了。真正能冲上榜单的，往往是那些能让团队今天就省一点 token、少切几个工具、少踩一点流程坑的项目。热度在变，评判标准也在变。

1. palmier-io/palmier-pro

  • 项目简介： 一个面向 macOS 的 AI 视频编辑器，想把剪辑、生成和工作流整合进同一个原生桌面界面里。
  • 为什么火： AI 视频现在最缺的不是“再来一个模型”，而是顺手的生产工具。Palmier Pro 瞄准的正是创作者每天都在用的桌面剪辑入口，这种离真实工作最近的位置，最容易吃到热度。
  • 技术亮点： 采用 Swift 做原生桌面栈，性能和系统整合能力先天更好；同时它不是把 AI 做成聊天浮层，而是直接嵌进视频编辑流程里。
  • 适用场景： 适合短视频团队、独立创作者、教育内容工作室，以及需要在 macOS 上做高频视频生产的人。
  • 关键数据： Stars 3,564；Today Stars 902；语言 Swift；Forks 289；License GPL-3.0；最近更新 2026-06-20；Topics ai-video、claude、macos、mcp、seedance2。

2. penpot/penpot

  • 项目简介： 开源设计协作平台，核心卖点是让设计和代码团队在同一套开放工具链里协作。
  • 为什么火： 每当设计工具领域出现定价、数据主权或协作焦虑，Penpot 这类 Figma 替代方案就会重新回到视野里。它这次上榜，说明不少团队又开始认真评估“开源设计工具能不能顶上去”。
  • 技术亮点： Clojure/ClojureScript 路线很少见，但也让它在产品架构和开放性上有明显辨识度；更重要的是，自托管能力对企业很有吸引力。
  • 适用场景： 适合重视数据主权的设计团队、需要自部署协作平台的企业，以及想摆脱 SaaS 锁定的组织。
  • 关键数据： Stars 51,550；Today Stars 420；语言 Clojure；Forks 3,306；License MPL-2.0；最近更新 2026-06-19；Topics clojure、clojurescript、design、prototyping、ui。

3. calesthio/OpenMontage

  • 项目简介： 一个开源的 agentic 视频生产系统，试图把 AI 编程助手升级成完整的视频制作工作室。
  • 为什么火： 今年最能传播的叙事之一，就是“Agent 不只会写代码，还能接管一条完整业务流水线”。OpenMontage 把这个故事讲得非常完整，所以天然容易被转发。
  • 技术亮点： 官方描述里直接给出 12 条 pipeline、52 个工具、500+ agent skills，这种规格意味着它不是小脚本拼接，而是在认真搭视频生产流水线。
  • 适用场景： 适合营销视频团队、知识内容工厂、教育内容制作，以及想探索自动化视频生成链路的开发者。
  • 关键数据： Stars 7,163；Today Stars 677；语言 Python；Forks 1,160；License AGPL-3.0；最近更新 2026-05-07；Topics agent、agentic-ai、ai、claude、copilot。

4. tursodatabase/turso

  • 项目简介： 一个兼容 SQLite 的 in-process SQL 数据库，主打更轻、更近、更适合现代应用部署。
  • 为什么火： 这波数据库热度，本质上不是大家想回到旧时代，而是大家越来越需要“像 SQLite 一样简单、又比 SQLite 更适合云边协同”的底座。Turso 正踩在这个节点上。
  • 技术亮点： 兼容 SQLite 生态是它最大的护城河，开发者几乎不用换脑子就能迁移；同时 Rust 路线也让它在性能和工程稳定性上更有想象空间。
  • 适用场景： 适合边缘应用、轻量 SaaS、AI Agent 本地状态存储，以及任何偏爱 SQLite 体验但又需要更现代部署能力的团队。
  • 关键数据： Stars 20,390；Today Stars 801；语言 Rust；Forks 1,043；License MIT；最近更新 2026-06-20；Topics database、embedded-database、sql、sqlite3、webassembly。

5. DeusData/codebase-memory-mcp

  • 项目简介： 一个高性能代码智能 MCP 服务，把代码库索引成持久化知识图谱，让模型能更快“记住”整个仓库。
  • 为什么火： 只要 AI 编程还在继续卷，代码记忆层就会越来越重要。这个项目抓住的正是大家最疼的点：上下文太贵、仓库太大、问答太慢。
  • 技术亮点： 支持 158 种语言、亚毫秒级查询、单静态二进制、零依赖，这套卖点非常狠；而且“99% 更少 token”这件事，在 Agent 场景里几乎就是成本按钮。
  • 适用场景： 适合代码问答系统、AI 编程助手、代码审查流水线，以及需要长期项目记忆层的工程团队。
  • 关键数据： Stars 9,479；Today Stars 1,271；语言 C；Forks 718；License MIT；最近更新 2026-06-20；Topics aider、ast、claude-code、code-analysis、code-intelligence。

6. google-research/timesfm

  • 项目简介： Google Research 推出的时间序列基础模型，目标是把 forecasting 这件事也做成可复用的“预训练底座”。
  • 为什么火： 过去基础模型大多盯着文本和多模态，如今时间序列也开始进入 foundation model 竞争区。只要 Google Research 一出手，讨论度就很难低。
  • 技术亮点： 它强调的不是单一预测任务，而是更通用的时间序列能力底座，这意味着模型可以被迁移到更多 forecasting 场景里。
  • 适用场景： 适合金融预测、供应链需求预测、监控趋势分析，以及研究人员搭建 time-series benchmark。
  • 关键数据： Stars 24,594；Today Stars 433；语言 Python；Forks 2,331；License Apache-2.0；最近更新 2026-06-20；Topics 暂无显性 topic 标签。

7. twentyhq/twenty

  • 项目简介： 一个面向 AI 时代的开源 CRM，被很多人视作 Salesforce 的开放替代方案。
  • 为什么火： 企业软件最近的高频问题是：如果 AI 真要进销售流程，CRM 应该长成什么样？Twenty 不是回答得最花哨的那个，但它踩中了这个刚需问题。
  • 技术亮点： TypeScript 栈让二次开发门槛更低，产品定位也明确——不是只做“能用的 CRM”，而是给团队一个可以继续接 AI 自动化的底盘。
  • 适用场景： 适合销售团队、客户成功团队、创业公司，以及需要自定义客户流程的企业 IT 团队。
  • 关键数据： Stars 50,888；Today Stars 140；语言 TypeScript；Forks 7,414；License NOASSERTION；最近更新 2026-06-21；Topics crm、crm-system、customer、good-first-issue、graphql。

8. Kong/insomnia

  • 项目简介： 一个跨平台 API 客户端，覆盖 REST、GraphQL、WebSockets、SSE 和 gRPC 等常见协议。
  • 为什么火： 接口形态越多，开发团队就越需要一个“别折腾、一个工具全看完”的调试入口。Insomnia 这种老牌工具重新冲榜，说明基础开发工具依然很能打。
  • 技术亮点： 最大优势不是单点新功能，而是覆盖面完整：多协议 + Cloud/Local/Git 多存储模式，足够支撑复杂 API 协作流程。
  • 适用场景： 适合后端工程师、测试团队、API 平台团队，以及经常管理复杂接口集合的开发组织。
  • 关键数据： Stars 39,366；Today Stars 329；语言 TypeScript；Forks 2,326；License Apache-2.0；最近更新 2026-06-18；Topics api、api-client、api-design、electron-app。

9. tw93/Pake

  • 项目简介： 一个把网页一键打包成桌面应用的工具，主打轻量和高性能。
  • 为什么火： “我就想把常用网页服务变成一个桌面 App，别让我上 Electron 那套重家伙”——这就是 Pake 最容易传播的原因。需求够具体，痛点也够真实。
  • 技术亮点： Rust 路线让它在包体积和资源占用上更有优势，一条命令就能完成封装，也非常适合在社交媒体上形成口碑传播。
  • 适用场景： 适合把内部工具、个人工作台、常用网页服务快速封装成桌面 App 的开发者和效率玩家。
  • 关键数据： Stars 55,007；Today Stars 2,546；语言 Rust；Forks 10,904；License GPL-3.0；最近更新 2026-06-18；Topics chatgpt、claude、desktop、gemini、hight-performance。

10. chopratejas/headroom

  • 项目简介： 一个面向 LLM 的上下文压缩层，可在工具输出、日志、文件和 RAG 数据进入模型前先做瘦身。
  • 为什么火： 这波热度很容易理解：Agent 跑得越长，token 账单越吓人。谁能把上下文压下去，谁就等于给团队多争来一部分预算。
  • 技术亮点： 它不是泛泛做摘要，而是瞄准工具输出、日志、文件和 RAG chunk 这些真实脏活；同时还提供 library、proxy、MCP server 多种接入方式，落地门槛不高。
  • 适用场景： 适合 Agent 平台、RAG 系统、LLM 应用后端，以及任何被上下文膨胀困住的团队。
  • 关键数据： Stars 42,122；Today Stars 3,795；语言 Python；Forks 2,905；License Apache-2.0；最近更新 2026-06-20；Topics agent、ai、anthropic、claude-code、compression。
