Claude Fable 5 开放只是表象：Anthropic 开始把模型能力按风险切开卖

Claude Fable 5 终于开放了。

这句话听起来像一次普通的大模型更新：更强、更贵、更适合长任务。

但这次真正值得看的，不是 Anthropic 又把 benchmark 往上推了多少，而是它第一次把一个“危险到不敢完全公开”的模型，拆成了两种产品：

  • Fable 5：所有人能用，但装了护栏；
  • Mythos 5：同一底层模型，但部分护栏被移除，只给受信任的安全/生物研究伙伴。

这不是一次单纯的模型发布，而是前沿模型产品形态的一次分叉。

以后最强模型可能不再是“买不买得起”的问题，而是：你是什么客户、做什么任务、愿不愿意接受数据留存、能不能被信任。

一、Fable 5 是公开版 Mythos，但不是完整 Mythos

Anthropic 官方说得很直白：Claude Fable 5 是一个 Mythos-class model made safe for general use。

换成人话：

Fable 5 是 Mythos 级能力的公开版本，但被加了安全护栏。

Mythos 5 和 Fable 5 用的是同一底层模型。差别不是“谁更聪明”，而是“哪些能力被允许释放”。

模型 开放范围 安全边界 定位
Opus 4.8 广泛开放 常规安全策略 复杂任务默认选择
Fable 5 公开开放 高风险领域加护栏/回退 公开版 Mythos 级模型
Mythos 5 受信任伙伴 部分护栏解除 网络安全、生物研究等高风险专业场景

这点很关键。

过去大模型发布通常是线性的：Haiku、Sonnet、Opus，便宜到贵，快到强。

Fable / Mythos 这一代不是简单线性升级，而是开始变成“同一能力，按风险切片”。

能力不再只是一个产品，而是一套访问控制系统。

二、它的“安全”不是拒绝，而是换模型

Fable 5 最有意思的机制，是高风险请求不会总是由 Fable 5 自己回答。

根据 Anthropic 官方说明，当请求触及高风险领域时，系统会先由安全分类器判断。如果触发护栏，请求会被路由到 Claude Opus 4.8。

主要高风险领域包括：

  • 网络安全攻击与漏洞利用；
  • 生物、化学相关危险能力；
  • 模型蒸馏；
  • 部分前沿模型研发辅助能力。

这比“抱歉我不能回答”聪明一点。

用户仍然会得到一个回答，只是回答者从 Fable 5 变成 Opus 4.8。Anthropic 说，平均来看，超过 95% 的 Fable 会话不会触发回退；也就是说，大多数日常任务仍然在 Fable 5 上完成。

但这里有一个容易被中文报道讲粗的细节：

Claude App 里的回退和 API 里的回退不是一回事。

官方文档写得很明确：多数 Claude 应用里，高风险请求会自动路由到 Opus 4.8；但 API 客户需要配置新的 Fallback API。如果开发者没有接好，体验未必就是“自动丝滑降级”。

这不是小问题。

因为 Fable 5 的真正用户，很可能不是普通聊天用户，而是企业、Agent 平台、代码迁移系统、自动化研究工具。对这些人来说，模型回退不是一句提示那么简单，它意味着：

  • 输出质量可能变化；
  • 成本计算可能变化；
  • 任务日志要标记哪一段由哪个模型完成；
  • 合规审计要能解释为什么某个请求被降级。

安全路由一旦进入生产系统，就不只是安全机制，而是工程接口。

三、为什么 Anthropic 这么谨慎？因为 Mythos 真的是双刃剑

Anthropic 不是突然变保守。

今年 4 月，Anthropic 启动 Project Glasswing，把 Mythos Preview 交给约 50 家网络安全和关键基础设施伙伴。5 月底，官方披露：这些伙伴已经找到了 超过 10,000 个 high 或 critical 级别漏洞。

随后项目扩展到 15 个以上国家、约 150 家新增机构。

这个数字很吓人，但真正吓人的不是“找到了一万个漏洞”。

真正的问题是：如果防守方能用它这么快找到漏洞，攻击方拿到同级能力后，也会用它这么快找到漏洞。

Anthropic 在 Glasswing 文章里说得很清楚：网络安全的瓶颈正在从“发现漏洞”转向“验证、披露、修补和部署”。

这句话比发布会上的模型分数重要得多。

因为它意味着前沿模型正在改变安全行业的节奏：过去专家稀缺，漏洞发现慢；现在发现可以被模型加速，真正跟不上的反而是人类组织流程。

Fable 5 的护栏，本质上是在给这种速度差打补丁。

四、能力很强，但强得最明显的地方不是聊天

Fable 5 的卖点不是“更会聊天”。

Anthropic 的定位很明确：它是给长时间、复杂、多阶段任务准备的。

官方列出的方向包括：

  • 大型代码迁移；
  • 多天级 autonomous coding；
  • 复杂知识工作；
  • 图表、表格、PDF、文件里的视觉理解；
  • 科研与分析任务；
  • 自己写测试、自己检查结果。

最抓眼球的案例来自 Stripe：Fable 5 在一个 5000 万行 Ruby 代码库里做全库迁移，一天完成，而原本估计需要一个团队手工干 两个多月。

这类案例不要当成“所有公司都能复制”的承诺。大厂案例往往有专门数据、专门工程环境、专门评估流程。

但它说明了一个方向：

Fable 5 不是为了把一句话回答得更漂亮，而是为了把一整段工作流吃下来。

这也是为什么它比 Opus 4.8 贵一倍。

官方价格：

模型 输入 / 百万 token 输出 / 百万 token
Opus 4.8 $5 $25
Fable 5 $10 $50
Mythos 5 $10 $50

Fable 5 还有 1M context window、128k max output，adaptive thinking always on，但没有 extended thinking。也就是说，Anthropic 把它包装成一个“高自治、高吞吐、长任务”的工作模型，而不是一个普通聊天升级包。

五、真正的代价：不只是贵，还有 30 天数据留存

Fable 5 这次最容易被忽略的变化，是数据政策。

使用 Fable 5 / Mythos 5，需要接受 30 天数据留存，用于安全监控。Anthropic 表示这些数据不会用于训练模型，主要用于识别新型越狱、复杂攻击、误报等安全问题。

但对企业来说，这句话不能轻轻放过。

尤其在 AWS 上，Fable 5 虽然进入 Amazon Bedrock 和 Claude Platform on AWS，但 AWS 官方博客明确写到：如果通过 Bedrock 使用 Fable 5，需要先通过 Data Retention API 选择 provider data sharing。

更直白一点：

一旦选择数据留存，你的数据会离开 AWS 自己的数据与安全边界，进入模型供应商要求的保留流程。

这对冲着“零数据留存”选择 Anthropic 的企业，是个真实变化。

它不一定不可接受，但必须重新评估：

  • 哪些任务能用 Fable 5？
  • 哪些数据不能进 Fable 5？
  • 留存期间是否可能被人工查看？
  • 内部合规文档怎么写？
  • 发生模型回退时日志如何记录？

最强模型的价格，开始包含一份隐私和合规账单。

六、中文稿里有一个判断是对的，但还可以再往前推一步

很多报道会把这事总结成：

Fable 5 是“带护栏的 Mythos”。

这个说法没错，但还不够。

更准确的判断应该是：

Anthropic 正在把前沿模型能力做成“风险分层产品”。

第一层是 Opus：强，但仍是常规公共模型。

第二层是 Fable：同一代最强能力可以公开，但高风险能力被分类器和回退机制切掉。

第三层是 Mythos：给经过审查的安全/生物研究伙伴，在部分高风险能力上解除限制。

这套结构以后很可能成为行业常态。

OpenAI、Google、Anthropic 迟早都会遇到同一个问题：当前沿模型在网络安全、生物研究、自动化研发上越来越强，完全公开会出事，完全不公开又浪费商业价值。

于是中间方案出现了：

  • 能力按风险分层；
  • 客户按信任分层；
  • 请求按分类器分层；
  • 数据按监控要求分层。

模型发布会从“谁最强”，变成“谁有资格用完整能力”。

写在最后

Claude Fable 5 的意义，不是 Anthropic 又发了一个更强 Claude。

真正的变化是：前沿模型公司开始承认，最强能力不能再像普通 SaaS 功能一样无差别开放。

它必须被切开、被路由、被审计、被留存、被分配给不同等级的用户。

这听起来不酷，甚至有点扫兴。

但这可能就是大模型走向基础设施之后的真实形态：

能力越强，产品越不像“一个模型”，越像一套治理系统。

Claude Fable 5 是公开版 Mythos，也是一次预演。

它预演的是：当 AI 足够强，模型公司会怎样把“危险能力”卖给全世界。
