当 AI 学会改写自己：一场没有发布会的暗战

Nathan

过去两年，”AI 会写代码”已经不稀奇。真正值得盯的是另一件事：当 Coding Agent 开始改写自己的代码、改写自己的工具、改写自己的工作流，谁能把这个循环跑稳、跑快、跑久。 这才是一线 AI 公司之间正在拉开的代际差距。

一、从”会写代码”到”会改自己”

2025 年的故事是：Cursor、Claude Code、Codex、Copilot 让人类工程师的产出翻倍。
2026 年正在发生的故事不一样——Agent 不再只是替你写业务代码，它开始动自己。

这不是科幻。Sakana AI 与 UBC 在 2025 年 5 月放出的 Darwin Gödel Machine（DGM） 给了一个干净的实证：一个 Coding Agent 反复修改自己的 Python 源码——换更好的代码编辑工具、加长上下文窗口管理、引入同行评审机制——然后用编码基准来验证每一次改动到底有没有变强。

结果是实打实的数字：

  • SWE-bench：20.0% → 50.0%
  • Polyglot：14.2% → 30.7%

数据来源：Darwin Gödel Machine 论文（arXiv:2505.22954），官方摘要原文。

注意它的关键设计：底层基座模型是冻结的（frozen foundation model）。也就是说，这 30 个百分点的提升，不是靠换更强的大模型堆出来的，而是 Agent 把”自己怎么用这个模型”这件事，一轮一轮优化出来的。

这件事的含义很重——模型能力之外，还存在一条独立的、可以自己往上爬的增长曲线。

二、自举飞轮：四个齿轮咬合在一起

把 DGM 这类系统抽象出来，自我进化其实是一个闭环。不妨把它画成一个飞轮：

四个齿轮缺一不可：

  1. 自主开发——Agent 写代码、改框架、产出新版本的自己。
  2. 自动测试——回归测试 + 边界测试，挡住幻觉漏洞和架构崩塌。
  3. 量化评测——用基准给每一轮打分，判断到底是真进步还是自我感觉良好。
  4. 数据回流——把退化信号、失败案例喂回去，启动下一轮。

跑通一圈，能力涨一点；涨上去的能力又让下一圈跑得更好。这就是”自举（bootstrap）”——自己把自己拎起来，理论上可以复利增长。

但飞轮听起来很美，真要转起来，魔鬼全在后面两个齿轮里。

三、为什么”测试”和”评测”才是命门

大模型有一个绕不开的天性：概率不确定性。同样的输入，今天对、明天错。

这意味着，一个纯靠”自己改自己”、没有任何管控的 Agent，跑着跑着大概率不是变强，而是悄悄变弱——功能回退、隐性 Bug 累积、某个边界场景的能力直接倒退，而它自己浑然不觉，还在 archive 里给自己打高分。

所以真正的自进化系统，必须靠两道闸：

  • 测试守住下限。 全覆盖、可规模化的自动测试，是 Agent 自我改造时的安全网。没有它，自进化就是高风险盲跑。
  • 评测拉高上限。 公开榜单（SWE-bench、HumanEval）人人能刷，刷不出差异化。真正拉开差距的，是企业自己的私有 Benchmark、复杂重构集、真实 Bug 库——它能捕捉公开榜单测不出的隐性退化，也是别人无法复刻的隐形护城河。

一句话：下限由测试守，上限由评测拉。上下限双重锁死，才有稳定的指数级飞轮。 否则就是一台转得越快、翻车越惨的机器。

这一点最近也有新的工程化证据。2026 年的 Agentic Harness Engineering（AHE） 这篇工作就把”可观测性驱动的 harness 自动进化”做成了管线：不去动模型，而是持续观测 Agent 在真实任务里的行为轨迹，自动定位 harness（工具层、提示层、调度层）的薄弱点并迭代它。

它的数据同样很干净：**10 轮迭代，把 Terminal-Bench 2 的 pass@1 从 69.7% 拉到 77.0%**，超过了人工精心设计的 Codex-CLI harness（71.9%）。而且——又是一个冻结的基座模型。

数据来源：Agentic Harness Engineering 论文（arXiv:2604.25850），官方全文。

它和 DGM 是同一个母题的两种打法：进化的对象不一定是模型权重，更多时候是”模型外面那一圈工程”——提示、工具、中间件、记忆、子 Agent。 而要让这种进化不跑偏，靠的还是观测、测试、评测构成的反馈闭环。

四、AI 公司真正的四层壁垒

把上面的逻辑往上抽一层，就能看清楚一线 AI 公司之间真正的竞争结构。它不是单一维度的”谁模型强”，而是层层咬合的四层壁垒：

层级 能力 角色
01 基座模型原生能力 准入门槛——有没有资格进场
02 可自迭代的 Coding Agent 增长引擎——能不能复利进化
03 软件测试自动化 安全下限——会不会越改越烂
04 评测体系 + 私有数据集 能力上限——能不能持续超越

这四层的关系很微妙：

  • 第一层是入场券。基座模型不够强，连游戏都进不了。但今天头部模型能力正在收敛，光靠它已经越来越难拉开身位。
  • 第二层是真正的引擎。谁能让自己的 Agent 自迭代跑起来，谁就拿到了一条独立于”等下一代大模型”的增长曲线。
  • 第三、四层是让引擎不爆缸的东西。它们最不性感、最像脏活累活，却恰恰是最难被抄走的——因为私有测试集和评测流水线是企业在自己的真实业务里一寸一寸长出来的。

模型可以买、可以追、可以蒸馏。但一套跑了两年、沉淀了无数真实失败案例的私有评测与测试体系，买不到。 这才是护城河真正深的地方。

五、写在最后：别只盯着模型跑分

行业的注意力，长期被”哪家模型又屠榜了”牵着走。但 DGM、AHE 这一批工作其实在提醒一件更要紧的事：

当模型能力趋同，竞争的主战场会从”模型本身”，转移到”围绕模型的那一圈自进化工程”。

谁能把自举飞轮跑稳——用测试守住下限，用私有评测拉高上限——谁就能在别人还在等下一个版本号的时候，自己先把自己迭代到下一个身位。

这件事没有发布会，没有跑分截图，也上不了头条。但它可能才是这一轮 AI 竞赛里，最被低估、也最决定胜负的暗线。
