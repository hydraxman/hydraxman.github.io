今天的 Trending 榜被一个关键词牢牢统治——**”让 Agent 跑得更远、更省、更稳”**。Top 3 全部围绕 Claude Code / Codex / Cursor 这类编码 Agent 的”周边基础设施”：headroom 用压缩把 60–95% 的上下文 token 还回去；hermes-agent 把”会进化、有记忆”的 Agent 做成了可在终端长期同行的伙伴；ECC 则把 Skills、Instincts、Memory 这些”调教 Claude Code”的方法论打成了一个工具集。半年前大家还在比谁的模型上下文更长，今天已经在比谁的 Agent 更会自我节制、更会自己装备自己。

另一条暗线是”把 LLM 嵌进真实工作流”：PaddleOCR 把任意 PDF/图像转结构化数据喂给模型，spec-kit 把”先写规范再写代码”的 SDD 流派做成了官方脚手架，open-notebook 给 NotebookLM 写了一份开源平替，NVIDIA Cosmos 直接把战场推到了物理 AI 的 World Model。Open-LLM-VTuber 提醒我们消费端的”陪伴向”AI 依然有强劲的草根活力，github/copilot-sdk 则把 Copilot Agent 的接入门槛降到了 Java/Kotlin/Swift 一行依赖。最后压轴的 jwasham/coding-interview-university 已经 34.9 万星——在 AI 写代码的时代，CS 基本功反而被更多人翻回去重读了一遍。

1. chopratejas/headroom — 把”喂给 LLM 的 token”先狠狠压一遍

  • 项目简介：headroom 是一个专门为 Agent 场景设计的”上下文压缩中间层”，可以把工具调用的输出、长日志、文件内容、RAG 检索块在送进 LLM 之前先压一遍，官方称同等答案下 token 用量减少 60–95%。
  • 为什么火：今天直接拿走 +3,139 stars，是榜首。Claude Code、Cursor、Codex 这类 Agent 用户最大的痛点就是”工具输出动辄几千行把上下文撑爆”，headroom 提供了库、Proxy、MCP server 三种接入方式，几乎是即插即用的省钱方案，社区一晚上炸开。
  • 技术亮点：同时给出 Python 库 + HTTP Proxy + MCP server 三种集成形态；针对 tool outputs、日志、文件、RAG chunks 做差异化压缩策略；topics 里 context-engineering / context-window / cursor / claude-code / token-optimization 把目标人群标得明明白白。
  • 适用场景：跑 Claude Code / Cursor / Codex 类编码 Agent 撑爆上下文、API 账单爆炸；RAG 系统检索块太长拖慢响应；任何长跑 Agent 需要”留点上下文 headroom”的场合。
  • 关键数据：语言 Python · Stars 12,165 · Today +3,139 · Forks 796 · License Apache-2.0 · 最近更新 2026-06-04 · Topics agent / ai / anthropic / claude-code / compression / context-engineering / context-window / cursor · Homepage https://headroom-docs.vercel.app/docs。

2. NousResearch/hermes-agent — 会和你一起成长的终端 Agent

  • 项目简介：Nous Research 推出的开源 AI Agent，主打”the agent that grows with you”——跨会话记忆、技能可沉淀、可装载 MCP 和插件，定位是”长期同行的终端 AI 同事”，不是一次性的问答机器人。
  • 为什么火：18 万星量级的项目今天还能加 1,951 stars，说明 Nous 的更新节奏 + Claude/ChatGPT/Codex/Cursor 全家桶集成持续吸引迁移用户；MIT 协议 + 活跃维护让企业内部也敢用。
  • 技术亮点：内置 memory / skills / cron / kanban / 多 Provider 路由；可同时接 Anthropic、OpenAI、Copilot、Codex、Cursor 等后端；技能 (skills) 体系本身就是个可二次开发的”Agent 装备库”；topics 横跨 ai-agents / anthropic / chatgpt / claude / claude-code / clawdbot。
  • 适用场景：想在终端常驻一个”懂你项目”的 AI 协作者；需要把日常 Ops/写作/研究/数据处理工作流统一到一个 Agent；想自建一套带技能与记忆的私有 Agent 平台。
  • 关键数据：语言 Python · Stars 180,751 · Today +1,951 · Forks 31,000 · License MIT · 最近更新 2026-06-04 · Topics ai / ai-agent / ai-agents / anthropic / chatgpt / claude / claude-code / clawdbot · Homepage https://hermes-agent.nousresearch.com。

3. affaan-m/ECC — Claude Code/Cursor 的”性能优化系统”

  • 项目简介：ECC 把自己定位为 Agent Harness Performance Optimization System——给 Claude Code、Codex、Opencode、Cursor 这类”主 Agent 框架”装上 Skills、Instincts、Memory、Security 和”研究优先”的开发方法论。
  • 为什么火：20 万星量级 + 今天 +1,736，反映出市场对”如何让 Claude Code 真的好用”的强烈需求；与 #1 headroom、#2 hermes-agent 一起构成了今天的”Agent 周边铁三角”。
  • 技术亮点：模块化 Skills 库 + Instincts（行为约束）+ 长期 Memory + 安全护栏；强调 research-first development——让 Agent 先查文档/测试再动手；JavaScript 实现，便于嵌入 VS Code/Cursor 这类前端友好环境。
  • 适用场景：Claude Code / Codex / Cursor 重度用户想”调教”出更可靠的 Agent；团队希望把 Agent 行为标准化、可审计；个人开发者想要一套现成的”AI 编码最佳实践”包。
  • 关键数据：语言 JavaScript · Stars 207,039 · Today +1,736 · Forks 31,787 · License MIT · 最近更新 2026-06-04 · Topics ai-agents / anthropic / claude / claude-code / developer-tools / llm / mcp / productivity · Homepage https://ecc.tools。

4. PaddlePaddle/PaddleOCR — PDF/图像 → 结构化数据的国产 OCR 旗舰

  • 项目简介：百度飞桨的 OCR 工具集，目标是”把任意 PDF 或图像文档转成可喂给 AI 的结构化数据”，覆盖识别、版面分析、表格抽取、KIE（关键信息抽取）、文档翻译等全链路任务，支持 100+ 语言。
  • 为什么火：今天 +105，常年盘踞 Trending；新版 PaddleOCR-VL 把视觉语言模型能力下放到本地小模型，且对中文文档极其友好，使其成为 RAG/文档智能场景的事实标准之一。
  • 技术亮点：轻量化模型 + GPU/CPU 双支持；文档解析 → 版面 → 表格 → KIE → 翻译流水线打通；新增 paddleocr-vl、pdf-extractor-rag topic，定位 AI4Science 与 LLM 前置组件。
  • 适用场景：合同/发票/科研 PDF 批量解析；做 RAG 想要更干净的文本块；多语言扫描件归档；任何需要”先把图变成 JSON 再喂模型”的工程化流水线。
  • 关键数据：语言 Python · Stars 79,761 · Today +105 · Forks 10,593 · License Apache-2.0 · 最近更新 2026-06-04 · Topics ai4science / chineseocr / document-parsing / document-translation / kie / ocr / paddleocr-vl / pdf-extractor-rag · Homepage https://www.paddleocr.com。

5. github/spec-kit — GitHub 官方的”先写 Spec 再写代码”工具箱

  • 项目简介：GitHub 官方推出的 Spec-Driven Development（SDD）脚手架，把”需求 → 规范 → 任务拆分 → AI 实现”流程模板化，配合 Copilot/AI 编码 Agent 使用。
  • 为什么火：10 万星量级 + 今天 +311，已经从尝鲜阶段进入”团队工程化”阶段；GitHub 亲自背书让大量企业愿意尝试 SDD 方法论；也是搭配 #2/#3 这类 Agent 框架的天然”上游”。
  • 技术亮点：规范模板 + PRD/工程模板 + 任务拆分流；Python CLI 易接入；与 GitHub Copilot 体系联动，可让 AI 严格按规范产出代码而不是即兴发挥。
  • 适用场景：团队想推行”AI 写代码，但人先写规范”的流程；做较复杂功能时先逼自己出 PRD/设计文档；面向多人协作的 AI 工程实践标准化。
  • 关键数据：语言 Python · Stars 108,479 · Today +311 · Forks 9,590 · License MIT · 最近更新 2026-06-04 · Topics ai / copilot / development / engineering / prd / spec / spec-driven · Homepage https://github.github.com/spec-kit/。

6. NVIDIA/cosmos — 给物理 AI 准备的世界模型开放平台

  • 项目简介：NVIDIA Cosmos 是面向”物理 AI”的世界模型、数据集和工具开放平台，目标用户是做机器人、自动驾驶、智能基础设施的开发者，让他们能基于预训练 World Model 做下游训练与仿真。
  • 为什么火：今天 +244，背靠 NVIDIA 一手生态；World Model + 物理 AI 是 2026 年最热的研究方向之一；以 Jupyter Notebook 为主交付，”开箱即看 demo”门槛极低。
  • 技术亮点：开源的视频/世界模型权重 + 配套数据集 + 微调与推理脚本；与 Isaac、Omniverse 等 NVIDIA 模拟器栈无缝衔接；Notebook 形态便于研究者迭代。
  • 适用场景：机器人/自动驾驶团队做仿真和合成数据；做视频生成/世界模拟相关研究；想理解 NVIDIA 在物理 AI 方向技术路线图的开发者。
  • 关键数据：语言 Jupyter Notebook · Stars 8,917 · Today +244 · Forks 575 · License NOASSERTION · 最近更新 2026-06-04 · Homepage https://www.nvidia.com/en-us/ai/cosmos/。

7. lfnovo/open-notebook — 开源版 NotebookLM

  • 项目简介：NotebookLM 的开源实现，提供”喂入资料 → AI 问答 / 摘要 / 思维导图 / 播客生成”等能力，并在原 NotebookLM 基础上扩展了更多模型与工作流灵活度。
  • 为什么火：今天 +482，连续多日上榜；用户对”我自己的资料 + 我自己的模型”组合需求强劲；NotebookLM 的播客生成功能尤其在中文圈被频繁讨论，开源平替自然受捧。
  • 技术亮点：TypeScript 全栈实现，前端体验现代；可对接多模型（OpenAI、Anthropic、Ollama 等本地/云端模型）；笔记本式工作流，集成笔记、问答、摘要、引文回溯。
  • 适用场景：学者/研究员管理论文与笔记；个人知识库 + AI 助理；想搭一个私有 NotebookLM 给团队内部用；做内容创作时把多份资料汇总成播客或大纲。
  • 关键数据：语言 TypeScript · Stars 24,841 · Today +482 · Forks 2,901 · License MIT · 最近更新 2026-06-04 · Topics assistant / learning / note-taking / notebook / notes-app / self-learning · Homepage https://www.open-notebook.ai。

8. Open-LLM-VTuber/Open-LLM-VTuber — 本地跑、能打断、有 Live2D 的语音 VTuber

  • 项目简介：跨平台、本地运行的 LLM 语音聊天伴侣，配合 Live2D 形象做出”会说话、会做表情”的虚拟主播/AI 老婆，支持免手语音、可中途打断、可对接任意 LLM。
  • 为什么火：今天 +583，C 端”AI 陪伴向”持续高热；Live2D + 本地推理 + 多模型可选满足了大量 ACG 圈用户的私有部署需求；也是少有的”消费向 AI”在 Trending 与企业项目同台竞争的代表。
  • 技术亮点：本地端到端语音管线（ASR → LLM → TTS）；语音中断（barge-in）实现自然对话；Live2D-web 渲染做嘴型与表情；支持任意 LLM 后端（云/本地）。
  • 适用场景：直播间 AI 助播 / 弹幕回应；个人 AI 桌宠或语音助理；学日语/英语口语对练；研究多模态人机交互的轻量参考实现。

9. jwasham/coding-interview-university — 自学成程序员的圣经路线图

  • 项目简介：一份”从零自学到能拿大厂 offer”的完整 CS 学习计划，覆盖数据结构、算法、系统设计、操作系统、网络、编译原理、面试题库等几乎全部 CS 基础与面试要点。
  • 为什么火：今天 +740，长青项目持续吸引新读者；AI 写代码越普及，面试 + 基本功反而越被重视；非英语母语国家程序员也大量 fork 用作个人学习地图。
  • 技术亮点：以 README 为入口的巨型 checklist，按主题分类、可勾选；引用各路高质量公开课、书籍、博客；CC-BY-SA-4.0 开源协议鼓励翻译与衍生。
  • 适用场景：自学转码或想系统补 CS 基础；准备 FAANG/大厂技术面试；导师给学生制定半年/一年学习路径；建立公司内训”工程师成长地图”。

10. github/copilot-sdk — Copilot Agent 的多平台官方 SDK

  • 项目简介：GitHub 官方发布的多平台 SDK，用于把 Copilot Agent 集成到任意 App 与服务中，覆盖 Java、Kotlin、Swift 等多端，定位是”给所有客户端开发者一条接 Copilot 的高速公路”。
  • 为什么火：今天 +107，作为官方仓库一上线即有保底关注；移动端/桌面端开发者一直缺乏一套官方 Copilot Agent 接入方案，这次 GitHub 自己出手补齐；也意味着 Copilot Agent 不再只是 IDE 内的功能。
  • 技术亮点：以 Java 为主仓库语言，强调跨平台一致 API；面向 Agent 调用范式而不只是补全；官方维护意味着随后会与 spec-kit、copilot extensions 形成生态闭环。
  • 适用场景：iOS/Android/桌面 App 想把”AI 助手”做成一等公民；企业内部 IM/工单系统嵌入 Copilot Agent；做 IDE 之外的”AI Pair Programmer”产品。
