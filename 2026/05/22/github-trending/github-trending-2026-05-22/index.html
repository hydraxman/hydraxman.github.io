今天的 GitHub Trending Daily 几乎是一份 “Claude Code 生态体检报告”：榜单 10 个项目，6 个直接服务 Claude Code/Coding Agent（官方插件目录、代码知识图谱、Karpathy 行为规范、.NET 官方 Skills、Superpowers 方法论、NotebookLM Skill），1 个是 Chrome 官方放出来的 DevTools MCP，1 个是“让所有软件 Agent-Native”的 CLI-Hub。

信号已经很清楚：模型层短期没有新爆点，开发者继续在补 Agent 落地的工程层——上下文怎么压（codegraph）、技能怎么治理（claude-plugins-official、dotnet/skills）、方法论怎么写进 prompt（karpathy-skills、superpowers）、浏览器/工具怎么接入（chrome-devtools-mcp、CLI-Anything）。

剩下两个非 Agent 项目也踩在产品化痛点上：OpenWA 让 WhatsApp 不再被官方 API 卡脖子，ai-engineering-from-scratch 帮工程师把模型变成可交付的产品。

1. anthropics/claude-plugins-official

  • 项目简介：Anthropic 官方维护的 Claude Code 插件目录 (Marketplace)，集中收录通过审核的高质量插件——agents、skills、commands、hooks、output styles、MCP servers 一站式索引。
  • 为什么火：过去半年第三方 Claude Code 插件生态野蛮生长，但鱼龙混杂。Anthropic 终于自己出来背书：今天上榜意味着官方“插件应用商店”心智正式确立，也是开发者下注 Claude 生态的明确信号。
  • 技术亮点：仓库本身是 Python 脚本 + 标准化 manifest——每个插件靠 marketplace.json/plugin.json 声明能力，Claude Code 直接通过 /plugin marketplace add anthropics/claude-plugins-official 一键挂载。结构很轻，价值在“治理”而非代码。
  • 适用场景：想给 Claude Code 安装可信插件、研究官方推荐插件目录结构、或自己写插件想被官方收录的开发者。
  • 关键数据：语言 Python；Stars 22,093；Today Stars +891；Forks 2,627；License —；最近更新 2026-05-21；Topics：claude-code, mcp, skills；Homepage：https://code.claude.com/docs/en/plugins

2. colbymchenry/codegraph

  • 项目简介：面向 Claude Code / Codex / Cursor / OpenCode 的“预索引代码知识图谱”，强调更少 token、更少工具调用、100% 本地。
  • 为什么火：今天 +4,200 stars，单日榜首级爆发。Coding Agent 上下文成本居高不下，“先建图，再让 Agent 按需取节点”几乎是公认收敛方向；这个项目踩在所有 AI IDE 的痛点正中央。
  • 技术亮点：TypeScript 实现的本地代码图谱：把符号、调用、依赖关系预索引成可检索的图，Agent 工具不再做盲目 grep 或全仓 read_file，而是按节点拉取最小相关上下文。属于 RAG-on-codebase 的图结构进化版。
  • 适用场景：大型代码库接入 AI 编辑器、想压低 token 账单的工程团队、本地隐私优先的代码 Agent 部署。
  • 关键数据：语言 TypeScript；Stars 13,027；Today Stars +4,222；Forks 744；License MIT；最近更新 2026-05-21；Topics：暂无公开 topics；Homepage：—

3. multica-ai/andrej-karpathy-skills

  • 项目简介：一份用来改造 Claude Code 行为的 CLAUDE.md——内容提炼自 Andrej Karpathy 关于 LLM 写代码常见坑的公开发言。
  • 为什么火：总 Stars 已经 14 万+，长期占榜单。Karpathy 的“LLM 编码陷阱”系列在 X 上传播极广，把它直接做成可贴的 CLAUDE.md 让每个 Claude Code 用户秒级享受“Karpathy 调教过的 Agent”，几乎零门槛。
  • 技术亮点：单文件项目，价值在“经验密度”：明确告诉 Agent 不要瞎重构、要先读代码、要做小步验证、要承认不知道、不要 silent fail。本质是把人类高手的元习惯写成 prompt。
  • 适用场景：所有用 Claude Code/Codex/Cursor 的工程师；可以拷过来当个人或团队的基线 system prompt，再按项目叠加。
  • 关键数据：语言 —；Stars 142,912；Today Stars +2,590；Forks 14,655；License —；最近更新 2026-04-20；Topics：暂无公开 topics；Homepage：—

4. dotnet/skills

  • 项目简介：.NET 官方仓库出品的 Claude Code Skills 包，专门帮 AI 编码助手写 .NET / C# 代码。
  • 为什么火：微软 .NET 官方亲自下场做 Claude Code Skills，是大厂为自家技术栈“在 AI Agent 里占座”的标志事件。今天还只有 2,145 stars，但 +179 是健康初速度，更重要的信号是“官方维护的语言级 Skill 包”会成为标配。
  • 技术亮点：按 Anthropic Skills 规范组织：每个 skill 一个目录、一份 SKILL.md、配套 references / scripts，覆盖 .NET CLI、项目模板、调试、单测等高频任务。
  • 适用场景：用 Claude Code 写 .NET/C# 项目、ASP.NET 后端、Blazor、MAUI 跨平台开发的团队。
  • 关键数据：语言 **C#**；Stars 2,145；Today Stars +179；Forks 175；License MIT；最近更新 2026-05-21；Topics：agent-skills；Homepage：—

5. obra/superpowers

  • 项目简介：一套被广泛采用的 Agentic Skills 框架与软件开发方法论，强调“先研究→先写计划→先写测试→再写代码”的纪律性流程。
  • 为什么火：总 Stars 20 万+ 长期屠榜。Superpowers 把“AI 协作开发应该怎么干”沉淀成可加载的 skill 集合，从 TDD、systematic-debugging、writing-plans 到 requesting-code-review 全套打包，正在成为 Hermes / Claude Code 等 Agent 框架默认引用的“通用工程方法论”。
  • 技术亮点：Shell + Markdown，结构极简，价值全在“流程定义”：每个 skill 有 trigger 条件、numbered steps、pitfalls、verification——把抽象的工程纪律编成机器可读 prompt，让 Agent 真正按章办事。
  • 适用场景：所有想让 Coding Agent 别一上来就乱改代码的团队；也是写自己 Agent skill 体系时最好的参照样板。
  • 关键数据：语言 Shell；Stars 201,384；Today Stars +1,572；Forks 17,938；License MIT；最近更新 2026-05-14；Topics：暂无公开 topics；Homepage：—

6. HKUDS/CLI-Anything

  • 项目简介：“CLI-Anything: Making ALL Software Agent-Native”——把任意软件包装成 Agent 可调用的 CLI 命令，并维护一个 CLI-Hub 索引站。
  • 为什么火：今天 +644。Agent 时代的接入瓶颈已经从“模型够不够强”变成“软件能不能被 Agent 调用”，把图形软件、SaaS、内部系统统一抽象成 CLI 是最低摩擦的桥；港大数据智能实验室 (HKUDS) 的学术背书也加分。
  • 技术亮点：Python 框架 + 公共 hub (clianything.cc)；约定一致的命令签名和输出格式，让 LLM/Agent 不用为每个工具写定制 wrapper。本质是 MCP 之外的另一条“工具协议”路线。
  • 适用场景：想让自家产品被 Agent 调用却不想立刻上 MCP 的厂商、内部工具想统一暴露给团队 Agent 的工程平台、研究 Agent 工具协议的研究者。
  • 关键数据：语言 Python；Stars 39,036；Today Stars +644；Forks 3,708；License Apache-2.0；最近更新 2026-05-20；Topics：暂无公开 topics；Homepage：https://clianything.cc/

7. rmyndharis/OpenWA

  • 项目简介：免费、开源、可自托管的 WhatsApp API Gateway——把 WhatsApp 接入自家系统的开放替代品。
  • 为什么火：今天 +704 stars。WhatsApp 官方 Business API 收费昂贵且审批繁琐，海外 SMB、AI 客服、营销自动化场景对“自部署可控”的开源网关需求长期被压抑；本轮节奏明显更猛，与 AI 客服/AI Agent 接入 IM 的浪潮叠加有关。
  • 技术亮点：TypeScript + 桥接 WhatsApp Web 协议；提供 REST/Webhook 接口，可作为消息总线接到 n8n、Dify、自家后端。开源 + MIT 让二次集成完全自由。
  • 适用场景：AI 客服/CRM/营销系统接入 WhatsApp、海外社群机器人、跨境电商售后自动化。
  • 关键数据：语言 TypeScript；Stars 5,340；Today Stars +704；Forks 1,068；License MIT；最近更新 2026-05-20；Topics：api, gateway, whatsapp；Homepage：https://www.open-wa.org

8. ChromeDevTools/chrome-devtools-mcp

  • 项目简介：Chrome 官方推出的 DevTools MCP Server——让 Coding Agent 能像开发者一样直接驱动 Chrome DevTools 协议 (CDP) 做调试、网络抓包、性能分析。
  • 为什么火：今天上榜不是因为单日爆量 (+132)，而是因为它来自 Chrome DevTools 官方账号，是浏览器厂商正式拥抱 MCP 协议的里程碑——意味着未来 Agent 直接打开 Chrome 调 console、抓 network、看 perf timeline 会变成标准能力。
  • 技术亮点：TypeScript 实现的 MCP server，把 CDP 的能力暴露成 MCP tools；Agent 可以让浏览器导航、截图、抓取 console 日志、读取网络请求、回放性能记录——这是“浏览器版的代码可观测性”。
  • 适用场景：前端 Bug 自动定位、Web 应用自动化测试、性能回归分析、Agent 驱动的网页 QA。
  • 关键数据：语言 TypeScript；Stars 40,416；Today Stars +132；Forks 2,567；License Apache-2.0；最近更新 2026-05-21；Topics：browser, chrome, chrome-devtools, debugging, devtools, mcp, mcp-server, puppeteer；Homepage：https://npmjs.org/package/chrome-devtools-mcp

9. rohitg00/ai-engineering-from-scratch

  • 项目简介：“从零开始的 AI 工程”教学项目——口号是 “Learn it. Build it. Ship it for others.”，把端到端 AI 应用构建过程拆成可跟做的练习。
  • 为什么火：今天 +1,318 stars。模型层卷不动了，工程层的“怎么把 LLM 真的做成产品”反而成了大量开发者的真实痛点；这类系统性、可跑通的工程教材最近几个月持续吃流量。
  • 技术亮点：Python 为主，覆盖 RAG、Agent、评测、部署、监控等模块；强调“先跑通最小可用版本，再迭代”，比纯理论教材更贴近真实交付。
  • 适用场景：想从 prompt 工程跨到 AI 应用工程的开发者、内部培训、训练营/课程的开源底本。
  • 关键数据：语言 Python；Stars 10,609；Today Stars +1,318；Forks 2,094；License MIT；最近更新 2026-05-21；Topics：agents, ai, ai-agents, ai-engineering, computer-vision, course, deep-learning, from-scratch, generative-ai, llm, machine-learning, mcp, nlp, python, reinforcement-learning, rust, swarm-intelligence, transformers, tutorial, typescript；Homepage：https://aiengineeringfromscratch.com

10. teng-lin/notebooklm-py

  • 项目简介：Google NotebookLM 的非官方 Python API 和 Agentic Skill，提供对 NotebookLM 全部主要能力的程序化访问，包括笔记本管理、内容上传等。
  • 为什么火：NotebookLM 在研究/学习场景里被认为是体验最好的 AI 产品之一，但官方 API 一直缺位；今天 +182，一份“非官方但可用”的 Python SDK 出现，等于把 NotebookLM 接入自家研究 Pipeline 的最后一公里打通。
  • 技术亮点：Python + Agentic Skill 双形态：既能当普通 SDK 调用，也能直接被 Claude Code 这类 Agent 加载为 skill；具体实现走的是逆向的 Google 内部接口，注意稳定性风险。
  • 适用场景：科研、学习、知识库自动化场景；想把 NotebookLM 的 podcast、问答能力嵌入自家工作流的人；做 RAG 评测时拿 NotebookLM 当 baseline 对比。
  • 关键数据：语言 Python；Stars 14,319；Today Stars +182；Forks 1,988；License MIT；最近更新 2026-05-21；Topics：agentic-skill, api, claude, claude-skills, google-notebooklm, notebooklm, notebooklm-api, notebooklm-skill, openclaw-skills, podcast-generator, python, python-api, sdk, skills；Homepage：https://github.com/teng-lin/notebooklm-py

一句话总结

今天的榜单不是一波新模型，而是 AI Coding Agent 的生态填坑日：官方插件治理、上下文图谱、行为规范、语言级 Skill、方法论、浏览器协议——所有补丁都打在去年 Coding Agent 暴露的真痛点上。把这十个项目放在同一张表里看，比单看任何一份模型 release notes 都更能说明：2026 年的开发者生产力争夺，主战场已经从“模型谁更强”切到了“谁的 Agent 工程层更厚”。
