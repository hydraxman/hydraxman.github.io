今天的 GitHub Trending 几乎成了一张 AI 工作流地图。榜首把图像提示词做成可复用资产，求职项目把岗位筛选、简历和面试串成一条流水线，Claude 插件市场、Agent 工作台、交易研究和个人知识库也都挤进前十。开发者关注的重点很具体：工具能否接住一整段任务，并留下可复查的结果。

榜单里也有一条清晰的反向信号。Omarchy 这套强调完整桌面体验的 Linux 发行版单日增加 1,080 Stars，说明本地控制、统一工具链和“开箱即用”的开发环境仍有强需求。与此同时，TradingAgents 与 awesome-llm-apps 已积累十万级 Stars，今天的增量却分别只有 191 和 161；进入日榜不等于突然爆红，更像成熟项目重新获得关注。

1. freestylefly/awesome-gpt-image-2

  • 项目简介： 这是一套面向 GPT Image 2 的 Prompt-as-Code 资产库。项目把 530 多个案例、20 多套工业模板和 Agent Skill 组织成可检索、可复制、可组合的结构，目标是让图像生成从零散灵感变成可复用流程。
  • 为什么火： 单日增加 1,698 Stars，是今天增量最高的项目。图像模型能力提升后，团队更缺的是稳定风格、批量产出和可维护模板；这个仓库直接解决了生产端最耗时间的整理工作。
  • 技术亮点： 提示词被拆成主体、光线、材质、构图和视觉细节等原子字段，既方便人工修改，也适合 Agent、脚本和自动化系统拼装。在线画廊还能按风格和场景浏览案例，再回到源文件复用结构。
  • 适用场景： 适合运营设计、文章配图、电商素材、社交海报和需要保持系列视觉一致性的内容团队。模型版本、参考图和生成参数仍会改变结果，模板能提高可控性，不能保证每次复刻完全一致。
  • 关键数据： JavaScript｜Stars 17,453｜Today +1,698｜Forks 1,806｜License MIT｜最近更新 2026-08-25｜Topics：AI 图像生成、Agents、Image Prompts。

2. anthropics/claude-plugins-community

  • 项目简介： Anthropic 用这个仓库镜像 Claude Code 与 Claude Cowork 的社区插件目录。开发者可以把目录加入 Claude Code，再按插件名安装；Claude Cowork 用户则从产品内插件页获取。
  • 为什么火： Claude 的扩展能力正从零散仓库走向统一分发。目录上线后，插件发现、安装和更新路径更清楚，单日获得 350 Stars；对开发者来说，这比手工复制一组命令或提示词更接近真正的软件生态。
  • 技术亮点： 仓库中的 marketplace.json 每晚从 Anthropic 的内部审核流程同步。README 明确写明，收录插件经过自动安全扫描并获准分发，官方插件、社区插件和岗位型知识工作插件也被拆成不同目录。
  • 适用场景： 适合为 Claude Code 增加专用开发能力，或给 Claude Cowork 接入特定知识工作流程。它是只读镜像，不能直接通过 Pull Request 投稿；自动扫描也不等于插件在所有环境里都安全，安装前仍应检查权限与代码。
  • 关键数据： Python｜Stars 1,677｜Today +350｜Forks 175｜License Apache-2.0｜最近更新 2026-08-24｜仓库定位：社区插件市场只读镜像。

3. MadsLorentzen/ai-job-search

  • 项目简介： 这是一个运行在本机的 AI 求职框架。它基于 Claude Code，把个人画像、职位抓取、匹配度评估、简历定制、求职信、审稿和面试准备连接成连续流程，生成的职业资料仍由用户自己保存。
  • 为什么火： 作者公开了自己的使用结果：69 份定制申请带来 20 次首轮面试和一份已签合同。这个具体案例让项目从“AI 帮你写简历”的泛泛承诺，变成一条可检查、可 Fork 的个人工作流，今天增加 1,266 Stars。
  • 技术亮点： /setup、/scrape 和 /apply 等命令把求职阶段拆成明确任务，申请环节采用起草者与审稿者协作，并支持 LaTeX 输出和 ATS 可解析性检查。核心评估与写作流程不限定语言和国家。
  • 适用场景： 适合愿意维护个人资料、逐份审核输出的技术求职者。现成职位门户 Skill 主要面向丹麦市场，迁移到其他国家要替换数据源；Claude Code、Python、Bun 和 LaTeX 也提高了上手门槛。
  • 关键数据： Python｜Stars 35,133｜Today +1,266｜Forks 12,105｜License MIT｜最近更新 2026-08-25｜Topics：AI Agents、Career、CV、Cover Letter。

4. apache/maka

  • 项目简介： Apache Maka（孵化中）是一套本地优先的 Agent 工作台。模型消息、工具调用、工具结果、权限决定和任务终止事件都会写入追加式日志，桌面端、终端和评测系统再从同一份记录构建各自视图。
  • 为什么火： 很多 Agent 产品能执行任务，却难以解释失败发生在哪里。Maka 把执行历史、崩溃恢复、权限审批和评测放进同一运行时，直接回应了开发者对可审计性与本地数据控制的需求，今天增加 538 Stars。
  • 技术亮点： Runtime Host 统一承接桌面、CLI 和评测任务；旧工具输出可以不再进入后续上下文，但原始证据仍保留。内置 Read、Write、Edit、Bash、Glob、Grep，并为越过沙箱边界的动作设置审批。
  • 适用场景： 适合调试长任务 Agent、比较模型和保存可恢复执行记录的开发者。项目仍在 Apache Incubator，尚无正式 Apache Release；当前 macOS Apple Silicon 桌面版属于早期公开版本，数据格式和命令可能变化。
  • 关键数据： TypeScript｜Stars 3,268｜Today +538｜Forks 325｜License Apache-2.0｜最近更新 2026-08-25｜Topics：Agent Runtime、CLI、Desktop、Local-first。

5. TauricResearch/TradingAgents

  • 项目简介： TradingAgents 用多组 LLM Agent 模拟交易机构的分工：基本面、情绪、新闻和技术分析先形成观点，多空研究员展开辩论，交易员与风险管理角色再汇总决策。
  • 为什么火： 项目已积累 100,111 Stars，成熟度和示例规模让它经常重新进入视野。7 月发布的 v0.3.1 修复前视偏差过滤、图路由崩溃恢复、检查点续跑和重试预算等问题，今天新增 191 Stars，更像稳定迭代带来的持续关注。
  • 技术亮点： 多角色图把数据获取、研究辩论、交易与风控拆开，支持检查点和持久决策日志，也覆盖多家模型与数据提供方。相比单次提示词给出买卖结论，这种结构更容易追踪每一步依据。
  • 适用场景： 适合多 Agent 编排、金融研究流程和回测方法研究。仓库明确声明它只用于研究，表现会受模型、温度、交易周期和数据质量影响，不能当作投资建议或收益保证。
  • 关键数据： Python｜Stars 100,111｜Today +191｜Forks 19,343｜License Apache-2.0｜最近更新 2026-07-18｜Topics：Finance、LLM、Multi-agent、Trading。

6. AgriciDaniel/claude-obsidian

  • 项目简介： claude-obsidian 把 Claude Code 与 Obsidian 组合成一套本地知识系统。来源材料先被保留，再生成带引用的 Markdown 页面、索引、知识地图和 Canvas，用户可以脱离 Agent 直接打开和编辑全部文件。
  • 为什么火： “第二大脑”类产品常把原始来源压成不可见摘要，这个项目反而强调来源、主张、矛盾、置信度和复核状态。它把知识整理的可信度问题放在功能中心，单日增加 810 Stars。
  • 技术亮点： 系统使用内容寻址副本、来源台账和主张台账保存证据；并行 Agent 只返回草稿，由单一编排者以可恢复事务写入知识库，避免多个 Worker 同时修改同一组文件。
  • 适用场景： 适合研究资料、个人知识管理和需要长期积累引用链的 Obsidian 用户。它不负责云同步、自动录音转写或事实担保，也不能替代备份与版本控制；首次初始化和既有 Vault 接管需要认真审阅变更计划。
  • 关键数据： Python｜Stars 12,588｜Today +810｜Forks 1,378｜License MIT｜最近更新 2026-08-01｜Topics：Agent Skills、AI Note-taking、PKM、Claude Memory。

7. rohitg00/ai-engineering-from-scratch

  • 项目简介： 这套开源课程覆盖 511 节课、20 个阶段和约 329 小时内容，横跨 Python、TypeScript、Rust 与 Julia。每一课都要求产出可复用成果，例如 Prompt、Skill、Agent 或 MCP Server。
  • 为什么火： AI 工程学习正在从“看懂概念”转向“能运行、能解释、能修改”。仓库要求学习者保存命令、工作目录、退出码、关键输出和修改产物，正好补上很多教程缺失的验收环节，今天增加 572 Stars。
  • 技术亮点： 课程把数学基础、模型、RAG、Agent、MCP 和工程交付拆成渐进路径，并提供定位测验与按目标选择的学习路线。相同课程既能在网页阅读，也能通过 Agent Skill 进入编码工具。
  • 适用场景： 适合希望系统补齐 AI 工程能力、并愿意亲手运行代码的开发者。511 节课意味着很高的时间投入；如果只想快速调用一个模型接口，完整路线会显得过重，最好先按目标选择阶段。
  • 关键数据： Python｜Stars 48,859｜Today +572｜Forks 8,555｜License MIT｜最近更新 2026-08-23｜Topics：AI Engineering、Agents、Course、Computer Vision。

8. tinyhumansai/openhuman

  • 项目简介： OpenHuman 是一套 Rust 构建的个人 AI 系统，把本地长期记忆、Agent 工作流编排和深度研究放在同一个桌面产品里。记忆会压缩进本机 SQLite 中的 Markdown 树，并可镜像到 Obsidian。
  • 为什么火： 它试图解决个人 Agent 最难连起来的三件事：持续记忆、可恢复任务和跨工具集成。用户既可以使用托管模型，也能接自己的 Provider Key 或本地 Ollama；这种“默认可用、同时保留迁移路径”的设计带来 541 个单日新增 Stars。
  • 技术亮点： 工作流使用可检查、带触发器和审批门的持久图；Agent 运行支持检查点、重放和逐次调用成本记录。快速分流 Agent 与深度推理核心分工，工具输出还会先压缩再进入模型上下文。
  • 适用场景： 适合想在一个客户端里统一个人记忆、研究和自动化的重度 AI 用户。README 明确标注 Early Beta，粗糙边角和接口变化仍应预期；部分搜索与托管能力依赖订阅，涉及加密支付和大量外部集成时也要单独评估权限与风险。
  • 关键数据： Rust｜Stars 37,697｜Today +541｜Forks 3,728｜License GPL-3.0｜最近更新 2026-08-25｜Homepage：tinyhumans.ai/openhuman。

9. basecamp/omarchy

  • 项目简介： Omarchy 是 DHH 主导的现代 Linux 发行版，目标是把桌面、终端、编辑器、浏览器、快捷键、开发工具和系统维护整理成一套强主张体验。仓库同时维护一份覆盖安装到安全的完整手册。
  • 为什么火： 在八个 AI 相关项目占据前十的日子里，Omarchy 仍拿到 1,080 个单日新增 Stars。开发者显然不只在找新的 Agent，也在找一套能减少环境拼装、把常用工具统一起来的本地工作台。
  • 技术亮点： 项目用 Shell 把系统配置与日常操作固化，手册覆盖主题、热键、剪贴板、语音输入、Neovim、AI、开发工具、网络、安全、系统快照和无人值守安装等 50 个主题。
  • 适用场景： 适合认同其桌面审美与快捷键体系、希望快速获得完整开发环境的 Linux 用户。“Opinionated”意味着默认选择很多，已有成熟 dotfiles、特殊硬件配置或企业管控要求的用户，迁移成本会更高。
  • 关键数据： Shell｜Stars 31,092｜Today +1,080｜Forks 3,164｜License MIT｜最近更新 2026-08-25｜Homepage：omarchy.org。

10. Shubhamsaboo/awesome-llm-apps

  • 项目简介： awesome-llm-apps 汇集 100 多个开源 Agent、Agent Skill 与 RAG 应用，覆盖旅行规划、数据分析、研究、内容生成、多模型协作和开发辅助等场景，并支持多家闭源与开源模型。
  • 为什么火： 它提供的不是抽象框架，而是一批可以直接克隆、换 Key、改业务逻辑的应用起点。随着开发者从模型演示转向完整应用，这类大规模样板库持续具有入口价值；项目累计 134,143 Stars，今天新增 161。
  • 技术亮点： 模板按 Agent Skill、入门 Agent 和高级多 Agent 应用分层。Skill 目录强调真实代码，并设置安全与评测 CI；同一仓库还能比较不同模型、工具和编排方式在相似任务中的实现差异。
  • 适用场景： 适合原型验证、教学和寻找 Agent 应用结构。项目跨度很大，不能把所有样例视为同一成熟度；部署前需要逐项检查依赖、密钥权限、数据来源、模型成本和特定模板的安全边界。
  • 关键数据： Python｜Stars 134,143｜Today +161｜Forks 19,735｜License Apache-2.0｜最近更新 2026-08-22｜Topics：Agents、LLMs、RAG、Python。
