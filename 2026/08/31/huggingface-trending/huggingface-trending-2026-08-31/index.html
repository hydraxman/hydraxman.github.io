今天的 Hugging Face Models 榜单几乎被两条线占满：Qwen 与 GLM 的新一代权重冲到前列，Unsloth 随即把其中三款转成 GGUF 部署包。榜首 Qwen3.8-Flash-Next 的 Trend Score 达到 4,199，领先第二名两倍以上；这个分数只表示平台趋势排序，不是性能、安全或质量评分。

另一处反差来自模型规模。榜单既有 27B 稠密模型，也有 770B 总参数的 MoE 预览版，还夹着一款联合音视频生成模型和一款主动移除安全拒答方向的衍生模型。选型时要同时看架构、格式、许可和风险，不能只看名次与累计下载量。

1. Qwen/Qwen3.8-Flash-Next

  • 模型简介： Qwen3.8-Flash-Next 是面向 Qwen4 的实验性架构预览，也是该架构首个开放权重版本。它把因果语言模型与视觉编码器组合在一起，覆盖文本、图像和视频理解；仓库提供的是经过预训练与后训练的 Transformers 权重。
  • 为什么热： 冻结快照中，它以 4199 的 Hugging Face 趋势排序分位列第 1；该数字只反映榜单趋势，不代表质量或基准性能。模型卡同时给出新一代 QSA 稀疏注意力、6B 激活参数、原生 262K 上下文和多模态能力，构成了明确的新架构关注点。
  • 技术特点： 语言模型主体为 125B 参数、每 token 激活 6B，另含 51B n-gram embedding 与 4B MTP；48 层、512 个专家，每 token 路由 10 个专家并使用 1 个共享专家。核心组合是 Gated DeltaNet、按 micro-block 选择的 Qwen Sparse Attention、Gated Residual 与 n-gram embedding。原生上下文 262,144 token，可通过 YaRN 扩到 1,000,000；支持 thinking/non-thinking、reasoning_effort 与 preserved thinking。部署侧列出 SGLang、vLLM、TokenSpeed，并建议生产/高吞吐使用专用服务引擎；模型卡没有给出最低 GPU 数量或显存。
  • 适用场景： 适合长上下文 Agent、代码与专业任务、复杂文档/图表理解，以及图片和长视频问答。若业务主要是短文本，只有确实需要超长上下文时才应启用静态 YaRN；模型卡警告固定缩放因子可能影响短文本表现。
  • 关键数据： Trend Score 4,199；Downloads 121,976；Likes 4,371；参数 125B 主体 / 6B 激活 + 51B n-gram embedding + 4B MTP；上下文 262,144 原生；可扩展至 1,000,000；SHA de4b8e4d43b9。
  • 许可与风险： 采用 Qwen Community License 1.0，而非 Apache/MIT。月活超过 1 亿或月收入超过 2,000 万美元的商业产品/服务需在界面显著展示模型名；Model-as-a-Service 或以编程/办公为主的 AI Work Assistant 商业用途须另行取得 Qwen 许可。模型卡将其标为实验预览，且没有给出通用安全/偏见限制章节；生产使用不能把“开放权重”理解为无条件商用。

2. zai-org/GLM-5.3-Flash

  • 模型简介： GLM-5.3-Flash 是 GLM-5 系列首个原生多模态模型。它并非在 GLM-5.2 权重上继续微调，而是从新训练的 base model 出发，把能力和推理效率作为架构设计重点。
  • 为什么热： 冻结快照中，它以 1608 的趋势排序分位列第 2，累计下载 346,516、Likes 1,693；这些是榜单与累计热度指标，不是质量分。320B 总参数但每 token 激活 18B、原生多模态、1M 配置上下文及常见本地服务框架支持，使它兼具新模型与部署效率话题。
  • 技术特点： 模型卡给出 320B 总参数、18B 激活参数、30T-token 多模态预训练语料；采用稀疏注意力与线性注意力混合架构，并引入 mHC。固定 SHA config 显示 45 层、288 个路由专家、每 token 激活 8 个并配 1 个共享专家，最大位置长度 1,048,576，含 24 层视觉编码器；同一 config 带 FP8 e4m3 量化配置。可通过 SGLang、vLLM、TokenSpeed、Transformers、KTransformers 和 Unsloth 部署，但模型卡没有公布最低 GPU 数、显存或吞吐。
  • 适用场景： 适合代码与 Agent 工作负载、长上下文工具调用、图像理解和中英双语对话。reasoning_effort 支持 low/high/max，默认 max；聊天场景应显式设置 clear_thinking=true，避免历史思考内容持续保留。
  • 关键数据： Trend Score 1,608；Downloads 346,516；Likes 1,693；参数 320B 总参数 / 18B 激活；上下文 config.json 为 1,048,576；SHA 04c4e9e95c5d。
  • 许可与风险： 固定 SHA README 与 LICENSE 均为 MIT，许可宽松，仍需保留版权与许可声明。模型卡没有单独列出偏见、安全或事实性限制；卡中“优于 GLM-5.2、接近 Claude Opus 4.8”等属于厂商自报，并依赖其脚注中的 harness、上下文和 judge 设置，不能改写成无条件领先。

3. zai-org/GLM-5.3

  • 模型简介： GLM-5.3 是以代码、长任务和工具执行为主要卖点的后训练模型。模型卡明确说明它与 GLM-5.2 使用同一 base model，所有增益都来自 post-training，因此应把它理解为同一底座上的后训练升级，而不是全新预训练底座。
  • 为什么热： 冻结快照中，它以 1282 的趋势排序分位列第 3，累计下载 50,116、Likes 1,331。模型卡把关注点集中在复杂编程、长时任务和网络安全能力，并公开了多组 Agent/Cyber benchmark 与部署路径；趋势分只表示当日排序热度。
  • 技术特点： README 没有披露总参数或每 token 激活参数，不能从型号或同系列模型推断。固定 SHA config 显示 GlmMoeDsaForCausalLM、78 层、256 个路由专家、每 token 激活 8 个并配 1 个共享专家、1,048,576 最大位置长度，且权重配置为 FP8 e4m3；README 列出 SGLang、vLLM、TokenSpeed、Transformers、KTransformers、Unsloth，以及 Ascend NPU 上的 vLLM-Ascend/xLLM/SGLang。模型卡未给最低 GPU/显存。
  • 适用场景： 适合代码库级生成、终端编程 Agent、自动化工具执行，以及在隔离和授权环境中的漏洞发现、红队与安全评估。reasoning_effort 默认 max；普通聊天应显式 clear_thinking=true。
  • 关键数据： Trend Score 1,282；Downloads 50,116；Likes 1,331；参数 README 未披露总参数/激活参数；config 为 78 层、256 路由专家、8 激活 + 1 共享；上下文 config.json 为 1,048,576；SHA e0b07fd2751b。
  • 许可与风险： 采用自定义 GLM-5.3 License。一般使用、修改、部署与衍生被允许，但运营 MaaS 且被许可方及关联方任意连续 12 个月总收入超过 100 亿美元时，商业使用前须通过 Z.AI 安全审查。其网络安全/利用能力本身带来明显双用途风险；模型卡 benchmark 多为厂商设置，部分含 Claude Code harness、长达 10 小时任务、1M 上下文或内部/第三方判分，不能横向简化成“整体能力第一”。

4. Qwen/Qwen3.8-27B

  • 模型简介： Qwen3.8-27B 是 27B 稠密视觉语言模型，面向代码、专业工作、研究和长时 Agent 任务。它原生理解图片与视频，并允许按请求关闭 thinking 或调整 reasoning_effort。
  • 为什么热： 冻结快照中，它以 783 的趋势排序分位列第 4，同时累计下载 4,511,348、Likes 13,328；后两项是累计量，不是当日增量。27B 稠密规模、原生多模态、262K 原生上下文与 Apache 2.0 组合，给了开发者相对直接的自托管入口。
  • 技术特点： 27B 稠密模型，64 层、hidden size 5120，采用 3 个 Gated DeltaNet 层与 1 个 Gated Attention 层循环的混合布局，并训练 MTP。原生上下文 262,144 token，可用 YaRN 扩到 1M；支持文本、图片和视频输入、thinking/non-thinking、reasoning_effort 及 preserved thinking。服务框架包括 SGLang、vLLM、TokenSpeed；模型卡没有最低显存/GPU 数据，且快照时托管版仍写着 coming soon。
  • 适用场景： 适合本地/私有化的代码助手、长文档分析、图表与 STEM 图片理解、长视频问答和多轮 Agent。超出 262K 才建议启用 YaRN；静态 YaRN 可能影响短文本，较高 presence_penalty 也可能造成语言混杂和轻微性能下降。
  • 关键数据： Trend Score 783；Downloads 4,511,348；Likes 13,328；参数 27B dense；上下文 262,144 原生；可扩展至 1,000,000；SHA 1d4bf0f2ff60。
  • 许可与风险： Apache 2.0，允许商用与衍生，但分发需保留许可证、版权/NOTICE 等义务。模型卡没有系统性的安全、偏见或事实性限制章节；其 benchmark 是官方模型卡自报。部署前还需实测真实显存、吞吐和长视频成本，因为卡片未量化这些硬件指标。

5. unsloth/Qwen3.8-Flash-Next-GGUF

  • 模型简介： 这是 Qwen/Qwen3.8-Flash-Next 的 Unsloth GGUF 量化/转换仓库，不是新的基础模型。它保留基础模型的视觉语言定位和 125B/6B 激活架构，把重点转向 llama.cpp 与 Unsloth Desktop 的本地运行。
  • 为什么热： 冻结快照中，它以 585 的趋势排序分位列第 5，累计下载 328,195、Likes 597。基础模型位列榜首的同时，量化衍生版进入前五，说明榜单关注不仅落在新权重，也落在“如何本地跑起来”；这里仍只是趋势排序信号。
  • 技术特点： README frontmatter 明确 base_model 为 Qwen/Qwen3.8-Flash-Next，并复述其 125B 主体、6B 激活、51B n-gram embedding、4B MTP、262K 原生/1M 扩展上下文。固定 SHA 仓库树可见 BF16、Q8_0、UD-IQ1/3/4 与 UD-Q2/3/4/5/6 等多档目录；README 指定 llama.cpp 或 Unsloth Desktop。模型卡没有给出最低内存/显存，也没有对每个量化档给出经独立复现的质量损失。
  • 适用场景： 面向愿意用 llama.cpp/桌面工具部署 Qwen3.8-Flash-Next 的本地推理用户，可用于多模态问答、长上下文 Agent 和代码任务。选型时应把量化精度、文件体积、内存占用与视觉投影组件一起实测，不能把 Unsloth 的“优于其他量化”宣传直接当成独立结论。
  • 关键数据： Trend Score 585；Downloads 328,195；Likes 597；基础模型 Qwen/Qwen3.8-Flash-Next；关系 GGUF 量化/转换衍生版；SHA c8b5954a88c2。
  • 许可与风险： frontmatter 沿用 Qwen Community License 1.0，但该 GGUF 仓库在固定 SHA 下没有独立 LICENSE 文件；应回到基础模型许可证执行。MaaS/AI Work Assistant 商业用途的另行许可要求与大规模产品署名门槛不会因量化而消失。量化质量声明来自发布方自报，且该仓库是衍生部署工件，不应写成独立模型创新。

6. unsloth/Qwen3.8-27B-GGUF

  • 模型简介： 这是 Qwen/Qwen3.8-27B 的 Unsloth GGUF 衍生仓库，目标是把 27B 原生视觉语言模型带到本地量化推理与桌面微调流程。它没有改变基础模型身份，README 直接复用了 Qwen3.8-27B 的架构说明。
  • 为什么热： 冻结快照中，它以 425 的趋势排序分位列第 6，累计下载 8,839,153、Likes 3,228；累计下载量不能解释为当天新增。Qwen3.8-27B 本体与其 GGUF 版同时上榜，体现基础模型发布与本地部署工件的联动关注。
  • 技术特点： 基础模型为 27B dense、64 层，262,144 原生上下文并可扩展到 1M。README 展示 4-bit 桌面运行并宣传 Dynamic 3.0 GGUF；固定 SHA 树进一步列出 IQ1、IQ2、IQ3、IQ4、Q2 至 Q8、BF16、MTP 与视觉 mmproj 工件，其中单文件量化约从 6.19GB 到 31.46GB，另有约 0.93GB mmproj。模型卡未给最低 RAM/VRAM，也未给各档量化的统一独立测评。
  • 适用场景： 适合 llama.cpp/兼容 GGUF 工具与 Unsloth Desktop 上的离线多模态助手、代码 Agent、长文档和视频理解。视觉任务不能只下载语言 GGUF，还要核对 mmproj；低比特档更省内存，但质量和速度要以目标硬件实测。
  • 关键数据： Trend Score 425；Downloads 8,839,153；Likes 3,228；基础模型 Qwen/Qwen3.8-27B；关系 GGUF 量化/转换衍生版；SHA 4ca720788d1e。
  • 许可与风险： README frontmatter 标注 Apache 2.0，并指向 Qwen/Qwen3.8-27B；固定 SHA 下未发现独立 LICENSE 文件。量化版仍需遵守基础模型的 Apache 2.0 署名/分发义务。Unsloth 对 Dynamic 3.0 的精度优势属于发布方声明，不能在没有同口径复现时写成确定的全面领先。

7. Lightricks/LTX-2.5

  • 模型简介： LTX-2.5 是可本地运行和微调的开放权重音视频生成模型，主要用途是从文本、图片和视频输入生成同步视频与音频。2.5 版增加原生多镜头生成、扩散式视频解码器、提示词增强和可选时长预测。
  • 为什么热： 冻结快照中，它以 346 的趋势排序分位列第 7，累计下载 1,137,181、Likes 2,243。它是 Top 10 中唯一以联合音视频生成而非语言模型为主的条目，多镜头一致性、音画同步、本地 ComfyUI/Python/Diffusers 路径形成了清晰的产品差异。
  • 技术特点： 模型族以拆分组件发布：22B DiT 提供 dev 与 distilled 版，配套自定义 Gemma 4 12B 文本编码器、视频/音频 VAE、LoRA、时长头和时空上采样器；另有 ComfyUI int8 与 Blackwell NVFP4 变体。distilled 版固定 8-step、CFG=1，dev 版可训练。Python 路径建议 Python≥3.12、CUDA≥12.7、PyTorch≈2.7；低显存方案是 bf16 checkpoint 配 fp8-cast 与 CPU offload。模型卡未给最低显存数字。
  • 适用场景： 适合广告分镜、短片预演、多镜头角色/场景连续性、图生视频、文本生成同步音视频，以及 LoRA/IC-LoRA 定制。Diffusers 包是同一模型的兼容封装；ComfyUI int8 文件不能直接用于 ltx-pipelines/PyTorch。画面尺寸需能被 32 整除，帧数需满足 num_frames % 8 == 1。
  • 关键数据： Trend Score 346；Downloads 1,137,181；Likes 2,243；参数 22B DiT + 自定义 Gemma 4 12B 文本编码器（组件式发布）；运行条件 Python≥3.12，CUDA≥12.7，PyTorch≈2.7；可 fp8-cast + CPU offload；SHA e8dc69fd2615。
  • 许可与风险： 使用 LTX-2.x Community License 且仓库为 gated auto。模型卡写明：实体（含共同控制的关联方）年收入低于 1,000 万美元可免费商用/生产使用，但转让 fine-tune 可能需要付费许可；超过 1,000 万美元需付费商业协议。限制方面，模型不用于提供事实信息，可能放大社会偏见、偏离提示并生成不当/冒犯内容；提示风格会显著影响结果。

8. tencent/Hy4-preview

  • 模型简介： Hy4 preview 是腾讯 Hy 团队的新一代 MoE 旗舰预览模型，当前仓库为 Instruct 版。它把 1M 上下文、稀疏注意力和面向软件工程/办公/游戏/科研的后训练放在同一模型中。
  • 为什么热： 冻结快照中，它以 311 的趋势排序分位列第 8，累计下载 2,123、Likes 315。仓库创建于 2026-08-27，模型卡直接给出 770B/49B、1M 上下文、FP8 部署和生产任务定位，这些可观察发布信号比累计下载更能解释其“新模型”属性，但不能据此推断质量。
  • 技术特点： backbone 为 770B 总参数、每 token 激活 49B，78 层；除首层 dense FFN 外，77 层使用 256 个路由专家 + 1 个共享专家，每 token 激活 top-8 + shared。另含 1 个原生 MTP 层（10B 总参数、0.7B 激活）用于 speculative decoding。注意力采用 Gated DSA + IndexCache，残差使用 iHC；上下文 1M。官方 vLLM/SGLang 示例部署 FP8 仓库并使用 TP=8、MTP speculative decoding 与 OpenAI-compatible API，但没有写明具体 GPU 型号或显存。
  • 适用场景： 适合长时软件工程、跨文件办公与分析、游戏原型迭代、科研推理和工具调用。默认 high reasoning，直接回答可切 no_think。官方同时提供完整微调流程与 AngelSlim 压缩工具，并另列 Hy4 preview-FP8 量化 instruct 模型。
  • 关键数据： Trend Score 311；Downloads 2,123；Likes 315；参数 770B backbone / 49B 激活；另有 10B MTP / 0.7B 激活；上下文 1M；部署 vLLM/SGLang 官方镜像示例，FP8，TP=8；SHA 705d81ee5156。
  • 许可与风险： Apache 2.0，允许商用与衍生，需遵守标准署名、许可证与 NOTICE 义务。它明确是 early preview：模型卡承认复杂任务可能思考过久，并有过度自我验证倾向；内部 163 人、203 项任务的对比属于腾讯自报内部评测。架构受 DeepSeek/GLM 启发不等于使用它们作为 base model，模型卡没有声明外部基础模型。

9. unsloth/GLM-5.3-Flash-GGUF

  • 模型简介： 这是 zai-org/GLM-5.3-Flash 的 Unsloth GGUF 量化/转换仓库，不是独立训练的基础模型。它把 320B/18B 激活的原生多模态模型转向 llama.cpp 与 Unsloth Desktop 场景。
  • 为什么热： 冻结快照中，它以 279 的趋势排序分位列第 9，累计下载 45,936、Likes 284。GLM-5.3-Flash 本体排名第 2，量化衍生版也进入 Top 10，显示本地运行工件与原模型同步获得关注；趋势分不代表量化质量。
  • 技术特点： README 明确 base_model 为 zai-org/GLM-5.3-Flash，并复述 320B 总参数、18B 激活、稀疏+线性混合注意力、mHC 与 30T-token 多模态预训练。卡片展示 1-bit “Low” 桌面运行，并要求使用 Unsloth 的 llama.cpp PR 或 Desktop；固定 SHA 树还可见 BF16、Q8_0 及 UD-IQ/UD-Q 多档目录。模型卡没有公开最低内存、显存、速度或各量化档的独立质量对比。
  • 适用场景： 适合有大内存/多设备或 CPU offload 条件、希望用 GGUF 运行 GLM-5.3-Flash 的本地多模态与 Agent 用户。1-bit 只是卡片展示的一个低比特选项，不能据此假设普通消费级设备都能顺畅运行 320B 模型。
  • 关键数据： Trend Score 279；Downloads 45,936；Likes 284；基础模型 zai-org/GLM-5.3-Flash；关系 GGUF 量化/转换衍生版；SHA 2975ab414d30。
  • 许可与风险： README frontmatter 标注 MIT 并指向 MIT 基础模型，但固定 SHA 下未发现独立 LICENSE 文件；分发时应保留基础模型版权和许可声明。Unsloth 的 Dynamic 3.0 精度优势属于发布方自报，且 llama.cpp 支持依赖特定 PR，兼容性不能按主线稳定版处理。

10. OBLITERATUS/Qwen3.8-27B-OBLITERATED

  • 模型简介： 这是基于 Qwen/Qwen3.8-27B 的 abliterated 衍生模型，通过权重空间手术移除拒答方向和安全说教式回避。它不是更大的新底座，而是改变对齐行为的 V3 变体；卡片说明 MTP 与视觉权重从 stock 模型恢复。
  • 为什么热： 冻结快照中，它以 267 的趋势排序分位列第 10，累计下载 725,757、Likes 942。它把“开放权重可被二次手术改变安全边界”这个红队议题带入 Top 10；趋势位置只表示关注度，不能当作能力、安全或质量背书。
  • 技术特点： 基础模型是 27B Qwen3.8-27B。V3 在 V2 的 SVD/LEACE complementary blend 上做迭代 refinement 与定向 corpus surgery，再恢复 stock MTP/vision；发布方自测 MMLU 为 82.33%±0.48，相比 stock 84.46% 下降 2.12 个百分点，STEM 类别下降 3.3 个百分点。提供 Transformers bf16（卡片称约 54GB）、GGUF Q2/Q3/Q4/Q5/Q6/Q8/IQ4（约 11–29GB）和视觉 mmproj；MLX 支持仍等待上游。Agent 使用若循环，卡片建议 repetition_penalty=1.15、较低温度并约 10 轮后压缩上下文。
  • 适用场景： 只适合受控环境中的对齐研究、拒答几何分析、红队和安全评估，或具备责任边界的本地研究。模型卡明确不面向造成现实伤害的用途；不应作为默认面向公众的助手或未经隔离的安全工具。
  • 关键数据： Trend Score 267；Downloads 725,757；Likes 942；基础模型 Qwen/Qwen3.8-27B；关系 安全拒答方向移除/abliteration 衍生版；SHA a58c3b53b3ce。
  • 许可与风险： 代码/权重标为 Apache 2.0，与 base model 相同；但许可证宽松不等于行为安全。模型卡明确安全护栏已被手术移除，会执行 stock 模型拒绝的请求，且 1000+ prompt 与 20 个 cyber/code prompt 的结果为发布者手工审计/自报。它存在现实滥用、合规、输出责任和能力退化风险，尤其不应把“uncensored”写成无代价优势。

读榜结论

需要相对直接的私有化入口，Qwen3.8-27B 的 27B 稠密结构与 Apache 2.0 更容易评估；需要超长上下文、多模态与高吞吐服务时，Qwen3.8-Flash-Next 和 GLM-5.3-Flash 提供了更激进的 MoE 路线，但硬件下限仍需自行实测。Hy4 preview 的 TP=8 示例和 early preview 状态，则更接近大型团队的评估对象。

三款 GGUF 仓库解决的是部署格式，不是重新训练出新模型。它们能降低本地运行门槛，但基础模型许可、视觉投影文件、内存需求和量化损失仍然存在。LTX-2.5 适合音视频生产研究；OBLITERATED 版本移除了安全拒答方向，只应进入隔离的红队与对齐研究环境。

数据来源：Hugging Face Models Trending 官方榜单，以及各模型固定快照提交的 Model Card、配置与许可证。Trend Score 仅表示趋势排序，不代表性能、质量或安全排名。
