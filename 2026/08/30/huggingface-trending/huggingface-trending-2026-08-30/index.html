Qwen3.8 与 GLM-5.3 占 8 席：Hugging Face 热榜正变成部署链之争

Hugging Face 今天的模型热榜高度集中：Qwen3.8 与 GLM-5.3 两个家族拿走 8 个席位。榜单里既有厂商发布的基础模型，也有 GGUF 量化和削弱安全拒答的衍生版本，平台热度已经沿着“发布—压缩—本地运行—对齐改造”整条链路扩散。

这种集中也容易制造错觉。同一家族多次上榜，不等于出现了多个独立基础模型突破；量化仓库解决部署格式和内存门槛，去拒答版本改变安全行为，贡献的工程价值与风险都不同。Trend Score 只描述当前平台关注度，不能代替质量、安全或性能测试。

榜单按 Hugging Face 的 Trend Score 排序。该分数不是模型质量分、基准成绩或下载日增量；Downloads 与 Likes 为榜单快照中的累计值。

1. Qwen/Qwen3.8-Flash-Next

模型简介： Qwen3.8-Flash-Next 是面向下一代架构的实验性开放权重版本，也是未来 Qwen4 架构的预览。语言模型部分为 125B 参数、每次激活 6B，另含 51B N-gram embedding 和 4B MTP；原生上下文为 262,144 tokens，可扩展至 1,000,000 tokens，并带视觉编码器。

为什么热： 4,118 的 Trend Score 明显领先第二名，既有新架构发布效应，也有低激活参数和长上下文带来的部署想象。GGUF 衍生版紧随其后，说明开发者很快把关注从发布说明转向实际运行。

技术特点： Qwen Sparse Attention 按微块筛选上下文，配合 Gated DeltaNet、Gated Residual 与 N-gram embedding，目标是降低长上下文推理成本。它同时调整注意力、残差通路和嵌入层，而非只扩大 MoE 规模。

适用场景： 适合研究长上下文、多模态 Agent 和下一代 Qwen 架构，或提前验证推理框架兼容性。需要稳定托管能力时，Model Card 把功能更完整的 Qwen3.8-Flash 列为生产服务版本。

关键数据： Trend Score 4,118；Downloads 52,341；Likes 4,273。快照版本 SHA 为 de4b8e4d43。

许可与风险： 采用 Qwen Community License 1.0，不是 Apache/MIT。向第三方提供模型服务或 AI 办公、编程助手的商业业务可能需要另行取得授权；实验性架构也不能直接等同于生产稳定性。

2. zai-org/GLM-5.3-Flash

模型简介： GLM-5.3-Flash 是 GLM-5 系列首个原生多模态模型，总参数 320B、激活参数 18B。官方称它从新的基础模型开始训练，并使用 30T-token 多模态预训练语料。

为什么热： 189,793 次累计下载和 1,604 个 Likes，说明它已经不只依赖发布话题。Flash 版本把多模态、Agent 和较低激活参数放进同一模型，对服务器部署者比单看总参数更有参考价值。

技术特点： 它采用稀疏注意力与线性注意力的混合架构，并加入 Manifold-Constrained Hyper-Connections。推理侧支持调节思考预算，也提供多种主流服务框架与本地工具的部署路径。

适用场景： 适合需要图文输入、代码与 Agent 任务，同时具备多卡服务器或成熟推理框架的团队。320B 总参数意味着“Flash”描述的是激活和服务效率，不代表普通消费级电脑可以轻松运行。

关键数据： Trend Score 1,533；Downloads 189,793；Likes 1,604。快照版本 SHA 为 04c4e9e95c。

许可与风险： 采用 MIT 许可。Model Card 中跨模型成绩主要来自发布方评测，部署决策仍应使用自己的真实任务、上下文长度和成本做 A/B 测试。

3. zai-org/GLM-5.3

模型简介： GLM-5.3 是这一代面向代码、工具调用和长任务的完整版本。Model Card 重点展示终端任务、软件工程、安全和办公自动化评测，定位明显偏向 Agent 工程。

为什么热： 它与 Flash 版同时进入前三，但累计下载只有 8,804。当前热度更接近新品与代码 Agent 成绩带来的关注，还不能说明已经形成广泛部署。

技术特点： 官方提供多种 GPU/NPU 推理框架路径，并支持调节思考预算。多项评测使用 300K、400K 乃至 1M 上下文设置，但这些是特定评测配置，不能自动当成所有环境的默认能力。

适用场景： 适合有服务器资源、需要长时间代码修复、工具调用或安全评测的团队。正式上线前应复现自己的仓库任务，因为模型表现会受到 Harness、超时、上下文管理和工具定义影响。

关键数据： Trend Score 1,210；Downloads 8,804；Likes 1,255。快照版本 SHA 为 e0b07fd275。

许可与风险： 使用 GLM-5.3 自定义许可，不等同于 MIT。一般使用、修改和分发被允许；经营模型即服务业务且达到许可中的大型企业收入门槛时，商业使用前需要通过 Z.AI 安全审查。

4. Qwen/Qwen3.8-27B

模型简介： Qwen3.8-27B 是 27B 稠密视觉语言模型，支持图片、视频、可控思考和多步 Agent 任务。它原生支持 262,144 tokens 上下文，可通过 RoPE scaling 扩展到 1,000,000 tokens。

为什么热： 4,028,839 次累计下载和 13,236 个 Likes 让它成为今天最成熟的基础模型之一，也是多个 GGUF 与去拒答版本的共同母版。27B 规模更容易被社区量化和移植。

技术特点： 架构组合 Gated DeltaNet 线性注意力与完整注意力，并保留 MTP 头；思考模式可按请求关闭，也能调节推理深度。视觉部分覆盖文档、图表和长视频理解。

适用场景： 适合代码 Agent、图文理解、文档处理和有较大内存预算的本地或私有化部署。27B 仍不是轻量模型，超长上下文和高帧率视频理解会显著增加内存与延迟。

关键数据： Trend Score 863；Downloads 4,028,839；Likes 13,236。快照版本 SHA 为 1d4bf0f2ff。

许可与风险： 采用 Apache-2.0。扩展到 1M 上下文依赖额外配置与资源，不能把理论上限当作普通设备默认体验；发布方基准也需要在实际 Agent Harness 中复验。

5. unsloth/Qwen3.8-Flash-Next-GGUF

模型简介： 这是 Qwen3.8-Flash-Next 的 GGUF 分发版，目标是让原始模型进入 llama.cpp 与 Unsloth Desktop 等本地环境。它没有改变基础模型架构，新增价值集中在量化、格式和工具兼容。

为什么热： 基础模型登顶后，本地格式通常会迅速承接需求。188,061 次累计下载说明用户关心的不只是模型发布，还关心自己的硬件能否运行。

技术特点： 它保留基础模型的视觉编码器、稀疏注意力和 262K 原生上下文能力，并提供 GGUF 路线与思考控制。量化精度比较来自发布方，仍需在同尺寸、同硬件和同任务条件下复现。

适用场景： 适合熟悉 llama.cpp、GGUF 和内存分层的本地推理用户，以及提前评估 Qwen 下一代架构兼容性的开发者。125B 总参数即使量化后仍有较高存储和内存门槛。

关键数据： Trend Score 545；Downloads 188,061；Likes 553。快照版本 SHA 为 c8b5954a88。

许可与风险： 继承 Qwen Community License 1.0，商业模型服务和 AI 办公、编程助手仍受单独授权条件约束。GGUF 降低部署门槛，但不会消除基础模型的能力、稳定性和许可限制。

6. unsloth/Qwen3.8-27B-GGUF

模型简介： 这是 Qwen3.8-27B 的 GGUF 量化分发版，服务于 llama.cpp 和 Unsloth Desktop 等本地工具。基础能力来自 Qwen 官方 27B 模型，仓库解决的是压缩与可运行性。

为什么热： 8,363,481 次累计下载是今天最高值，远超其 Trend Score 排名。用户会为不同硬件和量化档位反复下载，累计下载量因此不能简单换算成独立用户数。

技术特点： GGUF 把 27B 模型接入本地推理生态，并提供多个量化选择。不同档位会在文件大小、内存、速度和输出质量之间交换，“能加载”不等于长任务、视觉输入和工具调用都稳定。

适用场景： 适合本地代码助手、文档分析、离线实验和隐私敏感场景。应先按统一内存或显存选择量化，再用真实长任务检查重复、上下文和工具调用。

关键数据： Trend Score 482；Downloads 8,363,481；Likes 3,176。快照版本 SHA 为 4ca720788d。

许可与风险： 继承基础模型的 Apache-2.0。量化仓库中的精度优势由发布方提供，跨量化器比较应在相同位宽、提示词和推理后端下复现。

7. Lightricks/LTX-2.5

模型简介： LTX-2.5 是一套开放权重的视频、音频与世界模拟模型，可从文本、图片和视频输入生成同步视听内容。它加入原生多镜头生成、扩散视频解码器、Gemma 4 12B 文本编码器和可选时长预测器。

为什么热： 它是 Top 10 中唯一的视频生成模型，累计下载 1,044,661 次。多镜头一致性、同步音频与 ComfyUI 生态，比单纯追求单帧画质更贴近真实视频流程。

技术特点： 核心为 22B DiT，提供完整、蒸馏、INT8 与 NVFP4 等组件，并把文本编码器、视频/音频 VAE、LoRA 和时空上采样器拆开分发。官方推荐 Python 3.12、CUDA 12.7 和 PyTorch 2.7，部分 INT8 权重只适用于 ComfyUI。

适用场景： 适合有 NVIDIA GPU、需要本地生成并继续微调的短视频、广告预演和多镜头实验。复杂组件和较新 CUDA 要求意味着它不是下载一个文件即可运行的消费级工具。

关键数据： Trend Score 322；Downloads 1,044,661；Likes 2,110。快照版本 SHA 为 bf86adedf5。

许可与风险： 这是 gated 模型，采用 LTX-2.x Community License，不是标准开源许可证。许可对低于特定年营收门槛的主体较宽松，但超过门槛或转让微调成果时可能需要商业协议。

8. OBLITERATUS/Qwen3.8-27B-OBLITERATED

模型简介： 这是基于 Qwen3.8-27B 制作的“abliterated”版本：通过识别并投影掉与拒答相关的方向，显著削弱原模型的安全拒绝行为，并提供 Transformers、GGUF 和 MLX 等分发形态。

为什么热： 645,554 次累计下载说明去拒答模型仍有稳定需求。安全研究者希望观察对齐如何被权重手术绕过，本地用户则可能把更少拒答误认为更强能力，这两类动机需要分开看。

技术特点： 发布者称其方法结合多轮 SVD、LEACE 与定向语料手术，用来移除硬拒答与软回避；自测 MMLU 相比原版下降约 2.12 个百分点。该改造没有创造新基础能力，而是重新调整能力与安全边界。

适用场景： 合理用途主要是安全研究、拒答机制分析、红队测试和受控实验。它不适合直接面向普通用户、未成年人或没有独立审核层的生产系统。

关键数据： Trend Score 321；Downloads 645,554；Likes 910。快照版本 SHA 为 a58c3b53b3。

许可与风险： 继承 Qwen3.8-27B 的 Apache-2.0，但许可证宽松不代表内容安全。Model Card 明确警告它会响应恶意、违法或危险请求，使用者必须补上审核、滥用防护和法律合规。

9. tencent/Hy4-preview

模型简介： Hy4 preview 是腾讯 Hy 团队的新一代 MoE 旗舰预览版，总参数 770B、每 token 激活 49B；另带 10B 参数、激活 0.7B 的 MTP 层。模型使用 78 层骨干、256 个路由专家与 1 个共享专家，原生上下文标为 1M。

为什么热： 它在只有 1,394 次累计下载时进入第 9 名，典型地反映新品发布的短期关注。与量化仓库相比，它代表厂商端继续扩大规模和上下文的服务器路线。

技术特点： 注意力采用 Gated DSA 与 IndexCache，残差路径使用 iHC；官方部署示例基于 vLLM 或 SGLang，并给出 FP8 模型的 8 路 Tensor Parallel 配置。硬件定位明显是多卡服务器。

适用场景： 面向有多卡 GPU 资源的代码工程、办公分析、游戏开发和科研 Agent 实验。官方还提供微调与量化路径，但部署成本和运维复杂度都高。

关键数据： Trend Score 273；Downloads 1,394；Likes 277。快照版本 SHA 为 705d81ee51。

许可与风险： 采用 Apache-2.0。官方明确称其为 preview，并承认复杂任务可能推理过久或过度验证；公开评测主要来自发布方，生产采用前仍需独立复现。

10. unsloth/GLM-5.3-Flash-GGUF

模型简介： 这是 GLM-5.3-Flash 的 GGUF 量化分发版，目标是把 320B 总参数、18B 激活参数的基础模型接入 llama.cpp 与 Unsloth Desktop。本仓库没有重新训练基础模型，主要提供格式和量化选择。

为什么热： GLM-5.3-Flash 发布后迅速出现本地分支，27,288 次累计下载说明部署需求已经开始形成。它位列第 10，更像新模型分发链刚启动，而非已经完成广泛硬件验证。

技术特点： Model Card 提到 Unsloth Dynamic 3.0 量化，并要求使用相应的 llama.cpp 支持或桌面工具。基础模型仍是 320B 级 MoE，即便低位量化可以减小体积，也不会让普通轻薄电脑自动获得理想速度与质量。

适用场景： 适合有大内存工作站、熟悉 GGUF 与分层加载的开发者，先做 GLM-5.3-Flash 本地兼容和量化评估。生产前应测试长上下文、多模态输入、工具调用和低位量化退化。

关键数据： Trend Score 263；Downloads 27,288；Likes 266。快照版本 SHA 为 2975ab414d。

许可与风险： 继承基础模型的 MIT 许可。量化版降低分发与运行门槛，但发布方的精度声明仍需在相同硬件、位宽与任务上复验；基础模型的规模也决定了较高存储和内存成本。

如果目标是研究新架构，Qwen3.8-Flash-Next 与 GLM-5.3-Flash 提供了最直接的入口；如果准备本地运行，GGUF 分支的价值在格式与量化，而不是新能力。涉及去拒答模型时，减少拒绝会把审核、权限和法律责任转移给部署者，不能把“更愿意回答”当作“更适合产品”。
