GitHub 热榜今天不只追大模型：小模型、Agent 技能与工作流一起上位

今天的 GitHub 热榜，最亮眼的不是又一个参数更大的模型，而是一批把 AI 塞进真实工作现场的“小而硬”工具：14MB 的端侧模型、可审计的上下文图谱、能直接装进 Agent 的技能包，以及帮应用在不同模型间调度流量的代理层。

另一条线也很清楚：安全与情报工具重新回到榜单。开发者一边给 Agent 加能力，一边重新审视身份暴露、攻击面和决策责任。AI 开始接管工作流之后，控制权、可追溯性和本地运行，也随之变得更值钱。

1. cathrynlavery/diagram-design

  • 项目简介： 面向 Claude Code、Codex 和 Pi 的图表设计 Skill，提供 29 类编辑图、三套静态风格，并能把 draw.io 或 Mermaid 源文件重绘成自包含 HTML + SVG。
  • 为什么火： 它击中了生成式图表最常见的尴尬：结构对了，成品却像同一个模板复制出来。单日增加 4,504 Stars，说明开发者愿意为“少调半小时样式”投票。
  • 技术亮点： 把“图表达什么”与“怎么排版”分开，支持架构图、状态机、时间线、飞轮等模式；默认静态输出，无外部图片和构建步骤。它更像一本能被 Agent 执行的设计手册。
  • 适用场景： 技术文章、架构评审、产品方案、咨询报告和品牌化知识内容。代价也很明确：视觉语言很有主张，不适合要求像素级服从既有设计系统的团队。
  • 关键数据： HTML · 13,940 Stars · Today +4,504 · 840 Forks · MIT · 最近更新 2026-08-13 · Topics：— · Homepage：—

2. semantica-agi/semantica

  • 项目简介： 位于 LLM、向量库和 Agent 框架下方的图原生基础设施，把企业数据变成上下文图谱、知识图谱和可查询的决策证据链。
  • 为什么火： 当 Agent 开始参与信贷、医疗、法律和政府流程，“答案像不像对的”不够了，团队还得回答几个月后审计员追问的“当时为什么这么做”。
  • 技术亮点： 同时覆盖 RDF 与属性图，强调 W3C 标准、因果推理、数据血缘和确定性溯源；图谱构建与推理不强制依赖 LLM，便于把模型判断和系统事实分开。
  • 适用场景： 受监管行业的 Agent 平台、数据治理、风险与合规系统。它不是轻量 RAG 的即插即用替代品，组织要先承担本体建模、数据清洗和治理流程的成本。
  • 关键数据： Python · 6,482 Stars · Today +727 · 680 Forks · MIT · 最近更新 2026-08-13 · Topics：agent-memory / ai-governance / context-graphs / data-engineering · Homepage：https://getsemantica.ai

3. anthropics/skills

  • 项目简介： Anthropic 的 Agent Skills 公共仓库，收录技能示例、规范、模板，以及文档、表格、演示文稿、测试和企业沟通等工作流。
  • 为什么火： Agent 的竞争正从“会不会调用工具”转向“能不能稳定复用一套做事方法”。Skill 把提示词、脚本和资源装进一个文件夹，相当于给模型发了一本岗位手册。
  • 技术亮点： 每个技能以 SKILL.md 描述元数据与执行方法，并按需加载，避免把全部说明一次塞进上下文；仓库同时给出规范与模板，方便团队建立自己的技能库。
  • 适用场景： Claude Code 定制、企业流程固化、文档生产和 Agent 能力评估。要注意仓库并非统一许可证：部分技能采用 Apache 2.0，文档编辑技能只是源码可见，生产使用前必须逐目录核对。
  • 关键数据： Python · 168,930 Stars · Today +383 · 20,121 Forks · License：按目录区分 · 最近更新 2026-08-13 · Topics：agent-skills · Homepage：—

4. cactus-compute/needle

  • 项目简介： Needle 2 是一个 45M 参数、14MB 的端侧基础模型，专注工具调用、设备操作和结构化抽取，完整会话约占 28MB 内存。
  • 为什么火： 它把“端侧 Agent”从口号压缩成了能放进手机、手表、智能家居和机器人的体积。对隐私敏感或网络不稳定的设备来说，小模型能不能可靠调用工具，比闲聊能力更重要。
  • 技术亮点： CQ2-bit 压缩、256-token 滑动窗口、工具检索头、基于 Schema 的字节级语法约束，以及独立的置信度头；低置信度时可以把任务升级给更大的模型。
  • 适用场景： 可穿戴设备、家庭自动化、机器人控制、离线表单抽取。项目公布的性能比较主要来自自身基准，真正上设备前仍要用目标语言、工具数量和错误成本重新测一遍。
  • 关键数据： Python · 4,859 Stars · Today +768 · 330 Forks · MIT · 最近更新 2026-08-13 · Topics：on-device-ai / llm / gemma · Homepage：https://cactuscompute.com

5. altic-dev/FluidVoice

  • 项目简介： 一款 macOS 开源语音输入应用，支持本地语音识别、命令模式和文本重写，目标是做不依赖云端的 Wispr Flow 替代品。
  • 为什么火： 语音输入正在从“识别准不准”转向“说完能不能立刻得到格式正确的文字”。FluidVoice 把低延迟与隐私绑在一起，正好踩中本地 AI 的需求。
  • 技术亮点： Swift 原生应用、设备端 STT、多语音引擎与本地后处理；1.6.0 版本强化了 Parakeet 推理速度和上手流程。
  • 适用场景： 写邮件、会议后快速整理、无障碍输入和不愿上传语音的个人工作流。核心应用采用 GPLv3，但高级本地增强运行时目前私有维护，开源边界需要看清。
  • 关键数据： Swift · 9,797 Stars · Today +187 · 660 Forks · GPL-3.0 · 最近更新 2026-08-13 · Topics：dictation / macos / llama-cpp · Homepage：https://altic.dev/fluid

6. unslothai/unsloth

  • 项目简介： 把本地模型运行、微调、数据集制作、量化导出、服务部署和 Agent 接入收进桌面应用，覆盖 LLM、扩散、音频与多模态模型。
  • 为什么火： 本地 AI 最大的门槛往往不是模型，而是驱动、显存、格式和工具链。Unsloth 正在把原本散落在 Notebook 与命令行里的流程做成一个入口。
  • 技术亮点： 支持 LoRA、QLoRA、DPO、GRPO、FP8 等训练与导出路径，提供 OpenAI 兼容接口，并能把 Claude Code、Codex、Hermes Agent 等客户端接到本地模型。
  • 适用场景： 个人模型实验、私有数据微调、本地推理和团队原型验证。功能面很宽，也意味着硬件兼容和新模型支持变化快；生产部署仍需要单独做版本锁定与性能测试。
  • 关键数据： Python · 70,974 Stars · Today +354 · 6,403 Forks · Apache-2.0 · 最近更新 2026-08-13 · Topics：fine-tuning / llm / image-generation / agent · Homepage：https://unsloth.ai/docs

7. macro-inc/macro

  • 项目简介： 面向团队的一体化工作区，把邮件、消息、文档、任务、通话、CRM 与 Agent 放进共享后端，并用双向链接串起来。
  • 为什么火： 它单日增加 1,180 Stars，反映出团队对“再加一个 AI 插件”已经疲惫。开发者更想要的是：信息原本就在同一个系统里，Agent 不必跨五个 SaaS 拼上下文。
  • 技术亮点： 前端使用 SolidJS，核心服务强调 Rust；文档、任务、邮件和消息之间以原生双向图关联，团队级共享记忆可以直接服务于搜索和 Agent。
  • 适用场景： 希望减少 Slack、Linear、Notion、HubSpot 等工具切换的初创团队。它的难点不在安装，而在迁移：把公司沟通和客户数据全部压进一个系统，会带来明显的流程与锁定成本。
  • 关键数据： Rust · 2,529 Stars · Today +1,180 · 272 Forks · AGPL-3.0 · 最近更新 2026-08-13 · Topics：all-in-one / crm / ai-agents / mcp · Homepage：https://macro.com

8. megadose/holehe

  • 项目简介： 输入邮箱后，通过 120 多个站点的找回密码流程判断它是否注册过账号，并返回部分恢复信息与限流状态。
  • 为什么火： 数据泄露、社工攻击和数字足迹检查让老牌 OSINT 工具再次获得关注。它把手工逐站试探变成统一命令行和 Python 调用。
  • 技术亮点： 基于异步 HTTP 请求运行站点模块，输出统一结构，支持 CLI、Python、Docker 与 Maltego 工作流。
  • 适用场景： 经授权的数字足迹自查、企业安全调查和红队侦察。仓库最近一次推送停在 2024-09-10，站点接口容易失效；同时它涉及账号枚举，使用时必须取得授权并遵守隐私与平台规则。
  • 关键数据： Python · 12,348 Stars · Today +166 · 1,666 Forks · GPL-3.0 · 最近更新 2024-09-10 · Topics：osint / information-gathering / email · Homepage：—

9. smicallef/spiderfoot

  • 项目简介： 一套自动化 OSINT 与攻击面侦察框架，可从域名、IP、邮箱、用户名等目标出发，联动 200 多个数据模块。
  • 为什么火： AI 让钓鱼和漏洞利用更快，防守方也需要更快知道“互联网上暴露了什么”。SpiderFoot 的价值在于把大量零散情报源接成一次扫描。
  • 技术亮点： 同时提供 Web UI 与 CLI，内置相关性规则、SQLite、CSV/JSON/GEXF 导出，并可调用 Nmap、DNSTwist、WhatWeb 等外部工具。
  • 适用场景： 攻击面梳理、威胁情报、渗透测试前侦察和资产盘点。模块多不等于结果都可靠：API Key、限流、误报与数据合规仍需人工把关。
  • 关键数据： Python · 20,612 Stars · Today +278 · 3,312 Forks · MIT · 最近更新 2026-04-13 · Topics：cybersecurity / attacksurface / threat-intelligence / osint · Homepage：http://www.spiderfoot.net

10. NVIDIA-NeMo/Switchyard

  • 项目简介： NVIDIA NeMo 推出的 Rust LLM 流量代理与库，在 OpenAI Chat、OpenAI Responses、Anthropic Messages 与 OpenAI 兼容后端之间翻译协议并调度请求。
  • 为什么火： 模型越来越多，应用团队不想把代码绑死在一家接口上。Switchyard 让 Claude Code、Codex 或 OpenClaw 保持原来的“说话方式”，后端却可以切到 vLLM、NIM、Ollama 或其他模型。
  • 技术亮点： 支持随机、分类器和信号驱动的路由算法，能做 A/B 基准、阶段式选模，并通过 Prometheus 记录请求、错误、延迟、Token 与路由开销。
  • 适用场景： 多模型评测、成本与延迟优化、私有推理接入和兼容层实验。仓库明确标注为 pre-alpha，API 与算法还会大改，暂时不该被当成生产流量网关。
  • 关键数据： Rust · 1,153 Stars · Today +408 · 104 Forks · Apache-2.0 · 最近更新 2026-08-13 · Topics：— · Homepage：—

热榜每天都在换名字，但今天这 10 个项目把方向说得很明白：下一阶段的胜负，不只看模型知道多少，而看它能否在更小的设备、更乱的数据和更真实的团队流程里，把事情做完。
