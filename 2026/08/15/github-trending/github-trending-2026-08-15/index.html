今天的 GitHub 热榜像一张正在扩建的工作台：左边是会替 Agent 画图、开浏览器和整理团队资料的工具，右边是端侧小模型、本地 3D 生成与企业知识引擎。开发者不再只围观模型参数，而是在给 AI 补齐眼睛、双手、记忆和工作空间。

榜单里也有一条反向信号。holehe、SpiderFoot 这类老牌安全工具重新升温，说明 Agent 越能碰到真实账户和业务系统，身份暴露、权限边界与审计就越不能靠事后补课。AI 真正进入工作流后，最稀缺的不只是能力，而是可控的能力。

1. cathrynlavery/diagram-design

  • 项目简介： 面向 Claude Code、Codex 等编码 Agent 的图表设计 Skill，提供 29 类编辑图、三套静态风格，并能把 draw.io 或 Mermaid 源文件重绘成自包含 HTML + SVG。
  • 为什么火： 它击中了生成式图表最常见的尴尬：结构基本正确，成品却像同一个圆角框模板复制出来。单日增加 3,651 Stars，开发者显然愿意为“少调半小时样式”投票。
  • 技术亮点： 把“图表达什么”与“如何排版”分开，覆盖架构图、状态机、时间线、飞轮等模式；默认静态输出，不依赖外部图片或构建步骤，更像一本能被 Agent 执行的设计手册。
  • 适用场景： 技术文章、架构评审、产品方案和品牌化知识内容。代价也很明确：它的视觉语言很有主张，对要求像素级服从既有设计系统的团队未必合适。
  • 关键数据： HTML · 17,030 Stars · Today +3,651 · 1,010 Forks · MIT · 最近更新 2026-08-14 · Topics：— · Homepage：—

2. cactus-compute/needle

  • 项目简介： Needle 2 是一个 45M 参数、14MB 的端侧基础模型，专攻工具调用、设备操作和结构化抽取，完整会话约占 28MB 内存。
  • 为什么火： 它把“端侧 Agent”从概念压缩成了能塞进手机、手表、智能家居和机器人的体积。对隐私敏感或网络不稳定的设备来说，会不会可靠调用工具，比能不能闲聊更重要。
  • 技术亮点： 采用 CQ2-bit 压缩、256-token 滑动窗口、工具检索头、基于 Schema 的字节级语法约束和独立置信度头；低置信度时可以把任务交给更大的模型。
  • 适用场景： 可穿戴设备、家庭自动化、机器人控制和离线表单抽取。项目性能比较主要来自团队自测，上设备前仍应按目标语言、工具数量和错误成本重新评估。
  • 关键数据： Python · 5,522 Stars · Today +661 · 367 Forks · MIT · 最近更新 2026-08-14 · Topics：on-device-ai / llm / gemma · Homepage：https://cactuscompute.com

3. megadose/holehe

  • 项目简介： 输入邮箱后，通过 120 多个站点的找回密码流程判断它是否注册过账号，并返回部分恢复信息与限流状态。
  • 为什么火： 数据泄露、社工攻击和数字足迹自查让老牌 OSINT 工具再次获得关注。它把逐站试探变成统一命令行与 Python 调用，省掉了大量重复劳动。
  • 技术亮点： 以异步 HTTP 请求运行站点模块，统一输出结果，并支持 CLI、Python、Docker 与 Maltego 工作流。
  • 适用场景： 经授权的数字足迹自查、企业安全调查和红队侦察。仓库最近一次推送停在 2024-09-10，站点接口随时可能失效；账号枚举也必须获得授权并遵守隐私与平台规则。
  • 关键数据： Python · 12,791 Stars · Today +427 · 1,714 Forks · GPL-3.0 · 最近更新 2024-09-10 · Topics：osint / information-gathering / email · Homepage：—

4. macro-inc/macro

  • 项目简介： 面向团队的一体化工作区，把邮件、消息、文档、任务、通话、CRM 与 Agent 放进共享后端，并用双向链接串起来。
  • 为什么火： 团队已经开始厌倦“再装一个 AI 插件”。Macro 的卖点更直接：信息原本就在同一个系统里，Agent 不必跨五个 SaaS 拼上下文。
  • 技术亮点： 前端使用 SolidJS，核心服务强调 Rust；文档、任务、邮件和消息之间以原生双向图关联，团队级共享记忆可以直接服务于搜索和 Agent。
  • 适用场景： 希望减少 Slack、Linear、Notion、HubSpot 等工具切换的初创团队。难点不在安装，而在迁移：把沟通与客户数据集中到一个系统，会带来明显的流程与锁定成本。
  • 关键数据： Rust · 2,971 Stars · Today +435 · 301 Forks · AGPL-3.0 · 最近更新 2026-08-14 · Topics：all-in-one / crm / ai-agents / mcp · Homepage：https://macro.com

5. smicallef/spiderfoot

  • 项目简介： 一套自动化 OSINT 与攻击面侦察框架，可从域名、IP、邮箱、用户名等目标出发，联动 200 多个数据模块。
  • 为什么火： AI 让钓鱼和漏洞利用更快，防守方也需要更快回答“互联网上暴露了什么”。SpiderFoot 的价值是把大量零散情报源接成一次扫描。
  • 技术亮点： 同时提供 Web UI 与 CLI，内置相关性规则、SQLite、CSV/JSON/GEXF 导出，并可连接 Nmap、DNSTwist、WhatWeb 等外部工具。
  • 适用场景： 攻击面梳理、威胁情报、渗透测试前侦察和资产盘点。模块多不等于结果都可靠，API Key、限流、误报和数据合规仍需人工把关。
  • 关键数据： Python · 20,897 Stars · Today +292 · 3,338 Forks · MIT · 最近更新 2026-04-13 · Topics：cybersecurity / attacksurface / threat-intelligence / osint · Homepage：http://www.spiderfoot.net

6. citrolabs/ego-lite

  • 项目简介： 一款为人和 AI Agent 共同使用而设计的浏览器。每个 Agent 在独立 Space 里工作，可以继承本机登录态，同时不抢用户正在使用的标签页。
  • 为什么火： 浏览器自动化最难的往往不是“点按钮”，而是登录态搬不过去、多个任务互相抢页面。ego-lite 把浏览器本身改造成共享工作区，正面处理了这两个摩擦点。
  • 技术亮点： Agent 通过 JavaScript 函数组合 snapshot、fill、click、navigate 等操作，一次完成多步骤流程；独立 Space 支持并行任务，对深层 iframe 也强调更完整的语义快照。
  • 适用场景： 登录后网页操作、线索整理、竞品研究和多 Agent 并行浏览。当前只支持 macOS，最高 2.5 倍提速来自项目方基准；更重要的是，共享真实登录态会放大误操作风险，权限与确认步骤不能省。
  • 关键数据： JavaScript · 10,293 Stars · Today +153 · 526 Forks · MIT · 最近更新 2026-08-14 · Topics：browser-automation / agent-skills / codex · Homepage：https://lite.ego.app

7. holaboss-ai/holaOS

  • 项目简介： 一个本地优先的 Agent 桌面工作区，可并排运行 Claude Code、Codex 与内置 Agent，并共享记忆、工具、技能、应用和连接。
  • 为什么火： 今天 +769 Stars 的背后，是开发者对“Agent 操作系统”的兴趣：模型可以换，但记忆、授权与工作现场不该每换一次模型就重搭一遍。
  • 技术亮点： Electron + TypeScript 桌面端把记忆保存为本地可读文件，并接入应用界面、浏览器、MCP、技能和 50 多种 OAuth 连接；支持内置模型，也允许自带供应商密钥。
  • 适用场景： 希望在一个桌面里统一多个 Agent、企业工具与长期记忆的团队。它的能力面很宽，部署与权限模型也随之变复杂；仓库使用修改版 Apache 2.0，采用前应先核对额外条款。
  • 关键数据： TypeScript · 7,200 Stars · Today +769 · 633 Forks · Modified Apache 2.0 · 最近更新 2026-08-14 · Topics：agent-os / mcp / memory / workspace · Homepage：https://holaos.ai

8. github/spec-kit

  • 项目简介： GitHub 推出的规格驱动开发工具包，先把原则、需求、技术计划和任务写成可执行规格，再交给 AI 编码 Agent 实现。
  • 为什么火： 当“让 Agent 写代码”越来越便宜，真正昂贵的变成返工。Spec Kit 把需求从一次性文档提升为持续约束代码的源头，单日增加 1,147 Stars。
  • 技术亮点： 通过 constitution、specify、plan、tasks、implement 等阶段把需求逐步收紧，并支持 30 多种编码 Agent；扩展、预设和团队角色包让流程可以按组织复用。
  • 适用场景： 中大型功能、多人协作、受质量规范约束的项目和 Agent 驱动交付。对探索性原型或一天就能写完的小工具，这套流程可能比代码本身还重。
  • 关键数据： Python · 128,376 Stars · Today +1,147 · 11,471 Forks · MIT · 最近更新 2026-08-14 · Topics：spec-driven / engineering / copilot · Homepage：https://github.github.com/spec-kit/

9. lightningpixel/modly

  • 项目简介： 一款本地开源桌面应用，用 GPU 把图片转换成 3D 网格，并在应用内完成平滑、减面、工作流编排和导出。
  • 为什么火： 3D 生成正在从云端演示走向个人工作站。Modly 不要求上传素材，又把模型安装和节点工作流做进图形界面，降低了本地 3D AI 的上手门槛。
  • 技术亮点： 支持 Hunyuan3D、TripoSG、Trellis2 GGUF 等外部模型扩展；工作流先校验连线再执行，并提供可被 Agent 或脚本调用的 CLI 与机器可读结果。
  • 适用场景： 游戏原型、电商素材、3D 打印草模和创作者本地实验。生成质量仍取决于显卡、输入角度和所选模型；macOS 目前只支持 Apple Silicon，复杂资产不能期待一键达到生产级拓扑。
  • 关键数据： TypeScript · 5,866 Stars · Today +580 · 598 Forks · MIT（含署名要求） · 最近更新 2026-08-13 · Topics：3d / ai-local / desktop-app / self-hosted · Homepage：https://modly3d.app

10. infiniflow/ragflow

  • 项目简介： 面向企业知识应用的开源 RAG 与 Agent 引擎，把复杂文档解析、切块、检索、重排、引用和工作流编排放进同一套系统。
  • 为什么火： 企业已经不满足于“向量库能搜到”，还要求表格、扫描件与长文档能被正确拆解，答案可以指回原文，并能接进真实业务流程。
  • 技术亮点： 支持多种非结构化与结构化数据、模板化切块、多路召回和融合重排；提供可视化干预、可追溯引用、Agent 模板、MCP 与多聊天渠道接入。
  • 适用场景： 企业知识库、客服、研究检索、合同与技术文档问答。自托管至少建议 4 核、16GB 内存和 50GB 磁盘，官方预构建镜像仍以 x86 为主；功能完整的代价是部署和运维都不轻。
  • 关键数据： Go · 88,368 Stars · Today +474 · 10,379 Forks · Apache-2.0 · 最近更新 2026-08-14 · Topics：rag / context-engine / agentic-search · Homepage：https://ragflow.io

热榜每天都在换名字，但今天的方向已经很清楚：下一阶段的 AI 竞争，不是谁更会回答，而是谁能在权限清楚、结果可追溯的前提下，真正把手伸进工作流。
